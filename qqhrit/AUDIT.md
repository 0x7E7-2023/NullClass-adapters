# 安全审计 —— 齐齐哈尔工程学院（正方教务 V9，jwglxt；CAS 登录，教务主机非默认端口 20266）

审计对象：`jw-adapters/qqhrit/` 下的 `extract.js` / `parse.js` / `manifest.json` 与 `fixtures/`，
以及它们移植自的上游脚本 `shiguang_warehouse` 的 `QQHRIT/qqhrit.js`
（快照 commit `c4a35feb061a3f6db2d6c122927083c067c61309`，2026-10-19 拉取；MIT，作者 星河欲转；
本校脚本最后一次修改 `80e30cf5990f1166210b8af6b72bed71667232ca`，2026-09-23，两者均用只读的 `git log` 核对过）。

审计方式：逐行读上游脚本 + 逐行读移植件，跑移植手册 §5 的静态扫描，并用 Rhino 1.8.0 实跑全部 fixture。
静态扫描结果（2026-10-19）：

- 绝对 URL：`extract.js` 文件头注释里有一处 `https://github.com/XingHeYuZhuan/shiguang_warehouse`（写上游出处，不是请求）；
  `parse.js` 文件头同样一处。去掉注释后，两个文件里没有任何绝对 URL。
- 网络调用：只有 `extract.js` 第 60 行 `request()` 里的 `fetch(url, options)`。第 66 行的 `XMLHttpRequest`
  是请求头里的字符串，不是 XHR 对象。`parse.js` 没有任何网络调用。
- 凭据、本地存储、动态执行：`password` / `pwd` / `localStorage` / `sessionStorage` / `document.cookie` /
  `eval` / `new Function` / `sendBeacon` / `WebSocket` / `EventSource` / `new Image` 全部无命中。
- ES5 token 扫描（注释也算）：`=>`、反引号、`let `、`const `、`class `、`async`、`await`、展开运算符、
  模板串、`new Set` / `new Map` / `Array.from`、`URLSearchParams`、可选链、后行断言与命名捕获组，
  在 `parse.js`、`extract.js` 全文中全部无命中。
- 控制字节与 BOM：目录下全部文件无控制字节、无 BOM（自检工具逐个字节扫过）。
- 模板学校字样：代码、manifest、fixtures 里检索模板学校名 / 模板 key / 模板主机，零命中；只在本文件里
  作为「与模板的差异」的对照语境出现。

## 1. 请求域与请求清单（与代码逐条对应）

上游 `QQHRIT/qqhrit.js` 里有三个绝对 URL，都是 `http://jwxt.qqhrit.com:20266/jwglxt/...`：
课表首页（GET，N2151，第 277 行）、学期周次校历（POST，N2154，第 385 行）、课表接口（POST，N2151，第 434 行）。
移植件把这些主机名全部去掉了：四条请求的地址都由 `window.location.origin + '/jwglxt'` 拼出来
（上下文路径跟着当前地址走，见 `extract.js` 第 47 行 `jwBase`），端口跟着当前页面走。
所以请求主机只有用户当前所在的那一个教务主机，正常就是 `jwxt.qqhrit.com:20266`。

`manifest.json` 的 `allowHosts` 是 `["jwxt.qqhrit.com"]`（不带通配）；CAS 登录主机 `tysf.qqhrit.com:20261`
写进 `loginUrl`，应用本来就放行 `loginUrl` 的主机用于登录，不需要重复放进 `allowHosts`。
`scheduleUrlHint` 带 `:20266`（`http://jwxt.qqhrit.com:20266/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default`），
宿主靠它给这个带端口的 origin 注入桥 —— 不带端口的话真机上拿不到桥。

| 谁 | 方法 | 地址 | 干什么 | 取不到时 |
|---|---|---|---|---|
| extract.js | GET | `<origin>/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` | 读课表页上的学年学期字段（`#xnm` / `#xqm`）。**页面上已经有这两个字段时跳过这一步**（第 174 行 `currentTerm`） | 报错，提示重新登录后再点「提取课表」 |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151` | 取课表 JSON：`kbList` 排课行、`sjkList` 集中实践课、可能有的记录总数。请求体 `xnm=…&xqm=…&kzlx=ck&xsdm=&kclbdm=`，与上游逐字一致 | 报错，提示重新登录 |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcx_cxRjc.html?gnmkdm=N2151` | 取校区作息。请求体 `xnm` / `xqm` / `xqh_id`，`xqh_id` 取自课表行 | 交 `null`，parse 回落到学校内置 11 节作息；课表用到更多节次时按 H3 口径补时间，并写进 `warnings` |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcxZccx_cxZcByXnxq.html?gnmkdm=N2154` | 取学期周次校历，定开学日与总周数。请求体 `xnm` / `xqm` | 交 `null`，parse 回落到推算并写进 `warnings` |

与上游的差别：

- 上游每次导入都先请求课表首页生成两个选择框（`fetchAcademicOptions`），再弹窗让用户选学年学期。
  移植件改成：页面上读得到 `#xnm` / `#xqm` 就不发这条请求，读不到才去取一次首页
  （`extract.js` 第 174 行起，`DOMParser` 离线解析，不插入当前页面）。
- 作息请求（cxRjc）是**上游没有的**：上游整个脚本没有作息接口，只写死一张 11 节表，也从不调用
  `savePresetTimeSlots`。菜单号与请求体照同族正方脚本的写法（`WENHUA/wenhua_01.js`、`SCNU/scnu.js`，
  本次审计没有重新核对这两份脚本）：菜单号用课表菜单 `N2151`，请求体带 `xqh_id`。
- 两条附加请求（作息、校历）失败不影响导入：`optionalJson`（`extract.js` 第 217 行）把任何失败
  （非 2xx、网络错误、JSON 解析失败）都吞成 `null`，由 parse.js 回落，回落这件事会出现在导入预览的 `warnings` 里。
- 请求头统一带 `Content-Type`、`X-Requested-With`、`Accept`，不带任何自定义令牌。凭据用
  `credentials: 'include'`，让 WebView 按同源规则带 Cookie；脚本既不读 Cookie，也不把它发到别处。
- 登录页判断（`extract.js` 第 55 行 `onLoginPage`）：路径里带 `cas/login`（本校 CAS 统一登录）
  或 `login_slogin.html`（正方自带登录页）都算登录页，直接抛出「请先登录」的提示，不发任何请求。
- `parse.js` 不发任何请求（CI 里用 Rhino 实跑，是纯函数）。

## 2. 读了什么（数据面）

| 数据 | 从哪来 | 是否带出 |
|---|---|---|
| 学年学期（`xnm` / `xqm` 与下拉框文本） | 课表页的 `#xnm` / `#xqm`，或课表首页 HTML（`DOMParser` 解析的离线文档，不插入当前页面） | 带出（学期名要用） |
| 排课行 `kbList` 的 `kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd` / `xqh_id` | 课表接口 | 带出（这就是课表本身）；`xqh_id` 只用来拼作息请求 |
| 集中实践课 `sjkList` 的 `kcmc` | 课表接口 | 带出。它没有固定星期与节次，排不进周课表，但不能吞掉：写进 `warnings` 让用户自己加 |
| 校区作息（`jcmc` / `qssj` / `jssj` 等原样） | cxRjc | 带出到 parse，合格时成为载荷的 `periodTimes`，取不到为 `null` |
| 学期周次校历（`zs` / `rq` 等原样） | cxZcByXnxq | 交给 parse 只用来算开学日与总周数，不进入载荷 |
| 记录总数（`total` / `totalCount` 等，响应里有才有） | 课表接口 | 只用于对账，不进入载荷 |
| 学生个人信息（课表响应里夹带的 `xsxx`、学号、姓名、学院等） | 课表接口 | **不带出，也不进 fixture**。`extract.js` 第 105 行 `pickCourseRow` 按七个字段白名单挑，第 118 行 `pickPracticeRow` 只挑 `kcmc` |

不读的东西（静态扫描无命中）：`password` / `pwd` / 登录表单、`localStorage` / `sessionStorage`、
成绩（`/cjcx/*`）、学籍、个人信息、缴费，以及任何其它模块的接口。

## 3. 移植手册 §5 八条逐条

| # | 检查项 | 结论 |
|---|---|---|
| 1 | 不碰凭据 | **过**。没有密码读取、没有登录表单、没有本地存储访问。唯一的「凭据」是浏览器自带的会话 Cookie，脚本既不读它也不外发。上游的开场公告弹窗（`showAlert`）与两个学年学期选择框（`showSingleSelection`）没有移植：学年学期改成读页面上的 `#xnm` / `#xqm`，不向用户问任何东西 |
| 2 | 不外发 | **过**。全部 `fetch` 都在 `extract.js`，地址由 `window.location.origin` 拼成。没有 `sendBeacon` / `WebSocket` / `EventSource` / `new Image().src` / 隐藏表单，也没有第三方域 |
| 3 | 请求域可控 | **过**。请求主机只有一个，即用户当前打开的教务主机（正常是 `jwxt.qqhrit.com:20266`）。`allowHosts` 只写 `jwxt.qqhrit.com`，不写通配；CAS 主机只出现在 `loginUrl`。代码里没有写死的主机名 |
| 4 | 只读课表 | **过**。四条请求全部落在 `/jwglxt/kbcx/*`（课表页、课表接口、作息、周次校历），不碰成绩、学籍、个人信息、缴费。课表响应里夹带的学生信息一律不带出。作息与周次校历是学校公共数据，不含个人信息 |
| 5 | 不埋点 | **过**。没有统计、上报、遥测，也没有图片打点 |
| 6 | 不 eval 远程代码 | **过**。没有 `eval` / `new Function`。只对教务自己的响应做 `JSON.parse`（`extract.js` 第 129 行 `jsonOf`） |
| 7 | 不写页面 | **过**。`extract.js` 只读 `#xnm` / `#xqm` 的值。取课表首页用的是 `fetch` + `DOMParser`，离线解析，不插入当前页面，不改表单，不触发提交或点击。上游的 `showToast` / `notifyTaskCompletion` 等桥调用全部没有移植 |
| 8 | 不依赖用户输入之外的秘密 | **过**。没有硬编码的密钥、令牌或他人学号。脚本里的常量只有正方上下文路径 `/jwglxt`、两个菜单号 `N2151` / `N2154`，都是页面上可见的参数 |

**结论：可以进内置库。** 请求全部落在当前教务主机上（地址由当前页面的 origin 拼出），只读课表
（含作息与周次校历两个只读附加接口），不碰凭据、不外发、不埋点、不写页面。

## 4. 字段映射与本校特有处理

- **周次**（`parse.js` 第 329 行 `weeksOf`）：四写法全认（标记在「周」后 / 最前 / 括号里、混排），
  括号里的纯数字是教学班序号先摘掉；`runsOf`（第 424 行）把周次集合切成极大段，步长 2 视作单 / 双周。
  两处补充：
  - **「共 N 周」剥离**（第 335 行）：只剥备注本身（「共」加数字加可选的「周」）。
    `1-15周(单) 共16周` 不剥会多出第 16 周；但不能从「共」删到行尾 ——
    `1-8周(共8周),9-16周`（注释放进括号里）与 `共16周,1-15周(单)`（注释放最前）后面还有真正要用的周次，
    贪心删除会把 9-16 周整段吞掉、甚至把整门课丢光。
  - **单/双括号按相邻关系归属**（第 347-352 行）：通用括号处理之前，先把紧挨数字的单/双括号改成标记
    （前缀 `(单)1-8周` → `单1-8`，后缀 `1-8周(单)` → `1-8单`）。不先归属的话，
    `(单)1-8周,(双)9-16周` 的两个括号都会落成独立段，后面的就近逻辑把「双」并进已经带「单」的
    前一段，两段塌成「1-16 每周都上」。其余独立成段的标记仍走原来的就近逻辑。
- **节次**（第 447 行 `sectionsOf`）：认 `1-2`、`第9-10节`、`1,2`、两位一拼的 `0102`；多段按最大跨度放入并提醒；
  超过 `MAX_PERIOD = 20` 的当脏数据跳过并计数。
- **合并**（第 579 / 627 / 643 行）：先去掉完全相同的行，再套上游 `mergeAndDistinctCourses` 的两阶段
  （连续节次合并、同节次周次并集）。
- **开学日 / 总周数**：校历第 1 周优先，回退到那一周的周一（手册 §4.3）；校历取不到按第一学期
  9 月 1 日所在周的周一推算并说明。总周数校历优先，取不到用上游写死的 20 周；课表更晚就抬升并说明。
- **节次时间**：
  - 学校内置主表 `SCHOOL_PERIOD_TIMES`（第 61 行）是上游 `TimeSlots` 的 11 节，逐节照抄：
    1 08:00-08:45、2 08:55-09:40、3 10:20-11:05、4 11:15-12:00、5 13:30-14:15、6 14:25-15:10、
    7 15:20-16:05、8 16:05-16:50、9 18:00-18:45、10 18:45-19:30、11 19:30-20:15。
  - 教务作息接口合格就用教务的；不合规（不是从第 1 节起连续、时间不递增 / 重叠、超出 00:00-23:59）
    整张弃用，回落内置表并在 `warnings` 里说明（第 522 行 `periodTimesOf`、第 863 行起）。
  - 课表用到的节次超出表长时按 H3 口径逐节补（第 869 行）：空课默认 12 节表里同号那一节的开始
    不早于上一节下课就用它，否则按课间 5 分钟、每节 45 分钟顺推；越过当天 23:59 就停并说明。
- **逐课特殊上课时间**（第 724 行 `customKindOf`，判定逐条照上游 `applyCustomTimeLogic`）：
  - 周末（第 6、7 天）优先：用上游的周末 11 节表（第 97 行 `WEEKEND_PERIOD_TIMES`，逐节照抄）；
  - 工作日：地点含 `2#` 或 `3#` 且**首节或末节**落在第 3-4 节 → 第 3 节 09:55-10:40、第 4 节 10:50-11:35；
  - 工作日：地点含「图」「馆」或「齐三机床」且首节或末节落在第 3-4 节 → 第 3 节 10:05-10:50、第 4 节 11:00-11:45；
  - 其它节次仍用主表；起止节次超出 11 节时上游取不到时间、不施加自定义时间，这里同样不提醒。
  - 我们的载荷只有一张学期级节次时间表：这些课**照常按节次导入**，自定义时间丢掉但**出声**——
    按周末 / 特殊教室两类分别计数，点名课名（每门截到 20 字、最多 3 门）写进 `warnings`（第 954 / 960 行）。
    上游算出的自定义起止与主表同号节**确实相同**的不提醒（例如周末第 7-8、9-11 节）。
- **缺教师 / 缺教室**：照常导入（值为 `null`），按类型计数写进 `warnings`（第 767-768 行计数、第 969-974 行提醒）。
  上游在这里整行丢课：`qqhrit.js` 第 229-231 行要求 `kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd` 全部非空。
- **学期名**（第 252 行 `termName`）：取教务下拉框的学年学期；整段已是「…学年…学期」就直接用，
  否则用学年加「学年第 X 学期」；学年一个数字都读不出来时用「齐齐哈尔工程学院当前学期」兜底。
- **提醒出口**（第 215 行 `warn`）：所有提醒走同一个出口，单条超 200 字截断加省略号，总数到 20 条后
  最后一格写「另有 N 条核对提示超出上限未显示」，保证整次导入不会被载荷校验拒收。
  给学生看的文案统一用「节次时间」口径：不出现「作息表」「空课默认作息」「学校实际作息」
  （界面文案规范 §四把「作息表 / 时间表 / 默认模板」列为禁词，本批统一口径）。

## 5. 与模板 lcudcc 的差异（逐条）

1. 文件头、学校常量、`manifest.json` 全部改成齐齐哈尔工程学院；模板的 fixtures 全部删除重做（8 对）。
2. **作息主表换成学校 11 节**：模板回落到空课默认 12 节；本件回落到上游 `TimeSlots` 的 11 节。
   H3 补时间仍用空课默认 12 节表（与模板一致）。
3. **新增逐课特殊上课时间检测**：模板没有这段逻辑。本件按上游 `applyCustomTimeLogic` 判定，
   只用于生成两类汇总提醒，不往载荷里塞 `isCustomTime` / `customStartTime` / `customEndTime`。
4. **新增缺教师 / 缺教室的计数提醒**：模板只是把值留空，不提醒。本批公共说明要求按类型汇总计数。
5. **登录页判断加了 CAS**：模板只认 `login_slogin.html`；本件同时认 `cas/login`。
6. **课表响应按字段白名单交出去**：模板把 `kbList` 整行原样交给 parse；本件只留
   `kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd` / `xqh_id`，`sjkList` 只留 `kcmc`（本批公共说明要求）。
7. **学期名兜底**：「学校名 + 当前学期」，避免拼出只有一个「学年第 X 学期」的名字。
8. **manifest 的主机与端口**：`loginUrl` 是 CAS 主机 `tysf.qqhrit.com:20261`；
   `scheduleUrlHint` 必须带 `:20266`；`allowHosts` 是 `["jwxt.qqhrit.com"]`。
9. 课表请求体带 `kclbdm=`（与上游逐字一致，本批五所都带）。
10. **修正模板同源缺陷（B1）**：`weeksOf` 先按相邻关系归属单/双括号，再剥掉「共 N 周」；
    不先归属时 `(单)1-8周,(双)9-16周` 会被就近逻辑并成 `1-16 每周都上`。本批五件都按同一口径改。
11. **提醒文案统一「节次时间」口径**：内置节次时间与 H3 补时间两条提醒不再写作息表 / 空课默认作息 /
    学校实际作息。

## 6. 对上游的删改（都不牵涉安全问题，审阅者需要知道）

- 删除全部交互与桥调用：`showAlert`、`showSingleSelection`、`showToast`、`notifyTaskCompletion`、
  `saveImportedCourses`、`savePresetTimeSlots`、`saveCourseConfig`。我们的适配器是「拉」模型：
  `extract.js` 交数据、`parse.js` 出载荷，不向用户提问、不写应用配置。
- 删除写死的主机名 `http://jwxt.qqhrit.com:20266`，四条请求改成同源相对路径。
- 删除 `parseJsonData` 里「缺教师 / 缺教室整行丢掉」的严格过滤（上游第 229-231 行）：

## 审计修正（2026-10-20）

- **周次前缀标记误吞上一段的后缀**：`parse.js` 的 `weeksOf` 里，前缀写法的正则 `(单)1` 没排除标记前面紧挨着上一段（数字或「周」）的情况，
  把上一段的后缀 (单)/(双) 当成下一段的前缀：`1-8周(单) 9-16周(双)` 被读成 1-16 每周；`1-8周(单)9-16周` 被读成 1-15 单周，9-16 周的双周丢了；
  `1-16周(单) 17-18周` 被读成 1-17 单周，第 18 周丢了。
- 修正：标记前面紧挨着数字或「周」（中间可有空白）时按后缀归给前一段，只有在段首（字符串开头或分隔符之后）才当后一段的前缀；
  后缀后面直接跟着下一段数字时补一个逗号隔开。`(单)1-8周,(双)9-16周`、`1-8周(单),9-16周(双)`、`1-15周(单) 共16周` 等原有写法行为不变。
- 新增 fixture `week-adjacent`（三个反例；期望值按周次集合手推：1-7 单 + 10-16 双；1-7 单 + 9-16 每周，合并为 1-9 单 + 10-16 每周；1-15 单 + 17-18 每周，合并为 1-17 单 + 18 每周）。版本号 1.0.0 → 1.0.1。
- 已知取舍：`(单)1-8周 (双)9-16周`（前缀写法、段间只有空格）里的 `(双)` 前面紧挨「周」，按上述规则会被当作前一段的后缀；与后缀写法 `1-8周(单) 9-16周(双)` 在形态上无法区分，未见真实样本，按上述规则取后缀。
