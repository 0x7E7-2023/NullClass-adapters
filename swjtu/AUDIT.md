## 2. 读了什么、交出去什么（逐字段）

页面只读两处，都不带出原文：

| 来源 | 读什么 | 交出去什么 |
|---|---|---|
| `document.cookie` 的 `ytoken`，其次 `localStorage` / `sessionStorage` 的 `ytoken` / `YToken` / `token` / `TOKEN`（顺序照上游 `getYToken`），`extract.js:121` | 登录令牌 | **不交出去**：只放进发往本校同源接口的 `ytoken` 请求头，不写进返回值、报错、提醒或存储；超过 4096 字符不认 |
| `document.body.innerText` 前 20000 字（`extract.js:130`） | 匹配 `20xx-20xx学年第x学期` 这一种写法 | 只用匹配到的学年与学期号拼成学期名；页面其它文字（含姓名、学号）一律不带出 |

接口响应按**字段白名单**（`extract.js:189` `courseOf`）：

| 交出字段 | 内容 |
|---|---|
| `today` | 提取当天日期（本地日期，不用 toISOString） |
| `term` | `{ name, year, kind, source }`；`source` 为 `page` 或 `none`；读不到时 name 空串、year 0、kind 空串 |
| `courses[].courseName` | 课名（上游的 `courseName` → `name` → `kcmc` 优先级） |
| `courses[].staffName` / `staffNameOther` | 两位教师原文（拆分与去重放 parse.js） |
| `courses[].campusName` | 校区名（上游用它当地点兜底） |
| `courses[].slots[].classTime` / `classPlace` | 第 1…40 个 `classTime{n}` / `classPlace{n}` 的原文，空的跳过 |

**不交出去**的：响应里除上面这些以外的全部字段——学号、姓名、学院、专业、班级、学分、课程代码、人员 ID、
电话、身份证号等（冒烟里专门塞了这些字段，见 §8）。

## 4. 节次时间与周次映射（逐节照上游抄）

节次时间（`parse.js:40`，上游 `SWJTU_TIME_SLOTS`，13 节，写死，不问用户）：

| 节 | 时间 | 节 | 时间 | 节 | 时间 |
|---|---|---|---|---|---|
| 1 | 08:00-08:45 | 6 | 14:00-14:45 | 11 | 19:30-20:15 |
| 2 | 08:50-09:35 | 7 | 14:50-15:35 | 12 | 20:20-21:05 |
| 3 | 09:50-10:35 | 8 | 15:40-16:25 | 13 | 21:10-21:55 |
| 4 | 10:40-11:25 | 9 | 16:40-17:25 | | |
| 5 | 11:30-12:15 | 10 | 17:30-18:15 | | |

更晚的节次（>13）按统一修订 H3 顺推：从 21:55 起课间 5 分钟、每节 45 分钟（第 14 节 22:00-22:45、
第 15 节 22:50-23:35），越过 23:59 就停并如实说明（`parse.js:628`）。

周次（`parse.js:256` `weeksOf`）：

- 一段上课文字的周次部分来自「星期」之前的那截（`parse.js:361` `groupsOf`），交给 `weeksOf` 统一解析。
- 认：`1-16周`、`第1-第8周`、`1-16周(单)`、`(单)1-16周`、`(单)1-8周,(双)9-16周`（无逗号也认）、`1-3,5-9周`、
  `1至8周`、`1~16周`、全角数字与全角括号、`共16周,1-15周(单)`（「共 N 周」只剥备注本身）、`1-3周 5-9周`。
- 括号里只有数字的（`(1)`、`(1-2)`）是教学班序号，摘掉；含非周次字的（`(3组)`）是备注，摘掉；两者都计数写进提醒。
- 周次集合按手册 §4.1 切极大段：步长 1 → 每周（ALL），步长 2 → 单周 / 双周（ODD / EVEN）。
- 超出 1…30 周的周次丢弃并计数；一门课可以有多个上课安排（`classTime1…40` 每段一条）。

总周数：上游写死 19（`SWJTU_SEMESTER_TOTAL_WEEKS`）；课表排得更晚才抬到那一周（不静默改成最大周），并提醒
（`parse.js:623`）。开学日：接口不给，按学期推算——第一学期 = 9 月 1 日所在周的周一，第二学期 = 2 月 20 日
所在周的周一（`parse.js:220`），并在提醒里说明是推算的。

## 5. 上游里删掉 / 改掉的东西及理由

| 上游 | 处理 | 理由 |
|---|---|---|
| `showToast` / `showAlert` / `saveCourseConfig` / `savePresetTimeSlots` / `saveImportedCourses` / `notifyTaskCompletion` | 全部不移植 | 拾光的桥能力，空课由宿主保存；适配器只交载荷 |
| 全部 `console.log` / `console.warn` / `console.error` | 去掉 | 埋点类输出，且会把教务原文写进日志 |
| `buildTeacher` 把缺失教师写成「未指定」，`position` 写成「未指定」 | 教师、地点缺失交 `null` | 手册 §4.7 / 公共说明第 8 条：「未指定」会被课表当成真名显示；缺教师 / 缺教室照常导入并汇总提醒 |
| `cleanValue` 只把 `"null"` 与 `"无"` 当空 | 另外把「未知」「待定」「暂无」「暂无教师」「暂无教室」「未指定」「未安排」「undefined」都当空 | 公共说明第 8 条 |
| 「有时间文字但认不出节次」的课进 `skipped` 只弹一句条数；完全没给上课时间的课悄悄不见 | 每门课的原始时间段都交出去，parse.js 分别统计「教务没给时间」与「时间写法认不出来」并点名 | 公共说明第 6 条：不许静默丢课 |
| `parseWeeks` 整段文字只取**一个**单 / 双标记（`text.includes('单') ? 单 : …`） | 每段各自归属单 / 双（`weeksOf`） | `(单)1-8周,(双)9-16周` 在上游会退化成 1-16 每周都上 |
| `parseWeeks` 先把全部 `第` 删掉再按逗号切 | 先做区间终点前的「第」归一，其余交给宽松解析 | `第1-第8周` 不被拆成两周 |
| `semesterStartDate: null` 交给拾光自己推 | 本件按学期推算 firstDay 并提醒 | 空课载荷必须给 `firstDay`，推算值必须说出来 |
| 上游不支持 `data:{list:[…]}` 之外的其它外壳，且「有没有数据」与「挑字段」各判一次 | 外壳只在 `courseRowsOf`（`extract.js:180`）定义一次 | 批次九 `gdpu` 的教训 |
| 上游在登录页 / 未登录时抛 `未找到 ytoken` 之类的内部措辞 | 改成大白话，并先判断登录页 / 密码框 / 非本校主机 | 公共说明第 6、7 条 |

## 6. 与模板 `hnsf` 的差异

1. 取数方式：模板是乘方教务的 POST 表单 + 学期下拉框 + 第 1 周日期接口；本件只有一个 GET JSON 接口，
   学期从页面正文读，开学日只能推算。
2. 行数据：模板一行 = 一条排课（`xq`/`ps`/`pe`/`zc` 分字段）；本件一门课带 40 个定长 `classTime{n}` 文字段，
   星期、节次、周次都藏在中文文字里，由 `groupsOf` 切开后再交给 `weeksOf`。
3. 节次时间：模板三张表、按排课行时间自动挑选并可提问；本件只有一张 13 节表、不问用户、不按行时间校验。
4. H3 补节次：模板先用空课默认表里能接上的同号节次；本件 13 节已经覆盖到 21:55，更晚的节次没有可借的默认值，
   只做顺推（代码更短，理由写在这里）。
5. 模板的 `weekOne` / `plausibleStart` / 多教室 `jxcdmc2`、校区与作息提问、排课时间核对，本件都不需要，已删。
6. `hnsf` 的 `MAX_PERIOD=20`、周次切段、提醒限长、去重 / 合并、载荷拼装原样沿用。

## 9. 已知风险与未验证项（我们没有本校账号，真机没验过）

1. **学期文字来自页面正文扫描**。只认 `20xx-20xx学年第x学期` 这一种写法（`extract.js:130`）。如果扬华学堂
   只在学期下拉框里显示、正文没有这段文字，学期会退回按今天日期推算——提醒里会明说是推算的，用户可在
   「学期管理」改正，但名字可能不是他真正要导入的那个学期。
2. **开学日永远是推算值**。接口与上游都不给第 1 周日期，本件也没找到可用的日期接口（不猜接口）。提醒里写明了
   推算规则与结果，但开学日错了整学期的周次都会错位，这是本件最大的未验证风险。
3. **`ytoken` 的读取方式照上游**：Cookie 的 `ytoken` 优先，其次本地存储的同名键。如果学校把令牌设成 HttpOnly
   且本地存储里也没有，本件会停在「没有读到登录状态」——上游同样如此；真机若遇到，需要换一个读取点再发版。
4. **上课时间的文字格式**只按上游脚本接受的那一种（`周次 + 星期X + 第a-b节`，可连写多段）。上游正则以外的写法
   （例如「第1,2节」）会被记为「上课时间写法认不出来」并点名，不会静默丢课，但那门课不会导入。
5. **节次时间表是上游写死的 13 节**，学校如果调整了作息或存在分校区不同作息，需要改本表；导入时提醒用户核对。
6. **总周数 19 周**来自上游常量；学校实际周数不同时需要用户核对（课表更晚时会自动抬高）。
7. 冒烟用的是合成的页面与接口数据，真实页面的学期文字位置、`classTime` 的具体写法都没有样本可对照。
