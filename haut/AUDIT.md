# 安全审计 —— 河南工业大学（正方新版 jwglxt 平台）

审计对象：`jw-adapters/haut/` 下的 `extract.js` / `parse.js`，以及它们移植自的上游脚本
`shiguang_warehouse` 的 `HAUT/haut_01.js`（快照 commit `ff72d1f08782df965cae110034a9d87cd91e0c07`，
2026-10-08，MIT，上游 maintainer 是 `星河欲转`）。检查口径按移植手册批次三/四的检查表与第五批专项检查表逐条核对（§4、§4b），上游为另一所学校的同族正方件只作对照（§5）。

审计方式：逐行读上游脚本 + 逐行读移植件，并跑移植手册 §5 给的静态扫描
（`grep -oE "https?://[A-Za-z0-9.-]+"` 与 `grep -nE "fetch\(|XMLHttpRequest|sendBeacon|new WebSocket|\.src\s*="`），
另加 `console` / `eval` / `new Function` / 凭据与存储关键字的扫描。
扫描结果：上游的绝对 URL 只有 `https://jwglxt.haut.edu.cn` 一个主机（登录页常量在 L120，课表接口常量在 L188）；
移植件里出现的绝对 URL 只有文件头写上游出处的 `https://github.com`。网络调用：上游只有一处 `fetch`（L202），
移植件只有 `extract.js` 里的一个 `fetch` 包装函数（L64）；`X-Requested-With: XMLHttpRequest` 是请求头，不是 XHR 对象。
上游与移植件都没有 `eval` / `new Function`；移植件没有任何 `console` 调用；两边都没有 `password` / `pwd` / `localStorage` / `sessionStorage` 访问。

## 1. 请求域与请求清单（本节必须与代码一致，不许写得比代码窄）

上游 `HAUT/haut_01.js` 的绝对 URL 有两处（L120 登录页判断用的常量、L188 课表接口），主机都是 `jwglxt.haut.edu.cn`。
移植件把主机名去掉了：四条请求的地址全部由 `window.location.origin + '/jwglxt'` 拼出来（`extract.js` 的 `jwBase()`），
所以**主机只有用户当前所在的那一个教务主机**。正常就是 `loginUrl` 的主机 `jwglxt.haut.edu.cn`；
学生若通过学校的 WebVPN 打开，请求会跟着当前源走，不需要（也没有）额外放行任何域。**`allowHosts` 留空，不写通配。**

| 谁 | 方法 | 地址 | 干什么 | 取不到时 |
|---|---|---|---|---|
| extract.js | GET | `<origin>/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` | 页面上没有 `#xnm` / `#xqm` 时，取一次课表首页，用 `DOMParser` 离线解析出学年学期下拉框。用户已经开在课表页时直接读页面上的字段，不发这一条 | 报错（没有学年学期就没法查课表） |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151` | 取课表（JSON：`kbList` 排课行、`sjkList` 集中实践课、可能的记录总数）。请求体 `xnm=…&xqm=…&kzlx=ck&xsdm=&kclbdm=`，与上游 L187 逐字一致 | 报错 |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcx_cxRjc.html?gnmkdm=N2151` | 取**校区作息时间**（`xnm` / `xqm` / `xqh_id`，`xqh_id` 取自课表行） | 交 `null`，parse 回落到上游那张 11 节表，并写进 `warnings` |
| extract.js | POST | `<origin>/jwglxt/kbcx/xskbcxZccx_cxZcByXnxq.html?gnmkdm=N2154` | 取**学期周次校历**（`xnm` / `xqm`），用来定开学日与总周数 | 交 `null`，parse 回落到推算，并写进 `warnings` |

- 后两条接口**不来自上游 HAUT 脚本**（它只请求课表一条，也不读作息与校历）。路径与参数取自同族正方脚本：
  - 作息 `xskbcx_cxRjc.html`：快照 `resources/` 下能 grep 到这个路径，写法带 `?gnmkdm=N2151`；移植件沿用这个菜单号，请求体 `xnm` / `xqm` / `xqh_id`。
  - 周次校历 `xskbcxZccx_cxZcByXnxq.html`：`resources/` 下 grep 命中 31 个文件（含非适配器文件，未逐个核对），移植件挂菜单号 `N2154`。
  - 两处都不是每个部署都装了菜单，所以一律 best-effort（见上表最后一列）。
- 这两条请求失败**不会**影响导入：`optionalJson` 把任何失败（含非 2xx、超时、JSON 解析失败）都吞成 `null`，
  由 `parse.js` 回落，并且**回落这件事会出现在导入预览的 `warnings` 里**（不是静默降级）。
- 请求头只带 `Content-Type` / `X-Requested-With` / `Accept`，**不带任何自定义令牌**；
  `credentials: 'include'` 让 WebView 自己按同源规则带 Cookie，脚本既不读它、也不把它发到别处。
- `parse.js` 不发任何请求（CI 里用 Rhino 实跑，是纯函数）。

## 2. 读了什么（数据面）

| 数据 | 从哪来 | 是否带出 |
|---|---|---|
| 学年学期（`xnm` / `xqm` + 下拉框文本 `2026-2027` / `第一学期`） | 课表页的 `#xnm` / `#xqm`，或课表首页 HTML（`DOMParser` 离线解析） | 带出（学期名要用） |
| 排课行 `kbList`（`kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd` / `xqh_id`） | 课表接口 | 带出（这就是课表本身）；`xqh_id` 取第一个非空值作 `campusId`，用来拼作息请求 |
| 集中实践课 `sjkList` | 课表接口 | 带出（只有课名与周次，排不进周课表，但**不能吞掉**：写进 `warnings` 让用户自己加） |
| 校区作息 | 作息接口 | 带出（写进载荷的 `periodTimes`）；取不到或不合法就是 `null` |
| 学期周次校历 | 校历接口 | 只用来算开学日与总周数，**不整表带出** |
| 记录总数（若响应里有） | 课表接口 | 只用于对账，不整表带出 |
| **学生个人信息**（课表响应里夹带的 `xsxx` 之类） | 课表接口 | **不带出、也不进 fixture**（`extract.js` 只挑 `kbList` / `sjkList` / 记录总数） |

不读的东西（静态扫描无命中）：`password` / `pwd` / 登录表单、`localStorage` / `sessionStorage`、
成绩（`/cjcx/*`）、学籍、个人信息、缴费、任何其它模块的接口。

## 4. 检查表 10 条逐条（批次三/四口径）

| # | 检查项 | 本件结论 |
|---|---|---|
| 1 | 周次四写法 | **过，且有用例**。`1-16周(单)`（A）、`(单)1-16周`（B）、`1-16(单周)`（C）、`1-3,5-9周`（D）各一条，见 `fixtures/weeks-forms.*`。实现上（`weeksOf`，L279 起）先处理括号（X1，见第 2 条），再删量词「周」，再切段，所以「标记在周后」不会被切走，标记在括号里、最前、独立成段都能跟到自己那一段。**上游在这里是错的**：上游 `parseWeeks`（L9–L36）的两个正则 `/(\d+)-(\d+)周/` 与 `/^(\d+)周/` 都匹配不上 `1-16(单周)`，于是这一段得到空周次数组。上游之后怎么处理空周次没有逐行核对，本件的结论不依赖这一点。移植件按四种写法都认，认不出的进 `warnings`，不静默消失 |
| 1b | 空白的分段语义 | **过，有用例（K）**。`1-3周 5-9周`（无逗号、空格分段）按统一口径切成两段，各认各的标记（`1-3 ALL` + `5-9 ALL`）。破折号异体（含「至」「到」）连同两侧空白先归一成 `-`，`1 -16周(单)` 不会被劈开。这一条没有单独做变异（见 §6） |
| 2 | 括号内纯数字不是周次 | **过，有用例**。周次处理的第一步是逐个看括号（`weeksOf`，L289 起，X1）：括号里只有数字、逗号、区间的（如 `(1,2)`、`(1)`、`(1-2)`）整组摘掉并计数（`serialGroups`，写进 `warnings`）；括号里混了「组」之类周次以外的字的（如 `(3组)`）整组摘掉并计数（`noteGroups`，写进 `warnings`）；其它括号（`(1-16周)`、`（1-16周）`、`(单)`）换成逗号、内容保留；没闭合的括号换成逗号，不删（删了会把前后数字粘成一个）。用例：E `1-16周(1)` → 1–16 每周；F `(1-2)1-16周(双)` → 双周 2–16；G 整格只有 `(3)` → 判为没有周次，该行进 `warnings`，绝不塌成「第 3 周」。X1 用例见 `fixtures/weeks-brackets.*` 的 L–R 行，M3、M4 覆盖括号步骤的顺序与未闭合分支，M6 覆盖备注计数，纯数字序号分支没有变异覆盖（见 §6） |
| 3 | 无星期表头兜底 | **不适用，且没有猜列**。本件走的是接口（JSON），星期由 `xqj` 字段直接给出（1–7），不解析课表 HTML 表格，因此不存在「按行宽猜列」的问题；`parse.js` 里没有任何按行宽推断的逻辑。`xqj` 不在 1–7 的行走 `warnings`（计数 + 原因），不猜 |
| 4 | 时间合法性 | **过**。写进 `periodTimes` 的时间有两个来源：① 教务作息接口，逐条要求 `HH:mm`（小时 0–23、分钟 0–59）、`start < end`、从第 1 节起连续且不重叠，任一条不满足就**整表作废**并回落（`periodTimesOf`，L460 起）；② 上游 11 节表（`SCHOOL_PERIOD_TIMES`，与上游逐个比对一致，见 §4b 第 3 条）。内置 12 节表（`BUILTIN_PERIOD_TIMES`）只在它的开始不早于前一节下课时才用；否则从前一节下课起课间 5 分钟、每节 45 分钟顺推，顺推越过当天 23:59 就停并写 warnings（H3，`parse.js` L594–L632），见 §7 第 9 条。除这一条顺推外，脚本**不做时间加减** |
| 5 | `warnings` 上限 | **过**。所有提示都经 `warn()`（L167）收口：单条超 200 字截断（补「…」），总数超过 20 条不再追加并计数，末尾给出「另有 N 条核对提示超出上限未显示」。`check.js` 的 `validatePayload` 按 `JwPayloadCodec.validate` 口径复核全部期望载荷；本件条数最多的一份（`calendar-extra`）9 条 |
| 6 | 分页 | **不适用，但对账了**。正方这个接口一次性返回整学期排课，**没有分页参数**（上游也没有翻页）。响应里若带了记录总数就与行数对账，取到的少就出声：`calendar-extra`（教务说 30 条、实际 10 行）覆盖了这条 |
| 7 | 学期名 | **过**。取自教务下拉框的文本（`xnmText` / `xqmText` → `2026-2027学年第一学期`）。**没有拿适配器名当学期名**，也没有写死学校名 |
| 8 | `teacher` 拿不到就留空 | **过**。`xm` 为空的「大学体育(一)」（`basic`）与无教师、无教室的「大学语文」（`calendar-extra`）都以 `null` 进载荷。**上游在这里会整行丢课**（L68–69 要求 `kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd` 六个字段全非空），移植件只要求课名、星期、节次、周次 |
| 9 | `allowHosts` | **过**。`allowHosts: []`。四条请求全是**当前页同源相对路径**，只放行 `loginUrl` 那一个主机，没有任何通配。本件**不使用 OCR / 提问桥**（源码里没有 `__ncOcr` / `__ncSelect` 等全局名），所以不存在「通配拿不到桥」的问题 |
| 10 | 每件都要做变异测试 | **已做，见 §6**（六条变异：M1 作息表第 5 节、M2 H3 内置补位判断、M3 / M4 X1 括号两步、M5 X2 作息文案、M6 括号备注计数；全部使 check.js 判红，都在副本上做，真文件未动） |

## 5. 与模板件及同平台件的对照

上游 `HAUT/haut_01.js` 与模板件的上游同属正方新版 `jwglxt`，但**不是克隆**。`diffs/haut.diff` 的实质差异只有四处：
① 两处绝对 URL 的主机（`jwglxt.haut.edu.cn` 对模板件上游的另一所学校主机）；
② 文件头注释；
③ 起始学年提示的文案；
④ `TimeSlots`（HAUT 11 节，模板件上游 12 节，时间整体不同）。
`parseWeeks`、行过滤、请求体的 diff 里没有差异，所以 `1-16(单周)` 的漏匹配在模板件的上游里也存在，本件的结论不依赖模板件的审计。

| 层 | 能不能复用 | 本次结论 |
|---|---|---|
| 接口信封（POST 表单 + `{kbList:[...]}`） | **能** | 与同族件同一套。移植件沿用「响应必须是对象且 `kbList` 是数组」的判据，也沿用「响应带记录总数就对账」 |
| 行字段名（`kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd` / `xqh_id`） | **能** | 上游读的是同一组字段；本件 fixture 也按这组形状编 |

## 7. 移植时对上游做的删改（都不牵涉安全问题，但审阅者需要知道）

1. **两段式**：上游把取数、解析、存配置写在一段里；移植件按手册 §3 第 1 步切开：`extract.js` 只取数（`kbList` / `sjkList` / 作息 / 校历 / 学年学期原样交出），`parse.js` 是纯转换（CI 用 Rhino 实跑的那一段）。
2. **交互全部去掉**：上游的 `showAlert`（开场公告）、`showPrompt`（手填起始学年）、`showSingleSelection`（选第一/第二学期）三个弹窗都没有移植，改成读页面上的 `#xnm` / `#xqm`。要导入别的学期，用户在教务页面里切一下再点「提取课表」，他看得见自己切的是哪个学期。
3. **不再整行丢课**：上游要求 `kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd` 六个字段全非空（L68–69），缺教师或缺教室的课**整行丢掉且不吭声**。移植件只要求课名 / 星期 / 节次 / 周次，跳过的行按原因计数写进 `warnings`。
4. **节次解析放宽**：上游只 `split('-')` 取首尾（`0102` 这种会算出第 102 节）。移植件认 `1-2` / `第9-10节` / `1,2` / 两位一拼的 `0102`；多段（`1-2,5-6`）按最大跨度放入并写进 `warnings`；超出 1–20 节判为脏数据（计数 + `warnings`），不塞进载荷。
5. **周次解析重写**（检查表 1、2 的两个坑），见 §4。X1 又改了括号的处理顺序：括号整段是周次时把括号换成逗号、保留内容；纯数字序号与周次以外的备注才摘掉，并写进 `warnings`。
6. **开学日与总周数**：上游根本没有开学日（`config` 里只有 `semesterTotalWeeks` / `firstDayOfWeek`），总周数写死 20。移植件优先取教务的学期周次校历，取不到才按学期序号推算，且**两种情况都写进 `warnings`**。校历第 1 周日期被拒（判为别的学期）时，校历的周数一并作废，总周数回落内置 20 周并写 `warnings`（统一修订 H1）；课表超出总周数时抬高，提醒按来源分开（校历写的周数，或内置的 20 周），不会写出「一学期是 0 周」（统一修订 H2）。学期名同理（上游完全没有学期名这个概念）。
7. **作息优先用教务的**：上游的 11 节表成为回落值（教务作息接口取不到或不合法时用它，并写进 `warnings`）。上游第 9–11 节的 `"endTime"` 写法（带引号的键）是纯写法差异，时间值与其它节一致，移植件不保留这种写法。
8. **桥调用全部不移植**：`showToast`（17 处）、`saveCourses`（L243、L330）、`savePresetTimeSlots`（L278）、`saveCourseConfig`（L337）、`notifyTaskCompletion`（L350）都没有移植。移植件不写任何宿主 UI。
9. **超出作息表的节次按 H3 补（内置或顺推）**：内置表第 12 节（21:15–22:00）与上游第 11 节（21:20–22:30）重叠。移植件对超出教务作息表的每一节：内置表那一节的开始不早于上一节下课就用内置时间；否则从上一节下课起课间 5 分钟、每节 45 分钟顺推。顺推越过当天 23:59 就停，之后的节次不补时间（课程照常导入），并在 `warnings` 里写「课表用到了第 N 节及以后，顺推的时间会越过当天 23:59……」。补上的节次在 `warnings` 里写明来源，请用户在学期管理里核对。这是本件相对内置表的新行为（见 §8）。
10. **报错文字（X2）**：`extract.js` 里学生会看到的报错改掉了两处开发者用语：「教务系统返回 HTTP N」改成「教务系统返回错误（代码 N）」，「返回的不是课表 JSON」改成「返回的内容格式不对」。这些是报错（不是 `warnings`），不进 fixture。

## 8. 没能确定的事（交接给下一位）

- **这所学校的部署到底有没有作息（`cxRjc`）与周次校历（`Zccx`）这两个菜单**：没有账号，无法验证。取不到就是 `null` → 回落 + `warnings`，不会影响导入。

- **上游第 11 节 21:20–22:30 长达 70 分钟**，其它节约 45 分钟。它可能是学校真实的晚自习安排，也可能是上游笔误。移植件照抄上游；导入预览会提示核对。
- **超出作息表的节次是推算，不是学校的真值**：第 12 节等超出教务作息表的节次，按内置表（若不早于上一节下课）或上一节下课后 5 分钟、每节 45 分钟顺推。学校的真实作息若不是这样，需要学校自己的作息数据，本件不猜，导入预览会提示核对。

- **`second-term` 用例里校历的周数已不采信（统一修订 H1）**：校历接口忽略了学期参数、返回的是第一学期的日期，开学日判为不可信并推算；按 H1，这份校历的 18 周一并作废，不再拿来定总周数；总周数回落内置 20 周（课表最大周次 20，与之相同，所以不抬高）。审计者若认为不可信的校历连周数都该另行处理，请提出。

- **作息时间的真值**：内置表照抄上游 11 节，可能与学校实际作息不符；导入预览会提示核对。
