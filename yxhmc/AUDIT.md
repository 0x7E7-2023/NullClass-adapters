# 安全审计 —— 成都银杏酒店管理学院（正方教务系统，根路径部署）

审计对象：`jw-adapters/yxhmc/` 下的 `extract.js` / `parse.js`，以及它们移植自的上游脚本
`shiguang_warehouse` 的 `YXHMC/yxhmc.js`（快照 commit `ff72d1f08782df965cae110034a9d87cd91e0c07`，
2026-10-08，MIT，作者 Xuan-Xuann）。

审计方式：逐行读上游脚本与移植件；跑移植手册 §5 的静态扫描
（`grep -oE "https?://[A-Za-z0-9.-]+"` 与 `grep -nE "fetch\(|XMLHttpRequest|sendBeacon|new WebSocket|\.src\s*="`）；
自检脚本 `check.js` 实跑全部 9 份 fixture；六项变异测试（§6）。

扫描结果：上游脚本里的绝对 URL 只有一个主机 `http://zfjw.gingkoc.edu.cn`，其中**活代码 1 处**
（课表接口，写在 `fetchAndParseCourses` 里），另外 2 处在注释草稿里。移植件的绝对 URL 只有文件头里写上游出处的
`https://github.com`（注释，不是请求）；网络调用只有 `extract.js` 里的一个 `fetch` 包装函数
（`X-Requested-With: XMLHttpRequest` 是请求头，不是 XHR 对象）。

## 1. 请求域与请求清单（本节必须与代码一致，不许写得比代码窄）

上游把主机名写死在课表接口地址里。移植件把主机名去掉了：四条请求的地址都由当前页面的
`window.location.origin` 加上路径拼出来（`jwBase()`，见 `extract.js`），所以**主机只有用户当前所在的那一个教务主机**，
正常就是 `loginUrl` 的 `zfjw.gingkoc.edu.cn`。`allowHosts` 留空，**不写通配**。

本校与上游都是**根路径部署**（地址形如 `/kbcx/...`，没有 `/jwglxt` 前缀）。`jwBase()` 只在当前地址里
`/xtgl/` 或 `/kbcx/` 之前取一段（用来兼容网关前缀），两个标记都没有就直接用 origin。

| 谁 | 方法 | 地址（前缀为 `jwBase()`） | 干什么 | 取不到时 |
|---|---|---|---|---|
| extract.js | GET | `/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` | 读当前学年学期。**只在课表页上读不到 `#xnm` / `#xqm` 时才发**，已经开在课表页时跳过 | 报错：没读到学年学期，请重新登录并打开课表页 |
| extract.js | POST | `/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151` | 取课表 JSON（`kbList` 排课行、`sjkList` 集中实践课、可能的记录总数）。请求体 `xnm=…&xqm=…&kzlx=ck&xsdm=&kclbdm=`，**与上游逐字一致** | 报错：教务系统没有返回课表数据（返回的内容格式不对，多半是登录已失效） |
| extract.js | POST | `/kbcx/xskbcx_cxRjc.html?gnmkdm=N2151` | 取**校区作息**（请求体 `xnm` / `xqm` / `xqh_id`，`xqh_id` 取自课表行） | 交 `null`，parse 回落到内置 13 节表，并写进 `warnings` |
| extract.js | POST | `/kbcx/xskbcxZccx_cxZcByXnxq.html?gnmkdm=N2154` | 取**学期周次校历**（`xnm` / `xqm`），用来定开学日与总周数 | 交 `null`，parse 回落到推算，并写进 `warnings` |

- 后两条接口**不来自上游的启用代码**：上游只请求课表一条；`cxRjc` 只出现在它的注释草稿里，作者写的是
  「数据是获取当天，不确定假期是否正常获取，暂不使用此方案」。移植件照同族正方脚本启用它们，来源见 §5，
  未验证的风险见 §8 第 2、3 条。
- 可选接口失败**不影响导入**：`optionalJson` 把任何失败（网络错、非 2xx、JSON 解析失败）都吞成 `null`；
  但回落本身会出现在导入预览的 `warnings` 里，不是静默降级。
- 请求头只有 `Content-Type` / `X-Requested-With` / `Accept`，**不带自定义令牌**；Cookie 由浏览器按同源规则带上，
  脚本既不读它、也不把它发到别处。
- `parse.js` 不发任何请求（CI 里用 Rhino 实跑，是纯函数）。

## 2. 读了什么（数据面）

| 数据 | 从哪来 | 是否带出 |
|---|---|---|
| 学年学期（`xnm` / `xqm`，下拉框文本如 `2026-2027` / `第一学期`） | 课表页的 `#xnm` / `#xqm`；读不到时从课表首页 HTML 解析（`DOMParser` 离线文档，**不插入当前页面**） | 带出（学期名要用） |
| 排课行 `kbList`（`kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd` / `xqh_id`） | 课表接口 | 带出（这就是课表本身）。parse 只从行里取课程字段写进载荷；`xqh_id` 只用来拼作息请求。行本身原样交给 parse（见 §8 第 4 条） |
| 集中实践课 `sjkList` | 课表接口 | 只带课名，写进 `warnings`（没有星期与节次，排不进周课表，但**不能吞掉**） |
| 校区作息 | `cxRjc` | 带出，只取「第几节 + 起止时间」 |
| 学期周次校历 | `Zccx` | 只用来算开学日与总周数，不整表进载荷 |
| 记录总数（响应里有就取） | 课表接口 | 只用于对账：取到的比总数少就出声 |
| **学生个人信息**（响应顶层的 `xsxx` 之类） | 课表接口 | **不取**：`extract.js` 只挑顶层的 `kbList` / `sjkList` / 记录总数，其它字段一律不碰，也不进 fixture |

不读的东西（静态扫描无命中）：`password` / `pwd` / 登录表单、`localStorage` / `sessionStorage`、
成绩、学籍、缴费，以及任何其它模块的接口。

## 3. 移植手册 §5 八条逐条

| # | 检查项 | 结论 |
|---|---|---|
| 1 | 不碰凭据 | **过**。没有 `password` / `pwd` / 登录表单读取，也没有 `localStorage` / `sessionStorage` 访问。唯一的「凭据」是浏览器自带的会话 Cookie，脚本既不读它也不外发。上游的三个弹窗（`showAlert` 公告、`showPrompt` 手填学年、`showSingleSelection` 选学期）**全部没有移植**：学年学期改成读页面上的 `#xnm` / `#xqm`，一个字段都不问用户要 |
| 2 | 不外发 | **过**。`fetch` 只出现在 `extract.js` 的 `request()` 里；没有 `sendBeacon` / `WebSocket` / `EventSource` / `new Image().src` / 隐藏表单；代码里没有第三方域 |
| 3 | 请求域可控 | **过**。请求主机只有当前页面同源的那一个，正常就是 `loginUrl` 的 `zfjw.gingkoc.edu.cn`（http 还是 https 由用户实际打开的地址决定）。`allowHosts` 为 `[]`，**不写通配**；代码里也没有写死主机名 |
| 4 | 只读课表 | **过**。四条请求全部落在 `/kbcx/*`（课表查询模块：课表页、课表接口、作息、周次校历），**不碰成绩、学籍、缴费**等任何其它接口。课表接口响应里夹带的学生信息一律不带出（见 §2）。作息与周次校历是学校的公共数据，不含个人信息 |
| 5 | 不埋点 | **过**。没有统计、上报、遥测，也没有图片打点 |
| 6 | 不 eval 远程代码 | **过**。没有 `eval` / `new Function`；只对教务自己的响应做 `JSON.parse`。`check.js` 的静态检查也覆盖了这一点 |
| 7 | 不写页面 | **过**。`extract.js` 只**读** `#xnm` / `#xqm` 的值（下拉框或隐藏 input，与上游一样读 `value`）；取课表首页用 `fetch` + `DOMParser` 解析离线文档，**不插入当前页面**，既不改表单，也不触发提交或点击。上游的 `showToast` / `saveImportedCourses` / `saveCourseConfig` / `savePresetTimeSlots` / `notifyTaskCompletion` 等桥调用**全部没有移植**：载荷由 parse 返回，保存交给应用 |
| 8 | 不依赖用户输入之外的秘密 | **过**。没有硬编码的密钥、令牌或学号。脚本里的常量只有菜单号 `N2151` / `N2154`，都是页面上可见的参数 |

**结论：可以进内置库。** 全部请求落在本校教务主机上，只读课表（含作息与周次校历两个只读附加接口），
不碰凭据、不外发、不埋点、不写页面。§8 有几项需要组长知悉或决定，但都不是安全红线。

## 7. 移植时对上游做的删改（都不牵涉安全问题，但审阅者需要知道）

1. **两段式**：上游把取数、解析、保存写在一段里。移植件按手册 §3 第 1 步切开：`extract.js` 只取数（学年学期、`kbList`、`sjkList`、作息、校历、记录总数原样交出），`parse.js` 是纯转换（CI 用 Rhino 实跑的就是它）。
2. **弹窗全部去掉**：上游的开场公告、手填学年、选学期三个弹窗都没有移植，学年学期改成读页面上的 `#xnm` / `#xqm`。要导入别的学期，用户在教务页面里切一下再点「提取课表」（`warnings` 第 1 条会明说这一点）。
3. **同一地址连发两次课表请求**：上游 `fetchAndParseCourses` 对同一地址、同一请求体调用了两次 `fetch`，第一次只为打一条状态日志，且在 `try` 之外。移植件只发一次。
4. **不再整行丢课**：上游要求 `kcmc` / `xm` / `cdmc` / `xqj` / `jcs` / `zcd` 六个字段全部非空，否则整行静默丢掉。移植件只要求课名、星期、节次、周次；缺的教师或教室留空（`null`），跳过的行按原因计数写进 `warnings`。
5. **节次解析放宽**：上游用 `split('-')` 取首尾，`0102` 会被算成第 102 节。移植件认 `1-2` / `第9-10节` / `1,2` / 两位一拼的 `0102`；多段（`1-2,5-6`）按最大跨度放入（中间几节也算上）并写进 `warnings`；超出 1–20 节的行计为缺节次，不进载荷。
6. **周次解析重写**：上游只认「数字-数字周」与「数字周」两种形状，单双只认 `(单)` / `(双)`，`1-16(单周)` 这类写法匹配不上，整段周次变成空数组，课被静默丢掉。移植件认 `1-16周(单)`、`(单)1-16周`、`1-16(单周)`、`1-3,5-9周` 等写法。括号分三类：整段是周次的（`(1-16周)`、`（1-16周）`）保留周次；括号里只有数字的（`(1)`、`(1,2)`）是教学班序号，整组摘掉并写 `warnings`；括号里还有别的字的（`1-16周(3组)`）是备注，整组摘掉并写 `warnings`。落单的括号换成分段符，不直接删，免得两侧数字粘成一个（落单左括号的数字仍会被当成周次，见 §8 第 10 条）。空白当作分段符；单双标记自成一段时并给最近的周次段。
7. **作息表**：上游的 13 节 `TimeSlots` 逐节搬进 `SCHOOL_PERIOD_TIMES`，时间与上游逐字一致。节次超出教务作息表时的补位不照模板件无条件补：内置表那一节的开始不早于上一节下课才用，否则在上一节下课后顺推（见 §4 第 3 条）。上游 `config` 里的 `defaultClassDuration: 50` 与 `defaultBreakDuration: 10` 没有搬，以作息表为准。
8. **开学日与学期名**：上游没有开学日，也没有学期名的概念，总周数写死 20。移植件优先取教务的学期周次校历：第 1 周那一天所在周的周一为开学日；校历周数不够装下课表里的课时，按课表的最大周次抬高总周数，并写明。取不到校历就按学期序号推算开学日；总周数取不到时按 20 周导入，并写进 `warnings`。校历第 1 周的日期被判为不属于这个学期时，那份校历的周数也一并作废，总周数按 20 周导入（课表排到第 20 周以后则按课表的最大周次抬高）。两种来源的提醒分开写：校历给了周数，写「教务校历写的一学期是 X 周…」；课表排到超过内置 20 周而校历没有可用周数（校历作废或取不到），写「课表里有第 N 周的课，超过适配器内置的 20 周…」，不写「一学期是 0 周」。
9. **登录页判断**：上游在 `runImportFlow` 里把 `isLoginPage()` 注释掉了。移植件保留按路径判断的提示：当前地址含 `login_slogin.html` 时直接报错，不发任何请求。
10. **附加接口**：`cxRjc`（校区作息）与 `Zccx`（学期周次校历）为新增，见 §1。取不到就交 `null`，不影响导入。
11. **记录总数对账（新增）**：响应里带了记录总数、而取到的行数比它少时，写进 `warnings`（课表可能被截断）。上游没有这一步。
12. **集中实践课（新增，但不排课）**：上游只读 `kbList`，`sjkList`（集中实践课）直接丢掉。移植件仍不把它排进周课表（它没有星期与节次），但按门数写进 `warnings`，课名最多列 3 门。
13. **桥调用全部去掉**（`showToast`、`saveImportedCourses`、`saveCourseConfig`、`savePresetTimeSlots`、`notifyTaskCompletion`）：parse 直接返回载荷。
14. **文件头署名**：移植件的文件头只署名上游 `YXHMC/yxhmc.js` 与作者 Xuan-Xuann。上游文件头写的是「改编自 重庆化工职业学院」，移植件没有照抄，是否补来源说明由组长定（见 §8 第 8 条）。

1. **明文链路**：登录页与课表接口都是 `http://zfjw.gingkoc.edu.cn`（`manifest.json` 的 `loginUrl` 也是 http）。账号、密码与会话 Cookie 在这条链路上明文传输。这是学校的部署问题，适配器改不了，代码也不擅自把地址升成 https。**需要组长决定**是否在导入前加一句提醒。
