# 安全审计 —— 北方工业大学（正方教务 jsxsd，jwxtbk.ncut.edu.cn）

审计对象：`jw-adapters/ncut/` 下的 `extract.js` / `parse.js` / `manifest.json`，以及它们移植自的上游脚本
`shiguang_warehouse` 的 `NCUT/ncut_01.js`（快照 commit `baf83fa7972d4be6627c534992f7d2da399a0945`，2026-11-10 与 origin/main 对齐，
MIT，维护者 `EnderHCO3`；本校脚本最后一次修改 `1fe584c`，已用
`git -C <快照> log -1 --format=%h -- resources/NCUT/ncut_01.js` 核对，与任务卡一致）。

审计方式：逐行读上游 + 逐行读移植件，跑 `check.js`（Rhino 1.8.0 实跑全部 fixture + 载荷校验 + ES5 + 控制字节 + allowHosts），
再用 Playwright 在 Chromium 里起假教务站实跑 `extract.js`（9 个场景，见第 9 节）。

## 0. 出处与模板

- 上游 `NCUT/ncut_01.js`（131 行）：正方教务服务端渲染课表页，**零网络请求** —— 课表就是当前页面（或同源 iframe）里
  已经渲染好的 `#dv1` 表格。上游把「找文档、读周次下拉框、读节次时间、读课程」和「算周次、拼课程、存配置」写在同一段脚本里。
- 模板选 `hueb`（已审的正方件）：借它的骨架 —— 周次强解析（多段 / 单双标记前置后置 / 共 N 周 / 全角 / 括号备注 / 教学班序号）、
  两阶段合并、H3 补节次、提醒限长与统一出口、学期名与开学日的推算口径。取数层与 `hueb` 完全不同（`hueb` 发四个同源请求拿 JSON，
  本件零请求只读页面），所以 `extract.js` 按上游重写，`parse.js` 只保留骨架。
- 上游同族里没有可直接套的 DOM 取数件；同源 iframe 递归穿透的写法参考了 `lzu`（批次三十二，同样零请求）。
- 在模板之外补的：`#dv1` 是 table 还是外壳两种形态都认；`第1-第8周` 的终点侧「第」（批次十 `swu` 的教训）；
  `.person-class` 里 li 不足 4 个的格子计数；周次下拉框被切到某一周时**拒绝导入**（见第 5 节）。

## 1. 请求清单（与 `extract.js` 逐条对应）

**本件不发任何网络请求**（与上游一致）：课表在用户已经打开的教务页面上，`extract.js` 只读当前 document 与同源 iframe。
`allowHosts` 仍写 `["jwxtbk.ncut.edu.cn"]`（与 `loginUrl` 同源），只为把脚本的作用域写死在这台教务主机上。

| 方法 | 地址 | 干什么 | 取不到时 |
|---|---|---|---|
| — | — | 不发请求 | — |

入口判断（`onJwHost` / `onLoginPage`）在动手前先做：主机不是 `jwxtbk.ncut.edu.cn`、或页面上有密码输入框，直接给大白话提示、不读页面。

## 2. 读了什么、交出去什么（逐字段）

`extract.js` 交出的对象（`buildPayload`）：

| 数据 | 带出的字段 |
|---|---|
| 学年学期 | `term.xnm` / `xnm` 的 value 与下拉框文字、`xqm` / `xqmText`（页面有 `#xnm` / `#xqm` 才有，没有就是空串） |
| 周次下拉框 | `week.values`（每项就是每周日期）、`week.selected` / `selectedText` / `hasAll` |
| 课表行 | `rows[]`：`first` / `last`（首格 `(a, b小节)` 的两个节次号）、`start` / `end`（首格第二个 p 的整段起止时间）、`days`（这一天有课才非空）。**整行没课的大节也交出去**（`days: []`），节次时间表要靠它们 |
| 课程格 | `days[]`：`day`（td.kb-cell 的列序 1..7）、`courses[]`：`name`（`h3 a`）、`weeks`（第 2 个 li）、`teacher`（第 3 个 li）、`location`（第 4 个 li）、`li`（li 的个数） |
| 其他 | `today`（本机日期，只用于推算开学日） |

不带出：页面上其余任何内容 —— 学号、姓名、身份证、手机号、班级、教学班备注、隐藏元素里的文字，一个都不读（只按上面四个选择器取文本）。
冒烟里在页面顶部的 `#xsxx` 与课程格的第 5 个隐藏 li 里都塞了学号 / 姓名 / 证件号 / 手机号，交出的 JSON 里一个都没有（第 9 节）。

`parse.js` 除了上述字段，不读 `__ncInput` 里的其它键；输出只有规范里的载荷字段（`specVersion` / `kind` / `ocrAssisted` /
`warnings` / `terms[].name` / `firstDay` / `totalWeeks` / `periodTimes` / `courses[].name` / `teacher` / `note` / `blocks`）。

## 3. 移植手册 §5 八条逐条结论

1. **不碰凭据**：不读表单值、不读 Cookie / localStorage，不发任何请求。通过。
2. **不外发**：零请求，`extract.js` 里没有任何绝对地址（只有文件头的上游仓库地址，在注释里）。通过。
3. **只读课表**：只读课表页上的 `#dv1` / `#week` / `#xnm` / `#xqm`，不碰成绩、学籍、个人信息页面。通过。
4. **字段白名单**：见第 2 节。通过。
5. **不埋点**：无 `sendBeacon` / `WebSocket` / `new Image`。通过。
6. **不动态执行**：无 `eval` / `new Function`。通过。
7. **不写页面、不提交表单**：只读 DOM，不改任何节点、不点任何按钮。通过。
8. **不硬编码秘密**：无账号、无学号、无令牌。通过。

`check.js` 会提示 `extract.js` 出现 `password` 字样：那是 `onLoginPage` 里的 `input[type="password"]` 选择器（判断是不是登录页），
**只数个数，不读它的值**，也不交出。

## 4. 分析（与模板的不同构之处）

1. **取数形态**：上游零请求，课表是教务已经渲染好的表格。`extract.js` 因此只做 DOM 搬运；所有解析、推断、合并、提醒在 `parse.js`。
2. **找文档**：当前 document 的 `#dv1` 里要有 `table tbody tr`；没有就遍历同源 `iframe` / `frame`（递归、最多 8 个文档、跨域 try/catch 跳过），
   最多等 15 秒、每 300 毫秒看一次（与上游一致）。`#dv1` 既可能是包着课表的外壳，也可能直接写在 table 上，`hasSchedule` 两种都认
   （上游只认外壳形态，见第 6 节）。
3. **节次时间**：每行首格两个 p —— `(1, 2小节)` 与整段起止 `08:00-09:30`。上游算法：**本节开始 + 45 分钟当首节下课**、
   **整段结束 − 45 分钟当末节开始**，每节固定 45 分钟，一行只产出首、末两节。照抄（`addSlot` / `spanOf`）。
   **整行没课的大节（一天开头 1-4 节没课、中间某个大节没人选）同样要读**：上游 `parseTimeSlots` 遍历全部 `#dv1 tbody tr`，
   这里也把这类行（`days` 为空）交出来，否则那几节的真实时间会丢、还会被当成缺节次顺推，生成假的「推不出来」提醒。
   只跳过完全没有节次信息、也不是课表格子的行（表头、上午 / 下午的分隔行）。
   一行跨 3 节及以上时中间几节页面上本来就没有：按「统一修订 H3」从上一节下课后顺推（课间 5 分钟、每节 45 分钟），
   顺推会压到下一节已知时间时**宁可空着**并提醒（`fillGap` / `gapSlots`）。同一节出现两种时间时留第一次、计数并提醒（`slotConflict`）。
   本校没有写死的节次表，所以「整张回落到学校表」这条分支用空课内置的 12 节表（`BUILTIN_PERIOD_TIMES`）。
4. **开学日与总周数**：`#week` 下拉框的 option.value 就是每周日期（`all` 除外）。第一个能认出日期的值当第 1 周，
   有效项个数当总周数（与上游一致），并按手册 §4.3 回退到那一周的周一。没有 `#week` 时按学期锚点推算（开学日）与 20 周（总周数），
   全部写进提醒。课表里出现更晚的周次时把总周数抬到那一周（上限 30）。
5. **学期名**：上游不存学期名。这里优先用页面的 `#xnm` / `#xqm` 下拉框，读不到就用开学日推学年、按月份判第几学期
   （2-7 月第二学期，其余第一学期），得到 `2026-2027学年第一学期` 这样的可读名字；不拿适配器名当学期名。
6. **课程**：`td.kb-cell` 的列序 1..7 = 星期；一个格子里可以有好几门课（`.person-class`），逐门收。
   `.person-class` 里 `h3 a` 是课名，第 2/3/4 个 li 是周次 / 教师 / 教室。li 不足 4 个的格子跳过并计数（上游同样跳过，但不计数）。
7. **周次**：上游只认「一个区间 + 单/双周字样」，这里用模板的强解析（第 5 节第 3 条），上游能读的写法全部读对。
8. **某周视图**：上游 `adapters.yaml` 的说明要求「导入时把『我的课表』后的第 x 周改为全部周次」——页面只显示一周时课表是残缺的。
   移植后由 `parse.js` 直接报错（见第 5 节），不悄悄导入残缺课表。

## 5. 与模板 `hueb` 的差异

- **取数**：模板四个同源 POST（课表、作息、校历），本件**零请求**只读页面；因此 `periodTimes` 与「校历」都来自页面本身。
- **节次时间**：模板用教务接口的逐节作息，取不到整张用学校 13 节表；本件由每行的首、末两节推出整张表（上游算法），
  中间缺的节次顺推补并提醒；没有整张学校表可回落，兜底用空课内置 12 节表。
- **开学日 / 总周数来源**：模板取学期周次校历接口；本件取 `#week` 下拉框（日期清单 + 项数）。
- **学期名**：模板直接用 `#xnm` / `#xqm`；本件优先用它们，读不到就由开学日推学年与学期序号。
- **新增**：周次下拉框被切到某一周时拒绝导入（模板没有这个概念）；li 不足 4 个的格子计数；`第1-第8周` 的终点侧「第」；
  `[1-16周]` 方括号（上游会先把方括号剥掉）；`#dv1` 的两种外壳形态。
- **合并条件**：模板阶段 1 只认「正好接着」（`当前结束 + 1 === 下一开始`），本件改成「下一开始 ≤ 当前结束 + 1」并吸收重叠
  （批次十九 `xsyu` 的教训），重复行先去重。
- **提醒**：模板的「记录总数对账」「集中实践课」「sparse 节次」三条本件没有对应数据（页面上没有总数、没有实践课名单、节次来自行标签），已删。

## 6. 上游里被删掉 / 改掉的东西及理由

- **保存桥**（`saveCourses` / `saveTimeSlots` / `saveConfig` → `window.shiguangBridgePromise.*`、`notifyTaskCompletion`）：
  「拾光」的桥能力，空课由宿主保存，适配器只交载荷。
- **`setTimeout(main, 500)` 与 `catch (e) {}`**：上游所有错误都被吞掉，用户看不到任何原因。这里取不到就抛出可读的错误。
- **`?` 与 `??`、`async/await`、`for...of`、`padStart`、解构**：降到 ES5（Rhino 与旧 WebView）。
- **`parseWeeks`**：上游只认 `(\d+)-(\d+)` 一个区间 + 「单周 / 双周」字样，`1-3,5-9周`、`(单)1-8周,(双)9-16周`、
  `共 N 周`、`(1)` 教学班序号都读不对；换成模板的强解析并保留全部计数与提醒。
- **「缺教师 / 缺教室的课整行丢掉」**：上游 `lis.length < 4` 就 `return`；这里只有课名缺失才丢，教师 / 教室缺就留空并汇总提醒。
- **`duration = 45` 写死**：照抄（本校课表就是 45 分钟一节），作为常量 `SECTION_MINUTES`。
- **`hasSchedule` 只认 `dv.querySelector('table tbody tr')`**：`#dv1` 直接写在 table 上时上游会一直等到超时。这里两种形态都认。
- **周次下拉框被切到某一周时照常导入**：上游只在 `adapters.yaml` 的说明里写「请改为全部周次」，用户不改就导入残缺课表。
  这里直接报错并说明怎么切（`parse.js` 开头那段判断）。
- **节次时间 / 周次的「猜」**：上游没有的推断（开学日推算、缺节次顺推、同节两种时间）全部写进 `warnings`，并把教务原文里的
  课名 / 周次写法 / 备注截到 20 字，保证每条 ≤200 字。

## 9. 浏览器冒烟（Playwright + 假教务站，不联网；`.test/port-batch33/ncut/smoke.py`）

9 个场景全部 OK：

- `basic`：`#dv1` 是外壳（div 包 table）、有 `#week` 与 `#xnm/#xqm` → 学期名 2026-2027学年第一学期、开学日 2026-09-07、总周数 20、3 门课、连堂合成 1-4；
- `iframe`：`#dv1` 写在 table 上、整张表嵌在同源 iframe 里 → 同样解析出 3 门课；
- `no-week`：没有 `#week`、没有学期下拉框 → 开学日按今天的周一推算、总周数 20、提醒里带「推算」；
- `login`：登录页（有密码框）→ 报「当前打开的是教务登录页」，零请求；
- `missing`：没有 `#dv1` → 等满 15 秒后报「没找到课表」，零请求；
- `empty`：`#dv1` 只有表头、没有课程 → 报「课表页上没有读到课程」；
- `week-selected`：周次下拉框停在某一周 → `parse.js` 报「只显示一周……请切到「全部」」；
- `sparse-slots`：**空大节** —— 1-2、3-4、7-8 节整行没课，只有 5-6 与 9-10 有课 → 第 1-10 节时间仍然全部正确（第 1 节 08:00-08:45、第 7 节 14:00-14:45），课程只有两门，没有任何「推不出来」的提醒；
- `other-host`：页面在别的域名上 → 报「当前页面还不是北方工业大学的教务系统」，零请求。

每个场景都检查：`extract.js` 自己一条请求都没发；交出的 JSON 里没有页面上的学号 / 姓名 / 证件号 / 手机号（连课程格里隐藏 li 的那份也没有）；
每条提醒 ≤200 字。

## 10. 已知风险与未验证项

- **没有本校账号，真机没验过**：`#dv1` 的实际外壳形态、`#week` 的 value 是不是纯日期、`#xnm/#xqm` 是否存在、
  `.person-class` 里 li 的顺序（第 2/3/4 个是不是周次 / 教师 / 教室），全部来自上游代码与任务卡，没有拿真实页面对过。
  如果真实页面的 li 顺序不同，周次会认不出并进「数据不全」提醒（不会静默丢课），届时按真实页面调 `courseOf` 的下标即可。
- **周次下拉框停在某一周时直接报错**：这是有意为之（残缺课表的代价比一次报错大），但若某个部署的 `#week` 没有「全部」项、
  又总是选中当前周，用户会一直导不进来。真机上若出现这种情况，应改成「按选中周导入 + 强提醒」并重新评估。
- **节次时间表来自页面本身**：一行跨 3 节及以上时中间节次的时间是顺推的（不是教务给的），已写进提醒；
  同一节两种时间只留第一次出现的，也写进提醒。
- **H3 的表外节次补齐是防御分支**：节次时间表与课程来自同一批行，正常情况下不会出现「课表用到表外节次」，
  所以 `fillTail` / `uncoveredFrom` 两条在当前页面结构下走不到，也没有 fixture 覆盖（写不出来）；保留是为了页面改版后行时间缺失时不至于静默。
  同理，整张回落到空课默认 12 节表的分支也走不到（没有任何一行有时间时，也就没有任何课程）。
- **合并按「名称 + 教师 + 教室 + 星期」判定**：同一门课换教室或换教师不会被合并成一条，会显示成两条安排（内容都对，只是看起来多）。
