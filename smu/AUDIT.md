## 1. 请求域与请求清单（与代码逐条对应）

`allowHosts` = `[]`：所有请求都是同源相对路径，只会打到用户当前打开的教务主机，且 `extract.js` 先确认当前主机名就是 `zhjw.smu.edu.cn`（常量 `HOST`），否则提示先从门户进入教务系统、不发请求。

| # | 方法 + 路径 | 干什么 | 取不到怎么办 |
|---|---|---|---|
| 1 | `GET /new/student/xsgrkb/week.page` | 读学期下拉框 `#xnxqdm` 的默认项（只在当前页面没有下拉框时才请求） | 非 2xx / 网络错 / 没有下拉框 → 进入第 2 步；页面是登录页 → 报「登录已失效」 |
| 2 | `GET /new/student/xlxx/xlxxlist.page` | 同上，上游读学期列表的页面（只在第 1 步也读不到时请求） | 都读不到 → 报「没读到当前学期」，不猜、不问 |
| 3 | `POST /new/student/xsgrkb/getCalendarWeekDatas`，请求体 `xnxqdm=<学期代码>` | 取整学期课表（上游逐字一致的请求体） | 401 / 403 → 报「教务系统拒绝访问（代码 N）」；其它非 2xx → 「教务系统返回错误（代码 N）」；网络失败 → 「连不上教务系统」；非 JSON 或无 `data` → 「没有返回课表数据」；`code` 非 0 → 「没有返回课表数据（代码 N）」；空数组 → 「没有取到课表数据」，整次失败 |
| 4 | `POST /new/xlxx/data`，请求体 `xnxqdm=<学期代码>` | 取校历（周次 + 日期，给开学日与总周数） | 任何失败都交 `calendar: null`，不影响课表；parse 推算开学日、按 20 周给总周数并写进提醒 |

说明：请求头统一带 `Content-Type: application/x-www-form-urlencoded; charset=UTF-8`、`X-Requested-With: XMLHttpRequest`、`Accept: application/json, …`（上游只有课表与校历请求带这几个头，这里对所有请求都带，是超集）。凭证由浏览器的 `credentials: 'include'` 自动带，脚本不读不存。

## 2. 读了什么、交出去什么（逐字段）

读的：教务页面的 `#xnxqdm` 下拉框（选项的值与文字）、学期列表页的 `#xnxqdm`、课表 JSON 的 `data` 数组、校历 JSON 的月块 / 行 / 格（只取 `type`、`value`、`fullText`）。读页面只判断有没有 `input[type="password"]`，不读它的值。

交出去的 `extract.js` 输出（`{ term, today, rows, calendar }`）：

| 字段 | 内容 | 用途 |
|---|---|---|
| `term.code` | 学期代码（原样，只认 `[A-Za-z0-9_-]{1,20}`） | 请求体 |
| `term.label` | 下拉框文字，如「2026-2027学年第一学期」 | 学期名、学年读取 |
| `term.source` | `page` / `default` | 提醒措辞 |
| `today` | 本地日期 `yyyy-mm-dd` | 推算兜底 |
| `rows[]` 的 11 个字段 | `kcmc` 课名、`teaxms` 教师、`jxcdmc` 教室、`jxcdmc2` 教室-周次、`xq` 星期、`zc` 周次、`ps` / `pe` 起止节次、`kkxqdm` 校区编号、`qssj` / `jssj` 教务给的上课时间 | 只这 11 个，其它字段（学号、姓名、身份证、手机号、人员号等）**一律不带出**，见冒烟的泄漏检查 |
| `calendar[]` | `[{zc, rq}]`：周次 + 日期文本（整周没有日期的留一条 `rq: ""`），取不到是 `null` | 开学日与总周数 |

单个字段截到 1000 字，校历最多 600 条，响应体有长度上限（课表 4M、校历 1M、页面 3M）。

## 4. 与模板（gxmu）的差异

选 `gxmu` 而不选 `nenu`：`nenu` 的节次时间来自课表页源码里的 `businessHours`，本校没有这个来源；`gxmu` 是写死节次表，与本校「写死表」的做法一致，两阶段合并与提醒限长也都在。

1. **两张校区节次表**（13 节，逐节照抄上游 `CAMPUS_CONFIG`）替换 `gxmu` 的一张 12 节表；基础校区按课数多数决（上游是「第一个认得的编号」，见 §5）。
2. **新增 `jxcdmc2` 教室周次**（上游的写法，`gxmu` 不读）。
3. **新增自定义时间核对**：开始节次 ≥10 且教务给了 `qssj` / `jssj` 的课，与节次表对比，对不上的按课名汇总提醒（依据手册 §4.4：载荷里没有每门课的自定义时间，只能按节次放，并把差异说出来）。
4. **开学日与总周数改用校历**（`xlxx/data`），删掉 `getDatesOfWeek`；校历的最大周次是总周数，课表排到更晚的周次时抬高并提醒。
5. **学期**：删掉 `gxmu` 的「按日期推算学期代码 + `__ncSelect` 问学期」。学期只认页面上的下拉框；学期名只从下拉框文字读，读不出学年才退回今天所在周的周一。
6. **校区不同的课**：`gxmu` 没有校区概念，这里单独计数、按课名提醒（第 1-9 节时间不同）。
7. **白名单 11 个字段**（比 `gxmu` 多 `jxcdmc2`、`kkxqdm`、`qssj`、`jssj`）。
8. **`noteSample` 截短**：`gxmu` 把备注括号原文直接拼进提醒，这里改为 `shortName` 截到 20 字（「凡拼进教务原文的都截短」）。

| 上游 | 本件 | 理由 |

| `saveCampusTimeSlotsAndConfig` 里的 `showAlert`（「未记录校区提醒」，阻塞弹窗） | 基础校区自动取多数，另一校区的课按课名提醒 | 规则 2：能自动判断就自动判断；校区只影响第 1-9 节时间的一部分课，不值得打断用户。上游是「第一个认得的编号」，这里是多数，见下 |
| `savePresetTimeSlots` / `saveCourseConfig` / `saveImportedCourses` / `showToast` / `notifyTaskCompletion` | 不移植 | 拾光的桥能力；适配器只交载荷 |
| `BASE_URL` 绝对地址 | 同源相对路径 + 主机检查 | 规则 3 与手册 §5 第 3 条：请求域可控，不写死主机 |
| `parseWeeks`：只认逗号数字，非数字的周次整行静默丢弃（`if (!course.weeks.length)`） | `weeksOf`；认不出的计数进提醒 | 「不许静默丢课」；`1-16周(单)`、`第1-第8周`、`共 N 周` 等写法上游会丢课 |
| 行的 `if (!(raw.kcmc && raw.xq && raw.ps && raw.pe)) return;` 静默跳过 | 按原因计数（缺课名 / 星期 / 节次 / 周次）进提醒 | 「不许静默丢课」 |
| `teaxms || "未知教师"`、`jxcdmc || "不用场地"` | 空着（`null`），按类型汇总提醒 | 手册 §4.7：「未知」会被当成真名显示 |
| `mergeAndDistinctCourses` 的按签名分组 | 两阶段合并（`gxmu` 的做法） | 语义不同：上游按「日、名、教师、地点、自定义时间」分组、按节次签名拆周次段，我们只合并首尾相接且周次完全相同的段，不会改变任何一周的安排；上游的合并结果在我们这里可能分得更细，但不会丢课 |
| 自定义时间 `isCustomTime` / `customStartTime` / `customEndTime` | 不进载荷；与节次表核对，对不上的按课名提醒 | 载荷没有每门课的自定义时间字段，手册 §4.4 要求按节次放入，差异写进提醒 |
| `jxcdmc2` 里周次 0 的段（上游 `Number` 不过滤） | 周次超出 1..30 的丢弃并计数 | 载荷校验：周次 1..30 |
| `fetchSemesterCalendar` 的 `totalWeeks` 与 `startDate` | 同样取自校历（`calendarOf`），但开学日回退到周一并与学期锚点核对 | 手册 §4.3（每周从周一开始）与 §4.2 |

- 审计复核后的两处修正：（B1）无逗号前置的单双标记 `(单)1-8周(双)9-16周` 原先输出 1-16 周每周都上，现在按「本段以标记开头时后一个标记归下一段」归属，`(单)1-8周 (双)9-16周` 与后置 `1-8周(单)9-16周(双)` 也都读对，见 fixtures/week-markers 新增三门；（B2）学期名拼进提醒前截到 20 字（`shortName`）。

- fixture 清单（每对的覆盖点见 `manifest.json`）：
  1. `basic`：校本部；连续节次合并；单周与分段周次；奇数周；整学期；缺教师与教室汇总；开学日取校历；总周数取校历；页面选中的学期。

## 9. 没能确定的事与已知风险（我们没有本校账号，真机没验过）

1. **课表页地址未验证**：`scheduleUrlHint` 填的是 `https://zhjw.smu.edu.cn/new/student/xsgrkb/week.page`，这是按乘方平台的常见路径推的。上游从来不请求这个页面（它只请求 `xlxxlist.page`）。若真实的个人课表页不在这个地址，第一步读下拉框会失败，但第二步的 `xlxxlist.page` 仍能给出学期，课表照常导入。需要真机确认。
2. **字段格式只来自上游代码**：`kkxqdm` 的取值 `00001` / `00009`、`jxcdmc2` 的「教室-周次」写法、`qssj` / `jssj` 的 `HH:mm[:ss]`、校历的 `type` / `value` / `fullText` 结构，都是从上游代码读出来的，没有真实响应样本核对。
3. **学期代码形态未知**：上游把下拉框的值原样拼进请求体，这里也原样拼；只认 `[A-Za-z0-9_-]{1,20}`。若真实代码含其它字符，会在第一步被拒（下拉框读不到，报「没读到当前学期」）。
4. **校区多数决 vs 上游的「第一个认得的编号」**：多数决是我们的判断，上游是第一个编号。两校课都有的学生，上游会按第一门课的校区节次时间导入，这里按多数。这是需要主调度确认的决定（见报告）。
5. **自定义时间不在课表里生效**：上游按教务给的时间上课（开始节次 ≥10）；载荷只能按节次放，所以这些课在空课里显示的是节次表时间，差异只通过提醒说出来。
6. **校历总周数可能偏大**：校历的最大周次可能包含考试周等，这时总周数会比教学周多；课表排到的最晚周次只会抬高总周数，不会压低。
7. **节次表没有在本校真机核对**：两张表逐节对照的是上游代码，不是学校公布的节次时间。
8. **上游是乘方 `xsgrkb` 平台的脚本，本件照搬了它的请求方式**；如果学校改了版，任一请求失败都会有对应的大白话提示，不会静默。
