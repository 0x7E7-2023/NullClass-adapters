# 安全审计 —— 泰山学院（青果教务 v2；学生课表页是一张整页表格，开学日来自 V14 第 1 周周课表）

> **宿主策略更新（2026-11-09）**：本文关于 `JwNetworkGate`、提取期冻结/拦截或 JS 沙箱的描述仅记录旧版实现。现行策略对所有适配器一律不自动断网：不拦截网页请求或导航，也不改写页面网络接口。`allowHosts` 仍用于请求目标声明、桥注入和宿主图片下载。

审计对象：`jw-adapters/tsu/` 下的 `extract.js` / `parse.js` / `manifest.json`，以及它们移植自的上游脚本
`shiguang_warehouse` 的 `resources/TSU/tsu_01.js`（397 行，`TSU_01`；快照 `baf83fa7972d4be6627c534992f7d2da399a0945`，2026-11-11 拉取；
`git log -1 -- resources/TSU/tsu_01.js` 实测 `45495fe`（2026-10-07，提交说明「泰山学院(TSU)青果教务适配升级v2组合作息」），与任务卡一致；
MIT，作者 `素绫理`）。上游同目录 `adapters.yaml` 的 `import_url` 是 `http://jwxt.tsu.edu.cn`，原样作为 manifest 的 `loginUrl`；
描述写着「登录教务系统后在任意页面点击【执行导入】即可（课表数据经接口获取，不依赖当前页面）」「脚本会自动提交夏/冬令时组合作息」。

审计方式：逐行读上游脚本与移植件；`check.js` 自检（7 对 fixture 用 Rhino 1.8.0 实跑、载荷校验、ES5 与控制字节扫描、`allowHosts` 检查）；
`extract.js` 用 Playwright 起假教务站在 Chromium 内核里实跑 17 个场景（`.test/port-batch36/tsu/smoke.py`，不联网，假站返回 GBK 编码的网页与 JSON、
V14 周课表按上游注释返回 UTF-8，记录实际请求主机 / 地址 / 请求体 / 请求头，再把输出交给 Rhino 跑 `parse.js`；本机没有装 Playwright 自带的
Chromium，脚本自动退回系统 Edge 内核）；变异测试 6 处，见第 9 节。扫描结果：

- 绝对 URL：`extract.js` 与 `parse.js` 的文件头各有一处上游仓库地址（注释，不是请求）。`extract.js` 的请求地址由 `window.location.origin` 拼出，
  代码里写死的只有教务主机名 `jwxt.tsu.edu.cn`（用来判断「当前页面是不是教务主机」，不是请求目标）。
- 网络调用：只有 `extract.js` 里四处 `fetch`（学期列表、内部学号页、课表页、第 1 周周课表）。`parse.js` 没有任何网络调用。
- 凭据、本地存储、动态执行、信标、WebSocket、`new Image`：全部无命中。`check.js` 对 `extract.js` 的「出现 password 字样」提示来自
  `looksLikeLogin()` 里的一条正则（`type=password`）：它只是在**已经拿到的响应文本**里判断「这是不是登录页」，不读任何输入框的值，不存、不发。
- 内部学号（`xh`）：从学号页隐藏输入框读出（读不到再在当前页面 / 同源框架里找），**只**拼进发往本校教务课表页的 `params` 请求参数；
  不写进交出去的数据、报错、提醒或存储。它属于个人信息，但这是上游接口本身要求的定位参数（不是账号密码），且只发往本校同源地址。
- 上游 `showAlert` / `showSingleSelection` / `showPrompt` / `showToast` / `saveImportedCourses` / `saveCourseConfig` /
  `savePresetTimeSlots` / `saveComboSchedule` / `notifyTaskCompletion` 等宿主桥调用：移植件不调用任何桥（保存由宿主根据载荷完成）。

## 1. 复制模板与取舍

任务卡给了 `wzzy` / `xmcu` 两个候选，选 **`xmcu`**（批次十六，已审计）：本校与它**同平台（青果 v2）、同一条课表页取数路线**——
同一个 `getDropLists.action` 学期列表请求、同一个 `student/wsxk.xskcb10319.jsp?params=<Base64>` 课表页、同样的 GBK 解码、
同样的 `tr` → `td.td`（一格一天）→ `div[style*="padding-bottom:5px"]`（一门课）→ 子节点逐行「课名 / 教师 / 周次[节次] / 地点」、
同样的 V14 第 1 周周课表、同样的「按周的节次集合切段」合并。与 `xmcu` 的实际差别只有：本校**没有子目录前缀和 WebVPN 子域名**、
多一个取内部学号的学号页、节次时间表是 10 节且分夏 / 冬两套（模板 11 节）。`xmcu` 里的审计结论
（缺教师 / 缺地点、`(单)/(双)` 归属、「第1-第8周」、「共 N 周」只剥备注、提醒限长、H3 补节次、学期读法、开学日核对）全部原样继承，
只替换学校相关的常量与文字，并把周次解析换成批次三十五 `imut` 的新写法（混进周次里的节次整段摘除、无逗号连写的单双标记）。

## 2. 请求清单（与代码逐条对应）

**四个请求全部来自本校上游**（`xmcu` 的开学日请求是借同平台的 `wzzy`，本校不用借）。
`<base>` = 当前页面的 `origin`：本校教务直接挂在 `jwxt.tsu.edu.cn` 根上（上游 `JWXT_BASE = window.location.origin`），没有反向代理前缀，
所以不拼任何路径前缀；请求天然同源。

**`allowHosts` 与 `scheduleUrlHint`**：`loginUrl` 就是教务主机 `http://jwxt.tsu.edu.cn/`，四处请求都由 `window.location.origin` 拼出，
与 `loginUrl` 同源，所以 `allowHosts` 写 `[]`（任务卡指定）。`scheduleUrlHint` 按任务卡省略：课表页地址必须带
`params=<Base64(xn&xq&xh)>`，学期和内部学号都随人、随学期变，没有稳定可固定的深链；省略后「一键刷新」打开 `loginUrl`（教务首页），
学生在首页就能点「提取课表」（提取不依赖当前停在哪个页面，只要主机是 `jwxt.tsu.edu.cn`）。

**登录页 / 非教务主机，不发请求**：以下两种情况在发出任何 `fetch` 之前就抛错——
当前路径含 `/login`，**或**当前页面（含同源内嵌框架）里有密码输入框 / 登录表单（`input[type="password"]`、`form[action*="login"]`），
抛「当前打开的是登录页。请先登录教务系统，再点「提取课表」」；页面主机不是 `jwxt.tsu.edu.cn` 时抛「请先登录泰山学院的教务系统……」。
只判路径不够：青果的登录页就挂在根路径上（`loginUrl` 本身），未登录停在该页时路径里没有 `/login`，若不看页面会先发学期列表和学号页两个请求、
最后报「没能读取教务系统里的学生编号」，提示完全跑偏（复审 B1；冒烟 `login-page` / `login-page-root` / `login-root-form` / `portal`）。

与上游的差别（都不牵涉安全）：
- 上游弹窗让用户选学期；移植件按「当前地址 `params` → 页面 `xnxq` 控件 → 按日期判断（并拿学期列表核对）」自动取，只请求一个学期，用了判断值就在 `term.source` 里标明，`parse.js` 据此在提醒里说明。
- 上游开学日取到后弹窗让用户确认；移植件不弹窗，直接采用或按学期推算，并在提醒里请学生核对。
- 上游的 `fetch` 在网络错误时 `showToast` 后静默结束；移植件课表请求失败要抛出明确的报错，不静默。
- 上游只判断「当前地址是否以教务入口前缀开头」，不是就弹一条消息；移植件把登录页 / 非教务主机的页面都在不发请求的前提下给出大白话提示。

## 3. 与上游 / 不同构之处（本件的分析）

1. **课表格子的定位**：上游遍历整页的 `tr`，行内每个 `td.td` 的位置（第几个）就是星期几（没有设上限）。`extract.js` 的 `cellsOf()`
   完整保留这条规则，交出每个格子的 `d`（第几个 `td.td`，从 1 起）。`parse.js` 只收 1-7，更大的计入「所在的格子超出了星期一到星期日的范围」提醒。
   带课程 div 的格子交 `courses`；有文字却没有一个课程 div 的格子（上游会静默漏掉）交 `stray`（前 20 字）并计数提醒；空格子不交。
   一个 `td.td` 都没有 = 不是课表页（`hasTable=false`），与「有表格但没有课」区分开。
2. **一个课程 div 的逐行文字**：上游是子节点逐个取 `textContent.trim()`、去空行，要求至少 3 行、第 3 行整行匹配「周次[起-止]」，
   地点缺了写「未知地点」，缺教师时行数错位整条被静默丢掉。移植件：`extract.js` 逐字保留「每个子节点一行、去空行」（额外跳过注释节点，
   每行最多 200 字），`parse.js` 的 `timeLineOf()` 找**第 2 行起第一个方括号里含数字的行**当时间行；它前面第 1 行是课名，
   第 2 行起到时间行之前都算教师（多行用「、」连起来，没有就是空）；时间行后面第一行是地点（没有就是空）。
   缺教师 / 缺地点照常导入，汇总进提醒（指向「编辑课程」）；找不到时间行的计数说明。时间行方括号**后面**的文字、地点行**之后**的多余行
   （上游都会丢）计数提醒「还有别的文字没有导入」。
3. **周次**：上游 `parseWeeks` 按半角逗号切段，段内含 `-` 的取区间，否则取段里的数字；`1-8单`、`1-8周`、`第1-第8周`、`(单)1-8周`
   这类段会整条读成 NaN 或丢掉数字之间的区间，**整条周次静默丢失**；并且它只在区间分支里判断单 / 双，单写的一周不参与过滤。
   移植件沿用 `swu` / `jyvtc` / `imut` 的 `weeksOf()`（认「周」「第」全角、`~` `至`、`共 N 周` 备注、教学班序号 `(1)`、备注 `(3组)`）；
   它是上游写法的**超集**：`1-16`、`1,3,5` 与上游读出的结果完全相同。按批次三十五补了两条上游没有的写法：
   ① 周次里混着节次（`第5-8节,1-4周`）时节次整段摘除，不许遇到「节」就截断后面的真实周次；
   ② 无逗号连写的前置单 / 双标记（`(单)1-8周(双)9-16周`）后一个标记归下一段，不会退化成 1-16 每周都上。
   标记只管它自己那一段（`1-3,5-9 双` 只有 5-9 取偶数）；**单独写的一周**（没有区间）不受单 / 双影响（与上游同口径）；
   单双同写按每周都上并提醒；超出 1-30 的周次丢弃并计数提醒。
4. **节次**：上游取方括号里 `split('-')` 的第一个和最后一个。`periodRangesOf()` 同样取首尾，并认「第 3-4 节」「1-2,5-6」「1-2 5-6」
   （逗号 / 空白隔开的各算一段），要求 1 ≤ 起 ≤ 止 ≤ 20，读不出（含字母、超范围）计数提醒（上游得 `NaN`，该课静默不进矩阵）。
   单个数字 `[9]` 读成第 9-9 节。
5. **合并**：上游先把同「课名 | 教师 | 地点 | 星期」的所有行合成一组，做「周次 → 节次集合」矩阵，每周把节次集合切成连续段，
   节次段相同的周次归到一起。移植件 `groups` → `matrix` → `patterns` 同一做法；重叠节次（`[1-3]` + `[3-4]`）合成 1-4、
   同课错位按周切段，不丢任何一周；上游用 `|` 拼分组键，课名里带 `|` 会错位，移植件用 `JSON.stringify` 做键。
   课程再按「课名 + 教师」归档，块按（星期、起始节次、结束节次、起始周）排序，输出顺序固定。同一门课换了地点是同一门课的几个块。
6. **学期**：上游弹窗（`showSingleSelection`，默认第 0 项）。移植件先读当前地址的 `params`（学生课表页自己带着 `Base64(xn=…&xq=…&xh=…)`，
   只取 xn / xq），再读页面（含同源框架）里名叫 `xnxq`、值形如 `2026-0` 的控件，都没有才按今天的日期判断
   （8 月到次年 1 月 = 第一学期 `0`，2 月到 7 月 = 第二学期 `1`），并拿学期列表核对：判断出的学期在列表里就用它（`source=guess`），
   不在列表里就用列表第一个（`source=list-first`，与上游弹窗默认选中一致），列表取不到就直接用判断值。**只取这一个学期**，不回退到别的学期。
   学期名优先用学期列表里的名字（教务给的文字），取不到用 `xn-xn+1学年第一/二学期`。
7. **开学日**：上游 `fetchSemesterStartDate` 取 V14 第 1 周周课表里第一个 `<br>月-日`，年份按 `xq === "1" ? xn + 1 : xn` 推；
   移植件 `extract.js` 只交出前 14 处 `MM-DD` 原文，`parse.js` 的 `startFromSchool()` 取其中**第一个周一**，
   核对月份落在合理范围（第一学期 7-10 月、第二学期 1-4 月），通过就采用并提醒「是从周课表读出来的，没法向你确认，请核对」；
   没有周一或月份不合理就不采用，改按学期推算（第一学期 = 9 月 1 日所在周的周一，第二学期 = 2 月 20 日所在周的周一）并提醒；
   没有日期（请求失败）同样推算并提醒。年份读不出的极端情况报错，不编日期。
8. **总周数**：上游取课表里最大的周次（没有课就 20）。移植件取 20 与课表最大周次中较大者（最多 30），写进提醒——
   课表最晚排到第 16 周的学期，应用里也会有 20 周，比上游多出的空周不影响课。
9. **节次时间**：上游提交「夏令时骨架 + 冬令时差量」两套组合作息（`SUMMER_TIME_SLOTS` 全套 10 节、`WINTER_DIFF_SLOTS` 只含第 5-8 节），
   让「拾光」按 5 月 1 日–10 月 7 日 / 10 月 8 日–次年 4 月 30 日自动切换。本应用每学期只能存一套节次时间，移植件统一用**冬令时**
   （10 月 8 日–次年 4 月 30 日，学期主体在这一段），逐节照抄上游两套表合并后的值（`parse.js` 的 `PERIOD_TIMES`）：

   | 节 | 时间 | 节 | 时间 | 节 | 时间 |
   |---|---|---|---|---|---|
   | 1 | 08:00-08:45 | 5 | 14:00-14:45 | 9 | 19:00-19:45 |
   | 2 | 08:55-09:40 | 6 | 14:55-15:40 | 10 | 19:55-20:40 |
   | 3 | 10:00-10:45 | 7 | 16:00-16:45 | | |
   | 4 | 10:55-11:40 | 8 | 16:55-17:40 | | |

   夏令时与冬令时只差第 5-8 节 30 分钟（夏：14:30 / 15:25 / 16:30 / 17:25）。移植件在每次导入时都写一条固定提醒，说明 5 月 1 日至 10 月 7 日
   按夏令时上课、下午第 5 至 8 节比导入的表晚 30 分钟，让学生按实际在「学期管理」里改。每节开始都早于结束，满足载荷校验。
   课表用到第 11 节及以后时按统一修订 H3 顺推补齐（课间 5 分钟、每节 45 分钟）：第 11 节 20:45-21:30、第 12 节 21:35-22:20、
   第 13 节 22:25-23:10，第 14 节顺推会到 24:00，越过 23:59 就停，课程照常导入，补了哪些、哪些补不了都写进提醒（fixture `period-overflow`）。
10. **上游的静默丢课**：缺教师（行数错位）、周次带单双周标记、方括号里节次读不出、周次读不出、没有课程 div 的格子，上游一律不吭声丢掉；
   移植件缺教师 / 缺地点照常导入（`null`），其余各自计数并点名写进提醒。
11. **内部学号**：上游从一个独立的学号页（`xkjg.wdkb.jsp`）的隐藏输入框取 `xh`，再编进课表页的 `params`。移植件照做，
   但只交出「输入框的值」这一个字符串用于拼请求，页面上其余内容（姓名、学号、身份证号等，如果有）一律不读、不交。

## 10. 已知风险与未验证项

- **没有本校账号，真机没验过；也没有任何一份真实的课表响应样本。** `td.td`、`div[style*="padding-bottom:5px"]`、子节点逐行
  「课名 / 教师 / 周次[节次] / 地点」的结构全部来自上游代码；页面如果有别的写法（行首的节次列也带 `td` 类、
  课程 div 的样式写成 `padding-bottom: 5px` 带空格、课名与教师在同一个文本节点里），移植件会按「读不出」或「排版不一样」计数提醒，
  不会静默，但课读不进来。
- **内部学号页**（`xkjg.wdkb.jsp?menucode=S20301`）：上游用它取 `xh`，但页面结构与隐藏框的写法（`id="xh"`）没有真实样本；
  取不到会退回当前页面 / 同源框架的 `#xh`，再取不到就明确报错。若教务改过这个页面，可能表现为「没能读取教务系统里的学生编号」。
- **学期代号格式**：只认 `YYYY-0` / `YYYY-1`（与上游 `code.split("-")`、`xq === "1"` 的用法一致）。若列表里是别的编号
  （如 `2026-2027-1` 或短学期），学期列表会被整体过滤掉，改按日期判断并提醒；此时 `params` 读学期也会失败。
- **V14 开学日**：地址与解析来自本校上游（`fetchSemesterStartDate` 与 `xq === "1" ? xn + 1 : xn`），比 `xmcu` 借用别校的更有依据；
  但仍没有真实样本核对 `MM-DD` 是不是第 1 周周一，所以有「周一 + 月份范围」两道核对，提醒里永远要求学生核对。
- **GBK 解码**：假设教务原样返回 GBK（上游同样按 `gbk` 解码）。若响应实际是 UTF-8 而按 GBK 解码，课名会乱码（结构读得出、文字是错的）。
- **夏 / 冬两套节次时间**：应用每学期只能存一套，统一导入了冬令时；5 月 1 日至 10 月 7 日期间下午第 5-8 节实际晚 30 分钟，
  只能靠提醒让学生去「学期管理」改。反过来，如果学校某年调整了夏令时起止日期或时长，提醒里的日期也要跟着改（目前照上游写死）。
- **星期由 `td.td` 的位置决定**：照上游。若某些行的 `td.td` 数不是 7（行首有同类名的节次格、被 `rowspan` 占位），星期会错位；
  上游同样如此，我们无法判断，提醒里有「星期格超范围」的计数但错位在 1-7 之内不会被发现。
- **总周数**是 20 与最大周次中较大者，不是学校的真实总周数。
- **登录页判断靠页面结构**：`input[type="password"]` / `form[action*="login"]` 是通用特征；若教务在正常页面里也放了密码输入框（例如改密弹窗），会被误判成登录页、直接提示先登录而不发请求（不会外发、不会出错，只是学生需要手动再点一次）。根路径登录页没验证过真实样式，只知道上游脚本本身不判路径。
- **`scheduleUrlHint` 省略**：一键刷新落在教务首页；若首页要求某些初始化（例如必须先点某个菜单）才会话可用，无法发现。提取本身在任意教务页面都能跑。
- `TextDecoder('gbk')` 依赖 WebView 的 Chromium（Android 5+ 的系统 WebView 都有）；不可用时会抛出原生错误，学生看到的是"提取失败"，未做更友好的降级。
