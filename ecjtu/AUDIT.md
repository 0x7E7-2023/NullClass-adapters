## 为什么借这两套骨架

`jw-adapters/` 里没有同平台件。任务卡允许借 `zjut`（正方课表 DOM + 学期下拉）或 `hblgxy`
（强智表格 DOM）的骨架。本件复制 `hblgxy` 的目录结构，因为它已经把本系列踩过的坑写成了现成代码：
周次文字解析（单双、段首序号、`第X周至第Y周`）、提醒限长出口、缺教师 / 缺教室汇总、
节次时间超出内置表时的 H3 补齐、fixture 与 AUDIT 的写法。取数路径、表格结构、字段与合并语义
则完全按 ECJTU 上游重写，没有沿用强智的选择器。

## 上游在做什么（读代码得出的结论）

1. `parseScheduleTable(doc)`：`#courseSche` 从第 2 行（`rows[1]`）开始，每行取 `cells.slice(1, 8)`，
   即第 2～8 个格子依次当周一到周日；只处理 `innerText` 里带 `@` 的格子。
2. `parseCourseLines(lines, day)`：格子里每三行一组 ——「课名 / 教师@地点 / 周次 节次」，
   第 3 行用 `/^([\d,，\-单双()]+)\s+(\d+(?:,\d+)*)$/` 认出周次与节次；`@` 前是教师、后是地点。
3. `mergeCourses()`：按 `课名|教师|地点|星期` 分组，把每周的节次并成集合，再按「连续节次段」
   归并成一组周次 —— 所以同门课不同周次上不同节次时会拆成多条安排。
4. `parseSections()` 只取首尾节次；`mergeCourses()` 再用 `start..end` 把中间节次补满，
   于是 `1,3` 会被并成 `1-3`。本件改成按连续段拆（见下）。
5. 上游写死 10 节节次时间表；`semesterStartDate: null`、`firstDayOfWeek: 1`；
   总周数取 `Math.max(...所有周次)`。

## 逐条（移植手册 §5）

1. **不碰凭据** — 不读登录表单的值、不读 / 存 / 发账号密码，也不碰 `localStorage` / cookie。提取全程在
   用户已登录的页面里发生。`isLoginPage()` 只用 `doc.querySelector('input[type=password]')` 判断
   「这是不是登录页」，不读任何输入框的值（自检脚本因此给出 `password` 字样提示，属预期）。
2. **不外发** — 请求只有上面四个同源地址；没有 `sendBeacon` / `WebSocket` / `new Image()` /
   `EventSource`；`parse.js` 完全不联网（纯转换）。
3. **请求域可控** — 运行时只拼当前页面的 origin；manifest 里 `allowHosts = []`，
   `loginUrl` 是唯一同源主机 `jwxt.ecjtu.edu.cn`。脚本里出现的绝对地址只有提示文案里的
   `https://jwxt.ecjtu.edu.cn/index.action`，与 `loginUrl` 同源。
4. **只读课表** — 只读课表页与学期下拉框。不请求成绩、学籍、考勤、缴费、个人信息。
5. **不埋点** — 无统计、无上报、无遥测。
6. **不 eval 远程代码** — 无 `eval` / `new Function`；取回的 HTML 只交给 `DOMParser`（惰性文档，不执行脚本）。
7. **不写页面** — 不写 DOM、不改表单、不提交、不点页面元素。
8. **不依赖用户输入之外的秘密** — 没有硬编码密钥、令牌、他人学号；学期来自页面下拉框。

## 与上游的差异（删掉 / 改掉的东西及理由）

- **删掉确认弹窗、toast 与三段保存调用**（`showAlert` / `showToast` / `saveCourseConfig` /
  `savePresetTimeSlots` / `saveImportedCourses` / `notifyTaskCompletion`）：空课自己的导入流程负责确认与落库，
  适配器只交数据。
- **格子不再要求带 `@`**：上游 `if (!rawText.includes('@')) return` 会把缺教师或缺教室的整格课丢掉。
  本件交全部行文字，`parse.js` 把缺教师 / 缺教室的课照常导入（null）并按类型汇总提醒。
- **节次列表按连续段拆**：上游 `parseSections()` 取首尾、`mergeCourses()` 补满中间，`1,3` 会变成 `1-3`；
  本件 `sectionRunsOf()` 只合并真正连续的节次，同一天不连续的两段拆成两条安排。
- **星期按表头列号对齐**：上游把 `cells.slice(1,8)` 的下标直接当星期几；本件交整行格子，
  `parse.js` 先认星期表头再取列，认不出表头才按每行最后 7 格回落并提醒。
- **总周数默认 20**：上游取课表最大周当学期长度（第 8 周就结束的课表会被当成 8 周学期）；
  本件默认 20，课表出现更晚的周次才抬高并单独提醒。
- **开学日**：上游 `semesterStartDate: null`；本件按提取当天回退到周一推算，并在提醒里说明。
- **教师 / 地点占位词**：上游写「未知教师」「未排地点」；本件对「未知 / 待定 / 暂无 / 未排」等一律给 null。
- **节次时间**：上游 10 节表逐节照抄；课表用到第 11 节以后时按统一修订 H3 补齐并提醒
  （内置表有这一节且开始时间不早于上一节下课就用它，否则课间 5 分钟、每节 45 分钟顺推，越过 23:59 即停）。
- **周次解析重写**：上游只认 `[\d,，\-单双()]+`（不认「周」「第」「至」）。本件按批次八 / 十 / 十八 / 三十三 /
  三十五的审计结论处理 `1-8周`、`1-8,10-16`、`(单)1-8周,(双)9-16周`、无逗号前置标记
  `(单)1-8周(双)9-16周`、后置标记 `1-8周(单)9-16周(双)`、`第1周至第8周`、裸数字；
  「共 N 周」只剥备注本身；括号里的学分 / 学时 / 节次备注整段摘除，但整段周次写在括号里的 `(1-16周)` 保留。

## 已知风险与未验证项

- **没有本校账号，没有访问过真实教务**：`#courseSche` / `#term` / 三行一格的格子内容全部照上游代码推定，
  真机没验过。拿到真实页面 dump 请替换 `basic` 这组 fixture。
- **格子行序**：上游按 `innerText` 换行取三行一组；本件在惰性文档里改从 `innerHTML` 把 `<br>` 与块级标签
  换成换行。如果真实页面的行之间不是 `<br>` 而是纯行内元素，三行可能连成一行，此时该格会被跳过并计入提醒。
- **rowspan**：`extract.js` 按 `tr.children` 逐格取，不展开 rowspan。不足 7 格的行按标题 / 图例 / 备注行
  直接跳过（不解析、不提醒）；确实像课程行（≥7 格）但比表头短时按「最后 7 格 = 周一到周日」对齐并提醒，
  被并掉的是中间那一列时仍会错位。
- **iframe**：只认同源 iframe，跨域 iframe 读不到。
- **学期名**：`#term` 选中项的文字原样使用；如果教务给的是「2026-2027-1」这类代号，学期名就会是代号。
  取不到时用「华东交通大学 + 学年学期」生成并提醒。
- **周次启发式**：`第X周至第Y周` 依赖「至 / 到」归一；如果教务改用「-」以外的写法（例如「第1周到第8周」
  以外的中文数字），会认不出并计入提醒，不会静默算错。
- **节次 > 30** 按脏数据丢弃并提醒；总周数 > 30 的周次同样丢弃并提醒。
