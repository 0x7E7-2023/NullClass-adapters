# 安全审计 —— 厦门城市职业学院（青果教务，经学校 WebVPN 子域名访问；学生课表页是一张 id 为 mytable 的整页表格）

审计对象：`jw-adapters/xmcu/` 下的 `extract.js` / `parse.js` / `manifest.json`，以及它们移植自的上游脚本
`shiguang_warehouse` 的 `resources/XMCU/xmcu_01.js`（快照 commit `19a65bf07a3e998fcfc69cee692387cdc0523c1a`，2026-10-19 拉取，2026-10-20 复核仍是最新；
本校脚本最后一次修改 `80e30cf`，`git log -1 -- resources/XMCU/xmcu_01.js resources/XMCU/adapters.yaml` 实测一致；MIT，作者 `星河欲转`）。
上游同目录 `adapters.yaml` 只有一个条目 `XMCU_01`，`import_url` 为 `https://eone-443.webvpn.xmcu.edu.cn/`（融合信息门户，原样作为 manifest 的 `loginUrl`），
描述写着「登录后进入融合信息门户，在应用中心找到教务系统并进入，在左侧找到教学安排，点击后即可看到学生个人课表」「非本校开发者适配，如果有误建议提交 issues」。

审计方式：逐行读上游脚本与移植件；`check.js` 自检（8 对 fixture 用 Rhino 1.8.0 实跑、载荷校验、ES5 与控制字节扫描、`allowHosts` 检查）；
`extract.js` 用 Playwright 起假教务站在 Chromium 里实跑 22 个场景（`.test/port-batch16/xmcu/smoke.py`，不联网，假站返回 GBK 编码的网页与 JSON，
记录实际请求主机 / 地址 / 请求体 / 请求头，再把输出交给 Rhino 跑 `parse.js`）；另用 Node 桩跑一遍「课表请求被重定向到登录页」的分支（浏览器的 `route.fulfill` 做不出能被 `fetch` 跟随的重定向）；
变异测试 17 处，见第 9 节。扫描结果：

- 绝对 URL：`extract.js` 与 `parse.js` 的文件头各有一处上游仓库地址（注释，不是请求）。`extract.js` 的请求地址由 `window.location.origin` + `/xmcsjw` 拼出，
  代码里写死的只有教务主机名 `jws-443.webvpn.xmcu.edu.cn`（用来判断「当前页面是不是教务主机」，不是请求目标）。
- 网络调用：只有 `extract.js` 里三处 `fetch`（学期列表、课表页、第 1 周周课表）。`parse.js` 没有任何网络调用。
- 凭据、本地存储、动态执行、信标、WebSocket、`new Image`：全部无命中。`check.js` 对 `extract.js` 的「出现 password 字样」提示来自 `looksLikeLogin()` 里的一条正则
  （`type=password`）：它只是在**已经拿到的响应文本**里判断「这是不是登录页」，不读任何输入框的值，不存、不发。
- 上游 `showAlert` / `showSingleSelection` / `showToast` / `saveImportedCourses` / `savePresetTimeSlots` / `notifyTaskCompletion` 等宿主桥调用：移植件不调用任何桥（保存由宿主根据载荷完成）。

## 1. 复制模板与取舍

任务卡给的候选是 `wzzy` / `jyvtc`，选 **`wzzy`**（批次十四，已审计）：本校与它**同平台（青果）、同作者（星河欲转）、上游取数代码几乎逐字相同**——
同一个 `getDropLists.action` 学期列表请求、同一个 `student/wsxk.xskcb10319.jsp?params=<Base64>` 课表页、同样的 GBK 解码、同样的 `#mytable` → `td.td` →
`div[style*="padding-bottom:5px"]` → 子节点逐行「课名 / 教师 / 周次[节次] / 地点」解析、同样的「按周的节次集合切段」合并。上游两份脚本只差：
上下文路径与主机（`/xmcsjw` + WebVPN 子域名，对 `/wzzyjw` + 裸 IP）、节次时间表（11 节 × 45 分钟，对 13 节 × 40 分钟）、
本校上游**没有**取开学日、本校上游周次解析更弱（见第 3 节）。`jyvtc`（POST 返回网页片段、正则抠行）与本校取数层不同构，不选。
`wzzy` 里的审计结论（缺教师 / 缺地点、`(单)/(双)` 归属、「第1-第8周」、「共 N 周」只剥备注、提醒限长、H3 补节次、学期读法）全部原样继承，没有改动逻辑，只替换了学校相关的常量与文字。

**第三行不是本校上游的请求。** `xmcu_01.js` 从不取开学日（只保存课程和节次时间，没有学期日期）。这个地址与请求形状是**同作者、同平台的 `WZZY/wzzy_01.js`**（`fetchSemesterStartDate`）用的，
已在 `wzzy` 里审计；移植到本校是为了让开学日有真实来源（否则只能一律推算）。它是只读课表页的另一个视图（第 1 周周课表），响应里只抠 `MM-DD`；
本校没有账号，**该地址在本校是否存在 / 返回什么没验证过**——不存在或返回别的东西时，请求被忽略或日期被 `parse.js` 的「周一 + 月份范围」核对挡掉，退回推算并提醒（冒烟 `week-500`，fixture `start-bad` / `period-overflow` / `messy`）。
若主调度认为「不请求上游没有的地址」更重要，删掉 `fetchWeekDates()` 与 `extract.js` 里的调用即可，`parse.js` 无需改（`dates` 缺省时一律推算并提醒）。

`<base>` = 当前页面的 `origin` + 当前路径里 `/xmcsjw` 之前的前缀（若有）+ `/xmcsjw`（`jwBase()`）：
- 路径里有 `/xmcsjw/`（或恰好是 `/xmcsjw`）：取到它为止，前面若有反向代理前缀原样保留（冒烟 `proxy-prefix` 实测）。本校 WebVPN 是**子域名改写**形态（`jws-443.webvpn.xmcu.edu.cn` = 内网 `jws` 的 443 端口），路径没有前缀，`<base>` 就是 `https://jws-443.webvpn.xmcu.edu.cn/xmcsjw`（冒烟 `desk-page` 实测所有请求都落在这个主机上，每个请求都断言了主机名）；
- 路径里没有但主机是 `jws-443.webvpn.xmcu.edu.cn`（例如停在站点根 `/`）：补 `/xmcsjw`（冒烟 `root`）；
- 其它主机（融合信息门户 `eone-443.webvpn.xmcu.edu.cn`、WebVPN 首页 `webvpn.xmcu.edu.cn`、统一认证）返回 `null`，直接抛「请先登录厦门城市职业学院的教务系统（在融合信息门户的应用中心进入教务系统……）」，**不发请求**（冒烟 `portal` / `portal-app-center` / `webvpn-home`）；
- 路径含 `/login`（`/xmcsjw/cas/login.action`、站点根 `/login` 等）：抛「当前打开的是登录页……」，不发请求（冒烟 `login-page` / `login-page-root`）。

**`allowHosts` 与 `scheduleUrlHint`**：`loginUrl` 是上游 `import_url` 原样（融合信息门户 `eone-443.webvpn.xmcu.edu.cn`），而三处请求都发往教务的 WebVPN 子域名 `jws-443.webvpn.xmcu.edu.cn`，
**与 `loginUrl` 不同主机**，所以 `allowHosts` 必须写这一个精确主机名（不写通配 `*.webvpn.xmcu.edu.cn`：那会放行整个 WebVPN 背后所有被改写的内网服务，见移植手册 §5「代理域」一节；
本适配器只请求本主机上的三条固定路径，写精确主机名就够）。提取期间宿主会拦掉其它主机（规范 §3.3）。
`scheduleUrlHint` 写 `https://jws-443.webvpn.xmcu.edu.cn/xmcsjw/`——**这是上游 `checkLoginEnvironment` 里写死的「教务系统入口前缀」，不是一张课表页**；
真正的课表页地址带学年学期 `params`，随学期变，我们没有可以固定的值。放它的原因：一键刷新时若缺省会从 `loginUrl`（门户）打开，门户上本适配器按规定不发请求；
打开教务入口至少能落在教务主机上（会话还在就直接可用）。入口是否要先经过门户单点登录、会话过期时的落点，都没验证过。

与上游的差别（都不牵涉安全）：
- 上游弹窗让用户选学期；移植件按「当前地址 `params` → 页面 `xnxq` 控件 → 按日期判断（并拿学期列表核对）」自动取，只请求一个学期，用了判断值就在 `term.source` 里标明，`parse.js` 据此在提醒里说明。
- 上游弹窗提示「建议在‘课表查询’页面进行导入以确保数据最全」：移植件不弹窗；它直接请求课表页，不依赖当前页面是哪一页（只要在教务主机上），这条建议是否有别的含义（例如课表查询页才会带上某个会话状态）无法验证。
- 上游的 `fetch` 在网络错误时 `showToast` 后返回 `null` 静默结束；移植件课表请求失败要抛出明确的报错，不静默。
- 上游只判断「当前地址是否以教务入口前缀开头」，不是就弹一条消息；移植件把门户 / WebVPN 首页 / 登录页都在不发请求的前提下给出大白话提示。

## 3. 与上游 / 不同构之处（本件的分析）

1. **课表格子的定位**：`#mytable` 里每个 `<tr>`，行内 `td.td` 的位置（第几个）就是星期几（上游同一规则，没有设上限）。`extract.js` 的 `cellsOf()` 完整保留这条规则，
   交出每个格子的 `d`（第几个 `td.td`，从 1 起）。`parse.js` 只收 1-7，更大的计入「所在的格子超出了星期一到星期日的范围」提醒。
   带课程 div 的格子交 `courses`；有文字却没有一个课程 div 的格子（上游会静默漏掉）交 `stray`（前 20 字）并计数提醒；空格子不交。
2. **一个课程 div 的逐行文字**：上游是 `Array.from(div.childNodes).map(textContent.trim()).filter(非空)`，要求至少 3 行，`lines[0]` 课名、`lines[1]` 教师、`lines[2]` 含 `周次[节次]`、`lines[3]` 地点（缺了写「未知地点」）。
   上游的问题：缺教师时 `lines[1]` 是时间行，`lines[2]`（地点）没有方括号，整条课被静默丢掉；只有 2 行（缺教师且缺地点）同样丢。
   移植件：`extract.js` 逐字保留「每个子节点一行、去空行」（额外跳过注释节点，每行最多 200 字），`parse.js` 的 `timeLineOf()` 找**第 2 行起第一个方括号里含数字的行**当时间行；
   它前面第 1 行是课名，第 2 行起到时间行之前都算教师（多行用「、」连起来，没有就是空）；时间行后面第一行是地点（没有就是空）。
   缺教师 / 缺地点照常导入，汇总进提醒（指向「编辑课程」）；找不到时间行的计数说明。时间行方括号**后面**的文字、地点行**之后**的多余行（上游都会丢）计数提醒「还有别的文字没有导入」。
3. **周次**：上游 `xmcu_01.js` 的周次解析**比 `wzzy` 的上游更弱**：按半角逗号切段，含 `-` 的段 `split('-').map(Number)` 取区间，否则 `Number(段)`。
   于是 `1-8单`、`1-8周`、`第1-第8周`、`(单)1-8周` 一律读成 `NaN`——区间循环一次都不进、单个数字成 `NaN` 进矩阵——**整条周次静默丢掉**，这门课在上游导入后根本不会出现；
   并且上游完全没有单 / 双周的概念（写了「单」的段也不会只留奇数周）。我们没有本校真实样本，不知道本校教务是否真的把周次写成纯 `1-16` 这种形态（上游能用说明大概率如此），
   但无论如何，移植件沿用 `wzzy` / `jyvtc` / `swu` 的 `weeksOf()`（按位置归属标记，认「周」「第」全角、`~` `至`、`共 N 周` 备注、教学班序号 `(1)`、备注 `(3组)`），
   它是上游写法的**超集**：`1-16`、`1,3,5` 与上游读出的结果完全相同，上游读不出（会丢课）的写法这里读成合理的周次，不再丢。
   标记只管它自己那一段（`1-3,5-9 双` 只有 5-9 取偶数；`1-8 单,9-16 双` 各管各）；**单独写的一周**（没有区间）不受单 / 双影响；单双同写按每周都上并提醒；超出 1-30 的周次丢弃并计数提醒。
4. **节次**：上游取方括号里 `split('-').map(Number)` 的第一个和最后一个。`periodRangesOf()` 同样取首尾，并认「第 3-4 节」「1-2,5-6」「1-2 5-6」（逗号 / 空白隔开的各算一段），
   要求 1 ≤ 起 ≤ 止 ≤ 20，读不出（含字母、超范围）计数提醒（上游得 `NaN`，该课静默不进矩阵）。单个数字 `[11]` 读成第 11-11 节。
5. **合并**：上游先把同「课名 | 教师 | 地点 | 星期」的所有行合成一组，做「周次 → 节次集合」矩阵，每周把节次集合切成连续段，节次段相同的周次归到一起。
   移植件 `groups` → `matrix` → `patterns` 同一做法；重叠节次（`[1-3]` + `[3-4]`）合成 1-4、同课错位按周切段，不丢任何一周；上游用 `|` 拼分组键，课名里带 `|` 会错位，移植件用 `JSON.stringify` 做键。
   课程再按「课名 + 教师」归档，块按（星期、起始节次、结束节次、起始周）排序，输出顺序固定。同一门课换了地点是同一门课的几个块。
6. **学期**：上游弹窗（`showSingleSelection`，默认第 0 项）。移植件先读当前地址的 `params`（学生课表页自己带着 `Base64(xn=…&xq=…)`），再读页面（含同源框架）里名叫 `xnxq`、值形如 `2026-0` 的控件，都没有才按今天的日期判断
   （8 月到次年 1 月 = 第一学期 `0`，2 月到 7 月 = 第二学期 `1`），并拿学期列表核对：判断出的学期在列表里就用它（`source=guess`），不在列表里就用列表第一个（`source=list-first`，与上游弹窗默认选中的一致），
   列表取不到就直接用判断值。**只取这一个学期**，不回退到别的学期。学期名优先用学期列表里的名字（教务给的文字），取不到用 `xn-xn+1学年第一/二学期`。
   `params` 与 `xnxq` 控件是 `wzzy` 带来的读法，上游没有；控件名 `xnxq` 没有验证（找不到就走判断，提醒里如实说明，不影响正确性）。
7. **开学日**：上游没有。`extract.js` 照 `wzzy` 多取一次第 1 周周课表（第 2 节的第三行），只交出前 14 处 `MM-DD` 原文，`parse.js` 的 `startFromSchool()` 取其中**第一个周一**，
   年份按学期推（第二学期 = 学年起始年 + 1），核对月份落在合理范围（第一学期 7-10 月、第二学期 1-4 月），通过就采用并提醒「是从周课表读出来的，没法向你确认，请核对」；
   没有周一或月份不合理就不采用，改按学期推算（第一学期 = 9 月 1 日所在周的周一，第二学期 = 2 月 20 日所在周的周一）并提醒；没有日期（请求失败）同样推算并提醒。年份读不出的极端情况报错，不编日期。
8. **总周数**：上游取课表里最大的周次（没有课就 20）。移植件取 20 与课表最大周次中较大者（最多 30），写进提醒——课表最晚排到第 16 周的学期，应用里也会有 20 周，比上游多出的空周不影响课。
9. **节次时间**：上游 `importPresetTimeSlots` 写死一张 11 节表，每节 45 分钟，逐节照抄如下（已用脚本与上游逐节比对一致，`parse.js` 的 `PERIOD_TIMES`）：

   | 节 | 时间 | 节 | 时间 | 节 | 时间 |
   |---|---|---|---|---|---|
   | 1 | 08:15-09:00 | 5 | 14:00-14:45 | 9 | 18:30-19:15 |
   | 2 | 09:05-09:50 | 6 | 14:50-15:35 | 10 | 19:15-20:00 |
   | 3 | 10:15-11:00 | 7 | 16:00-16:45 | 11 | 20:00-20:45 |
   | 4 | 11:05-11:50 | 8 | 16:50-17:35 | | |

   上游表里第 9、10、11 节首尾相接（没有课间），第 3 节前有 25 分钟大课间、第 7 节前有 25 分钟——都照抄，没有「纠正」。每节开始都早于结束，满足载荷校验。
   课表用到第 12 节及以后时按统一修订 H3 顺推补齐（课间 5 分钟、每节 45 分钟）：第 12 节 20:50-21:35、第 13 节 21:40-22:25、第 14 节 22:30-23:15，第 15 节顺推会到 24:05，越过 23:59 就停，
   课程照常导入，补了哪些、哪些补不了都写进提醒（fixture `period-overflow`）；空课内置 12 节默认节次表在第 11 节之后与本校表衔接不上，所以没有「先用内置表」那一步。

## 4. 读了什么、交出什么（数据面）

`extract.js` 交出的整个对象（`JSON.stringify`）只有四个顶层键，没有网页原文：

| 键 | 内容 | 用途 |
|---|---|---|
| `term` | `{ xn, xq, source, name }`：学年起始年（4 位数字）、学期编号（`0` / `1`）、`source`（`page` / `guess` / `list-first`）、学期名（学期列表里同 `code` 那一项的 `name`，≤40 字，没有就空串） | 定学期、说明来源、学期名 |

**已知的边界**：课程 div 的逐行文字和 `stray` 是页面原文，若教务把学生个人信息写进课表格子里（我们没有见过），会随之带出；`stray` 限 20 字、每行限 200 字以压低这种风险。

## 10. 已知风险与未验证项

- **没有本校账号，真机没验过；也没有任何一份真实的课表响应样本。** `#mytable`、`td.td`、`div[style*="padding-bottom:5px"]`、子节点逐行「课名 / 教师 / 周次[节次] / 地点」的结构全部来自上游代码的反推；
  页面如果有别的写法（行首的节次列也带 `td` 类、课程 div 的样式写成 `padding-bottom: 5px` 带空格、课名与教师在同一个文本节点里），移植件会按「读不出」或「排版不一样」计数提醒，不会静默，但课读不进来。
- **第 1 周周课表地址**（`showLessonScheduleInfosV14.action`）不在本校上游，是借同平台 `wzzy` 的；本校是否开放、返回的网页里 `<br>MM-DD` 是不是第 1 周周一都没验证。已有「周一 + 月份范围」两道核对，读到"看起来合理但不对"的周一仍然可能，所以提醒里永远要求学生核对。
- **WebVPN 的影响**：假设 WebVPN 原样转发 GBK 字节并保留 `Content-Type`，页面里的 `fetch` 带得上会话 Cookie。若 WebVPN 把网页转码成 UTF-8 而我们按 GBK 解码，课名会乱码（课表读得出结构，但文字是错的）；
  上游同样按 `gbk` 解码，作者自己在这套 WebVPN 上跑通过，只能照信。WebVPN 会话过期时返回的是 WebVPN 自己的登录页，我们靠「带密码框」「最终地址含 `/login`」「`cas/login` 字样」识别；
  若它的登录页三者皆无，学生会看到「教务系统没有返回这个学期的课表页」而不是「登录已失效」，文字仍指向"确认能看到课表后再点"。
- **入口**：学生要从门户（`loginUrl`）进应用中心，再进教务系统，WebView 要先落在教务主机上才能提取；在门户页点「提取课表」只会得到提示。`scheduleUrlHint` 是上游写死的教务入口前缀，不是已验证的课表页，打开后是否直接可用未知。
  上游描述里还说"在左侧找到教学安排，点击后即可看到学生个人课表"，我们不依赖这一步（直接请求课表页），但若教务要求先打开过该页面才初始化会话状态则无法发现。
- **星期由 `td.td` 的位置决定**：照上游。若某些行的 `td.td` 数不是 7（行首有同类名的节次格、被 `rowspan` 占位），星期会错位；上游同样如此，我们无法判断，提醒里有「星期格超范围」的计数但错位在 1-7 之内不会被发现。
- **周次、节次写法没有见过真实样本**：上游注释写的是 `1-8 [3-4]` 这种。`parse.js` 比上游认的写法多，但真实页面如果在方括号后面还写了别的（上游会丢），会被计数提醒。
- **多行教师**（时间行前有 2 行以上）按「、」合并成一个教师字符串；如果其实是课名折成了两行，教师就会带上半截课名——纯启发式，上游遇到这种行数会整条丢掉。
- **学期的读法**：学期列表请求的返回格式（`[{name, code}]`）、`code` 形如 `2026-0` 都来自上游代码；列表的顺序假设"第一个是最新学期"（上游弹窗默认选第 0 项）；`xnxq` 控件名是猜的。按日期判断的学期可能不是学生想要的（例如假期里新学期还没排课），
  只请求一次，没有课就报「还没有课」，提醒里已写明学期的来源，让学生在教务页面里切学期后重点。学期编号只认 `0` / `1`；列表里其它编号（如短学期）会被忽略。
- **总周数**是 20 与最大周次中较大者，不是学校的真实总周数。
- **节次时间**照上游：第 9-11 节首尾相接（19:15 下课、19:15 上课）是上游的写法，若学校实际有课间，需要学生在学期管理里核对。
- `TextDecoder('gbk')` 依赖 WebView 的 Chromium（Android 5+ 的系统 WebView 都有）；不可用时会抛出原生错误，学生看到的是"提取失败"，未做更友好的降级。
