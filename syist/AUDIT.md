## 一、模板选择与分析

**主模板：`gscmxy`**（批次十四已审计的甘肃财贸职业学院）。理由：本校上游与 `GSCMXY/gscmxy.js`、`CTGU/ctgu.js` 同源——课表（`cxxszhxqkb.do`）、
调课（`xsdkkc.do`，请求体含 `*order=-SQSJ`）、位串 `SKZC` 解析、调课 `applyCourseChanges` 的口径逐行一致。`gscmxy` 已带统一口径
（调课按申请时间排序、对不上原课计数、缺教师 / 缺教室汇总、逐节顺推补节次、所有提醒走 `warn()` 限长出口、`/jwapp/` 页面判断、`tableOf` 唯一外壳），
所以直接复制，再改本校专属的几层。候选里 `ctgu` 与 `gscmxy` 几乎同构（少一个校区层）；`njnu` 的调课按教务给的顺序处理，没有申请时间排序，不选。
**节次接口 `jc.do` 的读取与校验借 `nuist`**（`nuist` 是已审计件里唯一读 `jc.do` 并做整表校验 / 回落的；`xjtu` 的 `jc.do` 真机 403、不读）。

### 与模板不同构之处（本校专属）

1. **实验课表**：上游除理论课（`cxxszhxqkb.do`）外，还请求 `modules/syjxkcb/cxsyjxxskb.do`（实验教学课表），行里多一个 `SYXMMC`（实验项目名），
   课名拼成 `KCM - SYXMMC`；教师在没有 `SKJS` 时取 `JSM`。模板没有这一层。见第六节。
2. **节次时间来自教务**：上游 `importPresetTimeSlots` 先读 `jc.do`（`DM` / `KSSJ` / `JSSJ`），读不到才用写死的 12 节 `DEFAULT_TIME_SLOTS`。
   模板（gscmxy）只有写死的 10 节。见下面「节次时间」与第六节。
3. **没有校区**：上游位置只取 `JASMC`（教室名），没有 `XXXQDM_DISPLAY`；模板的「教室(校区)」层整个删除。
4. **合并**：上游 `mergeAndDistinctCourses` 做两阶段合并（节次首尾相接合并、同节次的周次并集）。模板只做「完全重复去重」，本件补上这两步（见第六节）。
5. **校历接口**：上游只用 `cxjcs.do`（体 `XN=…&XQ=…`，取 `rows[0]` 的 `XQKSRQ` / `ZZC`）。模板两个叫法都问（`cxjcs.do` + `cxxljc.do`），本件只问上游用的那一个。
6. **端口 30334**：见下面「端口与 `allowHosts`」。
7. **入口是门户页**：`loginUrl` 就是门户首页（路径含 `/emaphome/`）。学生登录后落在门户，必须自己点开「课程表」进入 `wdkb` 应用才有授权，
   所以在门户页点「提取课表」只给提示、不发请求（`notReadyMessage`，规则沿用 `gscmxy`：主机不对、路径不在 `/jwapp/` 下、含 `login` 或 `/emaphome/` 一律不发请求）。
8. **周次文本**：和模板一样走位串 `SKZC`，没有「单 / 双」文字标记，也没有「共 N 周」备注，所以批次七八的「`(单)` / `(双)` 归属」
   「共 N 周只剥备注」「第 1-第 8 周」几条不适用（没有对应的输入）；位串里的单双周由 `runsOf` 的步长 2 判断，已用 `basic` / `weeks` / `merge` 用例钉住。

### 端口与 `allowHosts`

`loginUrl` 带非标准端口 `:30334`（上游 `import_url` 原样）。宿主的白名单（`JwHostAllowlist.matches` / `JwWebViewStep` 的 `hostOf`）只比较**主机名**，不比较端口；
白名单 = `loginUrl` 的主机 + `allowHosts`。`extract.js` 里全部是相对路径 `/jwapp/sys/wdkb/...`，请求落在当前页面同源（同主机、同端口），所以 `allowHosts` 写 `[]`，
不写端口（`allowHosts` 只收纯主机名）。做法同 `wzzy`。浏览器冒烟里假教务站就跑在 `jwxt.syist.edu.cn:30334` 上，逐条断言每个请求的 `host:port` 都是它。

### 内置备用节次时间（逐节照抄上游 `DEFAULT_TIME_SLOTS`；只在教务的节次表取不到或不合法时用）

| 节 | 开始 | 结束 | 节 | 开始 | 结束 |
|---|---|---|---|---|---|
| 1 | 08:20 | 09:05 | 7 | 15:15 | 16:00 |
| 2 | 09:10 | 09:55 | 8 | 16:05 | 16:50 |
| 3 | 10:10 | 10:55 | 9 | 17:20 | 18:05 |

教务节次表（`jc.do`）可用的条件：每行 `DM` 是节次号、`KSSJ` / `JSSJ` 是合法时间（`HH:mm` 或 `HHmm`，统一成 `HH:mm`）、结束晚于开始、节次号排序后从 1 起连续；
有任何一行不满足就**整表**回落备用表并提醒（`slots-bad`、`slots-gap` 钉住），空表也回落并提醒（`degraded` 钉住）。上游对 `jc.do` 的行不做任何校验。

## 三、读了什么、交出什么

读的接口数据：`datas.dqxnxq.rows[0]` 的 `DM` / `MC`；`datas.cxxszhxqkb` 的 `rows` 与 `totalSize`、`extParams.code` / `msg`；`datas.cxsyjxxskb.rows`；
`datas.xsdkkc.rows`；`datas.cxjcs.rows`；`datas.jc.rows`。不读页面 DOM、`localStorage` / `sessionStorage` / `document.cookie`、表单。

交给 parse.js 的对象（逐字段）：

| 键 | 内容 |
|---|---|
| `term` | `code`（学期编号）、`name`（`MC`，可空）、`source`（`api` / `guess`） |
| `today` | 本机日期 `yyyy-MM-dd`（只用于推算开学日） |
| `rowTotal` | 理论课表接口的 `totalSize`（只用于对账） |
| `rows` | 理论课表行，白名单 10 个字段：`KBID`（排课记录号，调课记录靠它对回原课，不是个人信息）、`KCM`、`SYXMMC`（实验项目名）、`SKXQ`、`KSJC`、`JSJC`、`SKZC`、`SKJS`、`JSM`（教师名）、`JASMC` |
| `experimentRows` | 实验课表行，同上白名单；没取到是 `null` |
| `changeRows` | 调课记录，白名单 16 个字段：`KBID`、`KCM`、`SQSJ`（申请时间，只用于排序）、`TKLXDM`、`SKZC`、`SKXQ`、`KSJC`、`JSJC`、`YSKJS`、`JASMC`、`XSKZC`、`XSKXQ`、`XKSJC`、`XJSJC`、`XSKJS`、`XJASMC`；没取到是 `null` |
| `calendarRows` | 校历行，白名单 4 个字段：`XN`、`XQ`、`XQKSRQ`、`ZZC` |
| `timeSlotRows` | 节次行，白名单 3 个字段：`DM`、`KSSJ`、`JSSJ` |

学号、姓名、身份证号、手机号、调课申请人 / 申请原因等其它字段一律不带出（`pick()` 按白名单逐字段取）。浏览器冒烟的假教务站在课表行、实验行、调课记录、校历行、节次行里
都埋了学号 / 姓名 / 身份证 / 手机号 / 申请原因 / 校历备注，交出的数据与最终载荷里一个都没有（见第七节 E1）。

## 六、上游删改项及理由

- **弹窗与桥交互**（`promptUserToStart` / `selectSemester` / `saveCourses` / `saveConfig` / `importPresetTimeSlots` 里的桥调用 / `showToast`）：空课由宿主负责保存与展示，适配器只交 extract / parse 两段。
- **选学期**（`selectSemester`：先 `xnxqcx.do` 取最近 10 个学期、再 `dqxnxq.do` 取默认项、弹窗选）：改为读教务当前学期（`dqxnxq.do`），读不到按日期推算并提醒；要别的学期请先在教务页面切好。
  上游用被选学期的 `XNDM` / `XQDM` 去问校历；这里从学期编号 `DM`（形如 `2026-2027-1`）拆出 `XN=2026-2027`、`XQ=1`——两者在金智里一致，但没有本校样本核实（见第九节）。
- **实验课合并方式**：上游把实验课表行和理论课行放进同一个数组，凭行里**有没有** `SYXMMC` 字段（`!== undefined && !== null`）判断是不是实验课，课名拼成 `KCM - SYXMMC`。这里同样拼，
  但要求 `SYXMMC` 非空：为空串时上游会拼出「课名 - 」（尾部多一个横杠），这里就用课名；课名为空而有实验项目名时用项目名（上游会拼出「undefined - 项目」或「 - 项目」），免得整行被当作缺课名丢掉。
- **教师 `SKJS.split('/')[0]` / `JSM`**：上游有 `SKJS` 就只取斜杠切开的第一段，没有才取 `JSM`。本校 `SKJS` 究竟是「姓名/工号」还是「甲/乙」没有样本，只留第一段在后一种情况下会悄悄丢人。
  改为按 `/ 、 , ， ; ；` 拆开，丢掉含数字的片段（工号）、去重后以「、」连接；`SKJS` 里一个名字都拿不到（空、全是工号）再试 `JSM`；都没有是 `null`（上游写空串）。
  这比上游多了一种回落（`SKJS` 全是工号时改用 `JSM`），不会让上游能取到的教师变空。
- **教室兜底「待定」**：改为 `null`，按门数汇总进提醒。
- **静默丢行**：上游 `parseSingleCourse` 对缺课名 / 星期 / 节次 / 周次的行返回 `null` 后直接 `filter` 掉，不留痕；改为计数写进提醒。
- **合并（`mergeAndDistinctCourses`）**：保留上游的两个阶段，实现不同：
  ① 阶段 2（同节次的周次合并）→ 先按（课程名 + 教师、星期、起止节次、教室）把周次并成一个集合再切段；② 阶段 1（节次首尾相接合并，要求名称、教师、教室、星期、**整组周次**都一致）→ 这里在并集之后要求**周次段**（起止周 + 单双周）一致。
  上游阶段 1 在周次还没并集的原始行上比较，所以会出现这样的差别（`merge` 用例里的「数值分析」）：1-2 节 1-8 周、3-4 节 1-4 周、3-4 节 5-8 周三行，
  上游阶段 1 因为周次集合不等没合并，阶段 2 把 3-4 节并成 1-8 周后留下 1-2 节、3-4 节两块；这里先并集再合并，得到 1-4 节 1-8 周一块。
  两者覆盖的格子完全相同，只是块的划分更整齐；不丢也不多出任何一节课。上游去重要求教师字符串一致，这里用整理后的教师（去工号、去重）比较，同一个人写法略有不同时也能合并。
- **调课逻辑（`applyCourseChanges`）保留，并补强三处**（上游对这三种情形都静默）：
  1. 记录按 `SQSJ`（申请时间）**从早到晚**处理（仅当每条都带 `SQSJ`；否则保持教务给的顺序）。上游请求带 `*order=-SQSJ`（倒序），按倒序处理时，
     连续两次调同一节课，第二次的「原时间」是第一次排出来的新时间，倒序时还没排出来，对不上而被跳过，结果停在中间状态；
  2. 对不上原课的记录（含 `KBID` 为空）计数提醒。上游用 `c._kbId === kbID`，两边都是 `undefined` 时会误对上，把同星期同节次的别的课去掉周次；这里要求 `KBID` 非空；
  3. 只去掉了原来的周次、没有排新时间的（类型不是 01 / 03，或给的新时间不完整 / 不合法）计数提醒——这种课在那几周会消失，必须让学生知道。
  另：新教室缺省沿用记录里的 `JASMC`（原教室），再缺省取原课的教室，并计数提醒；新教师缺省取 `YSKJS`（原教师）、再缺省取原课的教师（上游到 `YSKJS` 为止）。
  **课名**：上游另排的新课用记录的 `KCM`；这里用被调那门课原来的课名。普通课两者相同；实验课的课名带实验项目（`课名 - 项目`），记录里的 `KCM` 只有课名，
  用记录的会让调课后的实验课丢掉项目名、变成另一门课（`changes` 用例钉住，变异 M10）。
- **开学日**：上游把 `XQKSRQ` 的日期部分原样保存、不回退到周一；空课按周一起算，这里回退到那一周的周一（校历开学日不是周一时用例 `calendar-other` 钉住）。取不到时上游只保存总周数 20，不给开学日（空课必须有），
  这里按本机日期推算当前周的周一并提醒。
- **总周数**：上游 `parseInt(ZZC) || 20`；这里校历优先、取不到用 20，课表更晚就抬高到课表的最大周、校历超过 30 压到 30，各自写提醒。
- **节次时间**：上游读 `jc.do` 后不校验、直接保存；取不到或为空才回落备用表。这里加整表校验（见第一节）。
- **ES6 写法**：可选链、模板串、箭头函数、解构与展开、`for...of`、`includes`、`Set` 全部改为 ES5 等价写法。
- 上游课表行里的 `_kbId` / `_day` 等带下划线的内部字段不保留（调课时只用 `KBID`、星期、节次对课）。

## 九、已知风险与未验证项

我们**没有沈阳科技学院账号，真机没验过**，以下全部取自上游代码或同平台经验，没有本校接口样本：

- **字段名**：`KBID`、`KCM`、`SKXQ`、`KSJC`、`JSJC`、`SKZC`、`SKJS`、`JSM`、`JASMC`，实验课表的 `SYXMMC`，调课记录的 `YSKJS` / `TKLXDM` / `XSKZC` / `XSKXQ` / `XKSJC` / `XJSJC` / `XSKJS` / `XJASMC` / `SQSJ`，
  学期接口的 `DM` / `MC`，校历的 `XQKSRQ` / `ZZC`，节次的 `DM` / `KSSJ` / `JSSJ`。`SQSJ` 上游只出现在请求的排序参数里，响应里是否有同名字段**未核实**；
  没有就保持教务给的顺序，不影响正确性，只是连续两次调课可能停在中间状态。
- **实验课表是否带 `KBID`、`SKZC` 的形状**：上游用同一个解析函数处理实验课行，所以假定它和理论课行同形（`SKZC` 位串、`KSJC` / `JSJC` 节次）。若实验课行没有 `KBID`，
  针对实验课的调课记录会对不上、计入「没能对上课表里原来的课」的提醒（不会误改别的课）。若实验课行的 `SKZC` 不是位串，这些行会被计入「缺少课名、星期、节次或周次」的提醒，不会静默丢。
- **校历行有没有 `XN` / `XQ`**：上游直接取 `rows[0]`，没有核对这两个字段。这里行里有就核对、没有就认；若本校返回的是多个学期的行且又不带这两个字段，会取到第一行（与上游行为一致）。
- **`XN` / `XQ` 的拆法**：上游用学期列表里的 `XNDM` / `XQDM`，这里从 `DM` 拆（`2026-2027-1` → `2026-2027`、`1`）。若本校的 `DM` 不是这种形状，校历取不到（拆不出 3 段则根本不问），
  开学日按本机日期推算并提醒，总周数用 20。
- **调课记录里 `TKLXDM` 的含义**：上游只认 `01` / `03` 才另排新课，别的类型只去周次。我们不知道 `02` / `04` 等具体是什么；
  若有「只换教师不换时间」的类型，按上游口径那几周的课会消失——提醒里会写「其中 N 处只去掉了原来的上课周次，没有排新的上课时间」，学生能看到。
- **调课记录的审核状态**：上游不看审批状态（响应里是否有该字段未知），未通过 / 已撤销的申请若也在记录里，会被一并应用。提醒会写「已按…调整了 N 处」，请学生核对。
- **当前学期接口**：`dqxnxq.do` 在本校是否存在未核实（上游调用它，大概率存在），失败时按日期推算并提醒。
- **节次时间的写法**：假定 `KSSJ` / `JSSJ` 是 `08:20` 或 `0820`；若是别的写法（如带秒的 `08:20:00`），整表会被判不合法而回落备用表并提醒（课表时间仍是上游备用表的值）。
  备用表是上游作者写的，我们没法核实它是不是学校的真实作息。
- **页面判断的路径规则**：「路径以 `/jwapp/` 开头、不含 `login` / `/emaphome/`」是金智通用做法，没有在本校验证。若 `wdkb` 应用在本校的路径不在 `/jwapp/` 下，则上游的硬编码路径本身就不可用。
- **授权**：金智按「应用」授权，没点开过「课程表」时接口 403。本件只给提示，不自动进入应用（应用 id 本校未知）。
- **端口 30334 的协议**：入口是 `http://`（上游原样）。若教务以后改成 https，相对路径跟着页面走，不受影响；`loginUrl` 需要同步改。
- **`loginUrl` 是门户首页**：上游 `import_url` 原样。登录后学生要自己点开「课程表」；**不写 `scheduleUrlHint`**——金智的模块页 URL 当登录跳转目标时新会话会 403（`dlutci` 实测）。
- **总周数**：上游固定 20，本校实际周数以校历为准；校历取不到时可能与实际不符，已提醒。
- **fixture 全部合成**：课名与教师都是虚构的，只保证同样输入得到同样输出、规则覆盖到位，不代表真实教务返回的格式。
