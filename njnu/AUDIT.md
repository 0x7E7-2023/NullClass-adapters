## 零、分析：与模板的不同构之处

**模板选择**：上游 NJNU 是金智 jwapp 的 `wdkb`（我的课表）模块，课表接口 `cxxszhxqkb.do`、周次是 `SKZC` 0/1 位串、节次直接给 `KSJC` / `JSJC`（第几节，不需要字典换算）。
`jw-adapters/` 里同接口的已审计件是 `nuist`（`cxxszhxqkb.do` + `jshkcb/dqxnxq.do` + `jshkcb/cxjcs.do`，字段白名单、不碰学籍接口），选它做模板。
任务卡候选 `whut` 用的是 `kcbcxby` 模块（节次字典 `jcjcx.do`、`cxxskcb.do`），节次要用字典 DM 换算，与本校不同构，只借了它的提醒限长出口（`pushWarning`）。
缺教师 / 教室的汇总提醒与逐节顺推补节次时间（H3）照 `hueb` 的做法，课名截 20 字照 `hueb` 的 `shortName`。

**不同构的地方**（模板没有、按上游重写的）：

1. **调课 / 停课记录**：上游多请求一个 `xsdkkc.do`，把记录应用到课表上（`applyCourseChanges`）。模板没有这一层，`parse.js` 里新写 `applyChange`，语义逐条对照上游（见第三节第 2 条）。
2. **节次时间只有写死的一张 12 节表**（上游 `importPresetTimeSlots`），不读教务的节次接口。所以没有「教务节次表不合法就整表回落」那一套，改成「12 节不够用就逐节顺推补」。
3. **没有校区字段**：上游教室只取 `JASMC`，不拼校区，去掉模板的 `XXXQDM_DISPLAY`。
4. **学期**：上游弹窗让用户填学年、选学期。这里读教务的当前学期（`dqxnxq.do`），读不到按日期推算并提醒。
5. **总周数**：上游写死 20。这里先用校历的 `ZZC`，没有再用 20。
6. **页面入口**：上游 `import_url` 是统一认证页，而取数接口在 `ehallapp.nnu.edu.cn`。用户登录后落在门户 `hsnnu.nnu.edu.cn`，必须自己进「我的课表」，所以 `extract.js` 要判断当前页面是不是教务应用页，不是就给大白话提示、不发请求。
7. **周次是位串**：手册里的「`(单)` / `(双)` 标记归属」「共 N 周」「`第1-第8周`」这几类文字周次问题在本校**不存在**（周次是 0/1 位串，没有文字）。等价的边界是位串切段（连续 / 单周 / 双周 / 落单 / 混排）、位串格式不对、周次超过 30，各有 fixture 钉住。

## 一、请求了哪些域、哪些接口

**只有一个域：`ehallapp.nnu.edu.cn`**（上游调用的主机，已写进 manifest 的 `allowHosts`）。`extract.js` 里全部是**相对路径** `/jwapp/sys/wdkb/...`，请求打到当前页面所在的主机；`extract.js` 开头先判断页面路径是否在 `/jwapp/` 下（`pageProblem`），不在（统一认证页 / 门户页 / 别处）就直接报错、不发任何请求。

| 顺序 | 方法与路径（前缀 `/jwapp/sys/wdkb`） | 请求体 | 干什么 | 取不到（网络错误、非 2xx、返回的不是数据）时 |
|---|---|---|---|---|
| 1 | POST `/modules/jshkcb/dqxnxq.do` | 空 | 当前学年学期（`DM` / `MC`）。**上游没有**，用来代替上游的弹窗 | 按本机日期推算，`source` 记为 `guess`，`parse.js` 提醒 |
| 2 | POST `/modules/xskcb/cxxszhxqkb.do` | `XNXQDM=<学期编号>&`（与上游逐字一致） | 课表行（上游主请求） | **整次提取失败**：403 / 其它错误码 / 网络错误 / 返回的不是数据 / 没有数据表，分别给大白话报错 |
| 3 | POST `/modules/xskcb/xsdkkc.do` | `XNXQDM=<学期编号>&*order=-SQSJ`（与上游一致） | 调课 / 停课记录（上游第二个请求） | 交 `null`，`parse.js` 提醒「没能取到调课、停课记录」，课表按原定排课导入 |
| 4 | POST `/modules/jshkcb/cxjcs.do` | `XN=<学年>&XQ=<学期>`（与上游一致，编码后） | 校历：开学日 `XQKSRQ`、总周数 `ZZC` | 交空数组，`parse.js` 按今天所在周的周一推算开学日、总周数用 20，并提醒 |

- 四个请求**顺序执行，不并发**。请求头：`accept`、`content-type: application/x-www-form-urlencoded; charset=UTF-8`、`x-requested-with: XMLHttpRequest`（上游同款）；`credentials: 'include'`（带 WebView 里已有的会话，与上游一致）。
- 请求体里的 `*order=-SQSJ` 的星号是上游原样，保留。
- 不请求学期列表、学籍、成绩、个人信息、缴费等任何接口；学号不需要（接口按会话身份取数）。
- `allowHosts` 只有 `ehallapp.nnu.edu.cn`（审计修正：原先多列的门户 `hsnnu.nnu.edu.cn` 脚本从不请求，已删）。

## 二、读了什么、交出什么

- **读的响应**：`datas.dqxnxq.rows` 的 `DM` / `MC`；`datas.cxxszhxqkb.rows` 的排课字段；`datas.xsdkkc.rows` 的调课字段；`datas.cxjcs.rows` 的 `XN` / `XQ` / `XQKSRQ` / `ZZC`；课表接口取不到数据表时读 `extParams.msg` 作为报错原因。
- **不读**：页面 DOM（上游也不读）、`localStorage` / `sessionStorage` / `document.cookie`、表单。只读 `location.pathname` 判断页面是否在教务应用下。
- **交给 `parse.js` 的数据**：`term`（`code`、`name`、`source`）、`today`（本机日期）、`rows`、`changeRows`（`null` 表示没取到）、`calendarRows`。**按字段白名单**挑（`pick`），三张表各一份：
  - 课表行 8 个：`KBID`（课表与调课记录对应的号）、`KCM`、`SKJS`、`JASMC`、`SKXQ`、`KSJC`、`JSJC`、`SKZC`；
  - 调课记录 15 个：`KBID`、`KCM`、`TKLXDM`、`YSKJS`、`JASMC`、`SKXQ`、`KSJC`、`JSJC`、`SKZC`、`XSKJS`、`XJASMC`、`XSKXQ`、`XKSJC`、`XJSJC`、`XSKZC`；
  - 校历 4 个：`XN`、`XQ`、`XQKSRQ`、`ZZC`。
  学号、姓名、证件号、手机号、申请人、申请时间（`SQSJ`，只出现在请求体的排序参数里）等一律不带出去。冒烟里往响应中埋了这些字段，交出去的数据里一个都没有。
- 脚本不写入任何存储，不保存令牌，不外发任何数据。

## 三、从上游搬过来的核心逻辑

1. **周次位串**（上游 `parseWeeksFromSkzc`）：第 i 位为 `1` 表示第 i+1 周。上游遇到非 0/1 字符静默忽略；这里整行视为格式不对，计入「周次格式认不出」提醒，不导入。
2. **调课应用**（上游 `applyCourseChanges`）：
   - 按 `KBID` + 星期 + 起止节次找原课（上游同款条件；这里额外要求 `KBID` 非空，避免两边都空时按时间槽误匹配）；
   - 找不到原课的记录整条不处理（上游同款，连新排的那一段也不排），**但计数写进提醒**，不静默；
   - 把记录里 `SKZC` 的周次从原课里减掉；减空的课去掉（上游同款）；
   - `TKLXDM` 为 `01` 或 `03`，并且新周次 / 新星期 / 新起止节次都给了，另排一门新课；新课的教师先取 `XSKJS`，没有取记录里的原教师 `YSKJS`（上游同款），再没有取被调的那门课的教师（**新增**，见第四节）；教室同理（`XJASMC` → 记录里的 `JASMC` → 被调课的教室）；
   - 记录按教务给的顺序逐条应用，后面的记录能匹配前面新排出来的课（上游同款；上游请求带 `*order=-SQSJ`，即申请时间倒序）。
3. **教师**：上游取 `SKJS.split('/')[0]`；这里改为按 `/ 、 , ， ; ；` 拆开，丢掉空片段与含数字的片段（工号），去重后用「、」连接。
4. **节次**：上游直接用 `KSJC` / `JSJC`，这里一样；起止节次不合法（缺失、结束早于开始、超过第 20 节）的行计入跳过。

## 五、与模板（nuist）的差异

模板是 `jw-adapters/nuist/`。本件在模板基础上改了以下各项：

1. 请求地址：模板是写死的绝对地址 `https://jwxt.nuist.edu.cn/...`，本件用相对路径，由「当前页面在 `/jwapp/` 下」保证打到教务应用主机；协议跟随页面（上游写的是 `http://`，页面是 https 时会被浏览器当混合内容拦下）。
2. 页面判断：新增 `pageProblem`，登录页 / 门户页上点「提取课表」时给大白话提示、不发请求。
3. 新增调课 / 停课记录的请求与应用（第三节第 2 条），`parse.js` 新增 `applyChange`，`extract.js` 新增 `fetchChanges`。
4. 字段白名单：课表行多一个 `KBID`（调课对应用），去掉 `XXXQDM_DISPLAY`（上游不拼校区）；新增调课记录白名单。
5. 节次时间：模板读 `jc.do` 并回落 12 节；本校上游只有写死的 12 节，不请求节次接口。超出 12 节的逐节顺推补（H3）：课间 5 分钟、每节 45 分钟，越过 23:59 的不补、课照常导入，补了哪些、哪些补不了都写进提醒。上游的 12 节表不到第 13 节，没有「空课默认节次」可套，所以没有 H3 的「先用空课默认节次」那一档。
6. 总周数：模板是校历 → 位串长度；本件是校历 `ZZC` → 20（上游写死的 20），课表有更晚的周次就抬高，超过 30 按 30 并提醒。
7. 开学日：新增「教务给的开学日不是周一」的提醒（模板只静默对齐到周一），因为对齐是一次推算。
8. 报错：模板对课表接口的 `extParams.code !== 1` 一律报错；本件不依赖这个状态码（本校响应里是否带它没法核实），改为只在取不到数据表时读 `extParams.msg` 当原因。
9. 学期编号：模板直接信任 `DM`；本件要求形如 `2026-2027-1`，否则当作没取到。日期推算口径：9 月起是第一学期，1 月仍算上学年第一学期，2～8 月是第二学期。
10. 提醒出口：模板各条提醒直接拼；本件统一走 `pushWarning`（每条 ≤200 字、总数 ≤20 条，超出补一条「还有 N 条提示没有显示」）。
11. 缺教师 / 教室：模板不提醒；本件按类型汇总，点名课名截 20 字、最多 3 门，提醒指向「编辑课程」。
12. 教室不再拼「（校区）」；多名教师的分隔符与模板一致。

另有一处**对上游的有意增强**：调课新课的教师 / 教室在记录里也缺时，上游会写空串或「待定」，这里退到被调课的原教师 / 原教室（并提醒「沿用调课前的」），避免新排的课凭空丢了教师。

## 六、上游里被删掉 / 改掉的东西及理由

- **全部弹窗与桥交互**（`showAlert`、`showPrompt`、`showSingleSelection`、`showToast`、`notifyTaskCompletion`、`saveCourseConfig`、`saveImportedCourses`、`savePresetTimeSlots`）：只交付 extract / parse 两段纯转换，界面与入库由应用负责。
- **学年、学期输入弹窗与 `validateYearInput`**：不问用户学年学期，读教务当前学期。**代价**：只能导入教务认定的当前学期，不能像上游那样手填别的学年学期。
- **占位词**：教师缺失写空串、教室缺失写「待定」，规范禁止，改为 `null`。
- **静默丢行**（上游 `filter(c => c !== null)`）：改为分类计数写进提醒。
- **总周数写死 20、开学日取不到留空**：改为按第一节所述处理并提醒。
- **绝对地址 `http://ehallapp.nnu.edu.cn/...`**：改为相对路径（第五节第 1 条）。
- **ES6 写法**（箭头函数、模板串、可选链、`async` / `await`、`includes`、展开）：CI 不支持，改成等价的 ES5。
- **`console.log` / `console.error`**：不移植。
- **字段白名单**：上游把整行原样交给解析。本件只保留第二节列出的字段。
- **`_kbId` / `_day` 等临时字段**：上游把它们挂在课程对象上再 `delete`；这里放在 `parse.js` 内部的 item 对象里，不进载荷。
- **载荷字段**：上游 `saveCourseConfig` 的 `semesterTotalWeeks` / `semesterStartDate` 以我们的 `totalWeeks` / `firstDay` 表达，开学日对齐到周一（手册 §4.3）。
