## 一、模板选择与分析

**模板：`ctgu`**（批次十三已审计的三峡大学）。理由：本校上游 `gscmxy.js` 与 `CTGU/ctgu.js` 是同一份代码的两个分支——`diff` 只差
① 本校多了「教室(校区)」的拼接（`XXXQDM_DISPLAY`，课表行与调课记录里各一处）、② 节次时间表、③ 弹窗文案与注释；请求（`cxxszhxqkb.do` + `xsdkkc.do`，
请求头、请求体、`*order=-SQSJ`）、位串 `SKZC` 解析、调课 `applyCourseChanges` 逻辑逐行相同。`ctgu` 已经带了批次十三的统一口径
（调课按申请时间排序、对不上原课计数、缺教师 / 缺教室汇总、H3 逐节顺推、所有提醒走 `warn()` 限长出口、校历两种叫法都问、页面判断），
所以直接复制，只改本校专属的几层。候选里 `njnu` 同样含调课，但它的 `parse.js` 是另一种写法（调课按教务给的顺序处理），
`ctgu` 与本校上游更贴；`nuist` / `whut` 没有调课层，`whut` 还走 `kcbcxby` 模块，不同构。

### 与模板不同构之处（本校专属）

1. **校区**：上游把 `XXXQDM_DISPLAY`（校区名）拼成「教室(校区)」；没有教室只有校区时写「待定」。课表行与调课记录各有一份。见第六节。
2. **节次时间**：10 节、每节 40 分钟（模板是 12 节、45 分钟），课间不等长。顺推补节次的参数相应改成课间 10 分钟、每节 40 分钟。
3. **页面判断**：入口 `loginUrl` 是教务站点根地址（路径只有 `/`），不像模板那样落在一个带 `login` 的路径上。登录后教务应用都在 `/jwapp/` 下，
   所以页面判断改成「主机不对、或路径不在 `/jwapp/` 下、或路径含 `login` / `/emaphome/`」一律不发请求（`njnu` 的 `pageProblem` 也是同样的正向判断）。
4. **周次文本**：和模板一样走位串 `SKZC`，没有「单 / 双」文字标记，也没有「共 N 周」备注，所以批次七八的「`(单)` / `(双)` 归属」
   「共 N 周只剥备注」两条不适用（没有对应的输入）；位串里的单双周由 `runsOf` 的步长 2 判断，已用 `weeks` / `basic` 用例钉住。
   批次十的「第 1-第 8 周」写法同理不会出现。

## 二、请求清单（必须与 `extract.js` 一致）

全部在 `extract.js` 的 `postJson()`（`fetch`，同源相对路径，前缀 `/jwapp/sys/wdkb`，`credentials: 'include'`），**按顺序执行、不并发**。
请求头只有 `Content-Type: application/x-www-form-urlencoded; charset=UTF-8` 与 `X-Requested-With: XMLHttpRequest`（与上游一致）。

| 顺序 | 方法 | 路径 | 请求体 | 干什么 | 取不到时 |
|---|---|---|---|---|---|
| 1 | POST | `/modules/jshkcb/dqxnxq.do` | 空 | 当前学年学期（`DM` / `MC`）。**上游没有**（上游弹窗问用户） | 任何失败按本机日期推算（9 月～次年 1 月 = 第一学期，2～8 月 = 第二学期），`source` 记 `guess`，parse.js 写提醒 |
| 2 | POST | `/modules/xskcb/cxxszhxqkb.do` | `XNXQDM=<学期编号>` | 课表行（上游的请求） | 整次提取失败：403 →「教务系统返回错误（代码 403）：请先在教务首页点开一次「课程表」…」；其它非 2xx →「教务系统返回错误（代码 N）」；非 JSON →「返回的内容格式不对：登录状态可能已失效」；网络错误 →「连不上教务系统」；`extParams.code` 不为 1 且给了 `msg` → 把教务的原话报出来；没有 rows →「没能读到课表数据」 |
| 3 | POST | `/modules/xskcb/xsdkkc.do` | `XNXQDM=<学期编号>&*order=-SQSJ`（上游原样） | 调课 / 停课记录（上游的请求） | 交 `null`（与「没有调课」的空数组区分）；parse.js 提醒「课表可能没有反映最近的调整」 |
| 4 | POST | `/modules/jshkcb/cxjcs.do` | `XN=<学年>&XQ=<学期序号>` | 校历：开学日 `XQKSRQ`、总周数 `ZZC`。**上游没有** | 空数组 |
| 5 | POST | `/modules/xskcb/cxxljc.do` | 空 | 校历的另一种叫法（`dlutci` 真机验过的那一个）。**上游没有** | 空数组 |

- 4、5 都问，rows 合并后由 parse.js 的 `findCalendarRow` 按 `XN` + `XQ` 挑**第一条匹配学期编号**的行；挑不到就按没有校历处理。
  两个接口在不同的金智部署里叫法不同（`nuist` / `xjtu` 用 `cxjcs.do`，`dlutci` 用 `cxxljc.do`），本校是哪个没有账号核实，所以都问；失败不影响课表。
- 没有请求：`xnxqcx.do`（学期列表，上游用于弹窗选学期；我们不弹窗）、`jc.do`（节次时间，上游没有）、`cxxsjbxx.do`（学号，不需要，接口按会话取数）、
  任何成绩 / 学籍 / 个人信息 / 缴费接口。**没有**自动进入门户：上游没有，且应用 id 是各校专属的，本校没有核实；遇到 403 只给提示，让用户自己点开「课程表」。
- 页面判断（`notReadyMessage`）：主机不是 `jwxt.gscmxy.edu.cn`（统一认证页等）、路径不以 `/jwapp/` 开头（站点根地址、`/new/` 之类）、路径含 `login`
  或 `/emaphome/`（门户首页）时，**不发请求**，抛「现在还不在课表页面：请先登录…点开「课程表」…再点「提取课表」」。

## 三、读了什么、交出什么

读的接口数据：`datas.dqxnxq.rows[0]` 的 `DM` / `MC`；`datas.cxxszhxqkb` 的 `rows` 与 `totalSize`、`extParams.code` / `msg`；
`datas.xsdkkc.rows`；`datas.cxjcs.rows` / `datas.cxxljc.rows`。不读页面 DOM、`localStorage` / `sessionStorage` / `document.cookie`、表单。

交给 parse.js 的对象（逐字段）：

| 键 | 内容 |
|---|---|
| `term` | `code`（学期编号）、`name`（`MC`，可空）、`source`（`api` / `guess`） |
| `today` | 本机日期 `yyyy-MM-dd`（只用于推算开学日） |
| `rowTotal` | 课表接口的 `totalSize`（只用于对账） |
| `rows` | 课表行，白名单 9 个字段：`KBID`（排课记录号，调课记录靠它对回原课，不是个人信息）、`KCM`、`SKXQ`、`KSJC`、`JSJC`、`SKZC`、`SKJS`、`JASMC`、`XXXQDM_DISPLAY`（校区名） |
| `changeRows` | 调课记录，白名单 17 个字段：`KBID`、`KCM`、`SQSJ`（申请时间，只用于排序）、`TKLXDM`、`SKZC`、`SKXQ`、`KSJC`、`JSJC`、`YSKJS`、`JASMC`、`XSKZC`、`XSKXQ`、`XKSJC`、`XJSJC`、`XSKJS`、`XJASMC`、`XXXQDM_DISPLAY`；没取到是 `null` |
| `calendarRows` | 校历行，白名单 4 个字段：`XN`、`XQ`、`XQKSRQ`、`ZZC` |

学号、姓名、身份证号、手机号、调课申请人 / 申请原因等其它字段一律不带出（`pick()` 按白名单逐字段取）。浏览器冒烟的假教务站在课表行、调课记录、校历行里
都埋了学号 / 姓名 / 身份证 / 手机号 / 申请原因，交出的数据与最终载荷里一个都没有（见第七节 E1）。

## 六、上游删改项及理由

- **弹窗与桥交互**（`promptUserToStart` / `getAcademicYear` / `selectSemester` / `saveCourses` / `saveConfig` / `importPresetTimeSlots` 里的桥调用 / `showToast`）：
  空课由宿主负责保存与展示，适配器只交 extract / parse 两段。
- **选学年、学期**（`validateYearInput`、`getAcademicYear`、`selectSemester`）：改为读教务当前学期（`dqxnxq.do`），读不到按日期推算并提醒；要别的学期请先在教务页面切好。
  （上游的 `XNXQDM = 起始学年-起始学年+1-学期序号`，和 `dqxnxq.do` 的 `DM` 形状一致。）
- **教室 +「(校区)」**：上游 `finalPosition = campus && classroom ? classroom(campus) : (classroom || '待定')`。保留拼接格式（半角括号）；
  三处不同：① 教室名里已经含有校区名（如「安宁校区理化楼B101」+ 校区「安宁校区」）不再拼，免得出现「安宁校区理化楼B101(安宁校区)」；
  ② 只有校区没有教室时上游写「待定」，这里地点留 `null`（「待定」会被当成真教室显示），按缺地点汇总提醒；③ 校区与教室前后的空白去掉。
- **调课记录里的校区**：上游另排新课时校区取**记录自带**的 `XXXQDM_DISPLAY`、教室取 `XJASMC`，没有再取记录的 `JASMC`。同样保留；在此之上加了一条：
  记录没给新教室、沿用了旧教室，而记录里又没有校区时，补用被调的那门课原来的校区（上游此时会丢掉校区后缀，同一间教室调课前后显示不一致）。
  这是**我们加的**，不是上游行为，`changes` 用例钉住（`K300` 那条）。
- **教师 `SKJS.split('/')[0]`**：按斜杠只留第一段。本校 `SKJS` 究竟是「姓名/工号」还是「甲/乙」没有样本，只留第一段在后一种情况下会悄悄丢人。
  改为按 `/ 、 , ， ; ；` 拆开，丢掉含数字的片段（工号）、去重后以「、」连接；拿不到是 `null`（上游写空串）。
- **教室兜底「待定」**：改为 `null`，按门数汇总进提醒。
- **静默丢行**：上游 `parseSingleCourse` 对缺课名 / 星期 / 节次 / 周次的行返回 `null` 后直接 `filter` 掉，不留痕；改为计数写进提醒。
- **调课逻辑（`applyCourseChanges`）保留，并补强三处**（上游对这三种情形都静默）：
  1. 记录按 `SQSJ`（申请时间）**从早到晚**处理（仅当每条都带 `SQSJ`；否则保持教务给的顺序）。上游请求带 `*order=-SQSJ`（倒序），按倒序处理时，
     连续两次调同一节课，第二次的「原时间」是第一次排出来的新时间，倒序时还没排出来，对不上而被跳过，结果停在中间状态；
  2. 对不上原课的记录（含 `KBID` 为空）计数提醒。上游用 `c._kbId === kbID`，两边都是 `undefined` 时会误对上，把同星期同节次的别的课去掉周次；这里要求 `KBID` 非空；
  3. 只去掉了原来的周次、没有排新时间的（类型不是 01 / 03，或给的新时间不完整 / 不合法）计数提醒——这种课在那几周会消失，必须让学生知道。
  另：新教室缺省沿用记录里的 `JASMC`（原教室），再缺省取原课的教室，并计数提醒；新教师缺省取 `YSKJS`（原教师）、再缺省取原课的教师（上游到 `YSKJS` 为止）。
- **总周数写死 20**：改为校历优先，上游的 20 作为校历取不到时的值。
- **ES6 写法**：可选链、模板串、箭头函数、`for...of`、`includes` 全部改为 ES5 等价写法。
- 上游的 `course._position` / `course._campus` 之类带下划线的内部字段不保留（调课时只用 `KBID`、星期、节次对课）。

## 九、已知风险与未验证项

我们**没有甘肃财贸职业学院账号，真机没验过**，以下全部取自上游代码或同平台经验，没有本校接口样本：

- **字段名**：`KBID`、`KCM`、`SKXQ`、`KSJC`、`JSJC`、`SKZC`、`SKJS`、`JASMC`、`XXXQDM_DISPLAY`，调课记录的 `YSKJS` / `TKLXDM` / `XSKZC` / `XSKXQ` / `XKSJC` / `XJSJC` / `XSKJS` / `XJASMC` / `SQSJ`
  （`SQSJ` 上游只出现在请求的排序参数里，响应里是否有同名字段**未核实**；没有就保持教务给的顺序，不影响正确性，只是连续两次调课可能停在中间状态）。
- **调课记录里 `XXXQDM_DISPLAY` 指的是新校区还是原校区**：上游直接拿它跟 `XJASMC`（新教室）拼；若它其实是原校区而新教室在另一个校区，调课后的地点校区后缀会标错。
  我们照上游口径，没法核实。
- **`TKLXDM` 的含义**：上游只认 `01` / `03` 才另排新课，别的类型只去周次。我们不知道 `02` / `04` 等具体是什么（停课？代课？换教师？）；
  若有「只换教师不换时间」的类型，按上游口径那几周的课会消失——提醒里会写「其中 N 处只去掉了原来的上课周次，没有排新的上课时间」，学生能看到。
- **调课记录的审核状态**：上游不看审批状态（响应里是否有该字段未知），未通过 / 已撤销的申请若也在记录里，会被一并应用。提醒会写「已按…调整了 N 处」，请学生核对。
- **校历接口叫法**：`cxjcs.do` 与 `cxxljc.do` 本校是哪个（或都没有）未核实；都取不到时开学日按本机日期推算并提醒，总周数用上游的 20。
- **当前学期接口**：`dqxnxq.do` 在本校是否存在未核实，失败时按日期推算并提醒。
- **页面判断的路径规则**：「路径以 `/jwapp/` 开头、不含 `login` / `/emaphome/`」是金智通用做法，没有在本校验证。若本校门户首页的路径落在 `/jwapp/` 下且不含
  `/emaphome/`，在门户首页点「提取课表」会先发请求再得到 403 的提示（文案同样指向「先点开课程表」），不会出错，只是提示晚一步。
  若 wdkb 应用在本校的路径不在 `/jwapp/` 下，则上游的硬编码路径本身就不可用。
- **授权**：金智按「应用」授权，没点开过「课程表」时接口 403。本件只给提示，不自动进入应用（应用 id 本校未知）。
- **`loginUrl` 是上游 `import_url`（站点根地址）**：该页登录后跳到哪里未核实，**不写 `scheduleUrlHint`**——金智的模块页 URL 当登录跳转目标时新会话会 403（`dlutci` 实测）。
