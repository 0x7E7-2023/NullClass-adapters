# 安全审计 —— 兰州大学教务适配器（`lzu`）

- 上游：`shiguang_warehouse` 的 `LZU/lzu.js`（MIT，作者 **yalerove**，`adapters.yaml` 的 maintainer）
- 上游快照：`baf83fa7972d4be6627c534992f7d2da399a0945`（2026-11-09 与 origin/main 对齐）；本校脚本最后一次修改 `63e312d`（2026-09-04，`git log -1 -- resources/LZU/lzu.js` 核对过）
- 平台：兰州大学本科生教务 `http://jwk.lzu.edu.cn/academic`（URP 系老教务，服务端渲染页面，没有 JSON 课表接口）
- 移植者：0x7E7-2023（haiku 移植，2026-11-09）
- 审计对象：本目录 `extract.js` / `parse.js` 全文（`extract.js` 只读当前页面与同源框架，`parse.js` 不碰网络与页面）

## 1. 平台与模板选择

本校上游是 URP 系的多策略 DOM 解析件（兰大 `showTimetable` 网格、URP 标准网格、课程列表、纯文本四套回退），
与已审计的 `jxfu`（批次十八，Struts2 + 页面内 `kbxx` 数组）**取数层不同构**：`jxfu` 从页面源码里抠一个 JSON 数组，
本校要从表格 / `td[id]` 的 DOM 结构里读。因此：

- `extract.js` 只做 DOM → 普通 JSON 的搬运，交出去四种结构（见 §3）；上游的四套策略、周次 / 节次解析、去重合并、
  开学日与总周数全部搬进 `parse.js`，CI 里能真跑；
- `parse.js` 的周次解析（单双标记归属、「第」「周」、括号备注、「共 N 周」）、提醒限长、缺教师 / 教室汇总、
  H3 补节次，照模板 `jxfu` 的成品写法复制后按本校改；
- 模板里与本校无关的学期下拉框 / 备用接口 / 日期探测全部删掉（本校没有这些请求）。

选 `jxfu` 是因为它是同批次「URP 系」任务卡指定的模板，且它的后半段（纯转换层、提醒口径、H3）已经过批次十八审计。

## 2. 请求清单（与代码一致）

**本适配器不发任何网络请求。** `extract.js` 只有 DOM 读取（`querySelectorAll` / `innerHTML` / `innerText` / `contentDocument`），
没有 `fetch` / `XMLHttpRequest` / `sendBeacon` / `WebSocket` / `new Image()`，也没有构造任何地址（连相对路径都没有）。
课表就在用户已经打开的页面（以及同源 `<iframe>` / `<frameset>` 子文档）里，上游同样不请求任何接口。

| # | 方法 | 地址 | 干什么 | 取不到时怎么办 |
|---|---|---|---|---|
| — | — | — | 无网络请求 | 页面里没有课表数据时，`parse.js` 报「没有从当前页面里认出任何课程……」，让用户确认页面 / 学期 |

因此 `allowHosts` 为空数组（唯一主机 `jwk.lzu.edu.cn` 与 `loginUrl` 同源），没有 CAS、WebVPN 或第三方域。

## 3. 读了什么、交出去什么（字段白名单）

读取（只在当前页面与同源框架里）：

| 读的东西 | 位置 | 用途 |
|---|---|---|
| 登录页判断 | 顶层页面的 `input[type="password"]`（**只数有没有，不读 `.value`**） | 有就直接报错，不做任何读取以外的动作 |
| 表头节次时间 | `th[id^="0_"]` 或文字里有「第 N 节 + HH:MM」的 `th` | 交给 `parse.js` 认节次号与起止时间（`extract.js:` `collectHeaderSlots`，第 132 行） |
| 课表表格 | 含「周一..周日」表头的 `table`（`hasDayHeader` 第 149 行 / `collectTables` 第 161 行） | 策略 C 行列网格；学生信息表、成绩表不会命中 |
| URP 标准网格 | `td[id*="_"]` 里的 `.class_div > p`（`collectUrpCells` 第 188 行） | 策略 A |
| 表格行 | 含「周 / 星期 / 节 / 学年」等字样的 `tr`，以及它前面那一行课程信息行（`collectRows` 第 250 行） | 策略 B |
| 正文行 | 同上过滤后的 `body.innerText` 行（`collectText` 第 270 行） | 策略 B2 + 学期名 |

交出去（`extract.js:304` `JSON.stringify`）：

```
{ today, headerSlots:[{id,text}], tables:[{rows:[[{id,lines}]]}],
  urpCells:[{id,divs:[[文本]]}], listRows:[[单元格文本]], textLines:[文本], truncated }
```

- 每个格子的一行文字最多 300 字（超出截断并交 `truncated: true`）；表格最多 30 张、单表 400 行、正文 4000 行、URP 格 500 个；
- **个人信息过滤**（`safeLine` 第 60 行）：含「学号 / 姓名 / 身份证 / 手机号 / 考生号 / 准考证 / 性别 / 出生日期 / 籍贯 / 民族 / 政治面貌」的
  行整行不交；只有纯数字且 ≥8 位的正文行（身份证号 / 手机号 / 学号）整行不交（`bareNumber` 第 245 行）；
  非课表的表格行只有在「有课程号样式 + 有非数字文字」且下一行与课表有关时才交（`looksCourseInfo` 第 231 行）；
- `parse.js` 只交载荷需要的字段：课名、教师（可为 null）、地点（可为 null）、星期、起止节次、周次段 / 单双周、学期名、
  开学日、总周数、节次时间；`today` 只用于推算兜底，不涉及个人信息；
- 教师姓名与教室属于课表本身的内容（载荷里要用），不算个人信息。

冒烟里在正文、学生信息表、课表页源码里都放了学号 / 身份证号 / 手机号 / 姓名和自造标记，确认 `extract.js` 输出里一个都没有。

## 4. 与上游的差别

1. **两段式**：上游是「拾光」的整段流程（`showAlert` 确认、四套策略、合并、`saveImportedCourses` / `savePresetTimeSlots` /
   `saveCourseConfig`、`showToast`、`notifyTaskCompletion`）；这里 `extract.js` 只交页面结构、`parse.js` 只交载荷，不调用任何宿主桥。
2. **策略顺序按上游代码**：`parse.js:864` 的 `strategies` 依次是「行列网格（策略 C）→ URP 标准网格（策略 A）→ 表格行（策略 B）→
   正文行（策略 B2）」，取第一个有课的结果。任务卡正文写的是 C → B → A → B2，与上游代码（`lzu.js` 第 557-562 行）不一致；
   按公共说明「取数路径一律以代码为准」，这里跟代码。`parse.js` 的四种策略各自对应：`strategyGrid` 第 529 行（网格视图）、
   `strategyUrp` 第 569 行（URP 标准网格）、`strategyList` 第 668 行（课程列表 / 选课结果）、`strategyText` 第 720 行（纯文本兜底）。
3. **iframe / frame 递归穿透**照上游：`extract.js` `allDocuments` 第 112 行沿 `iframe, frame` 的 `contentDocument` 递归，
   最多 8 个文档；跨域框架取不到就跳过，不报错。
4. **节次时间**：先认页面表头（`parse.js` 第 897-924 行，`th[id^="0_"]` 或「第 N 节 HH:MM-HH:MM」），**四种策略都会读**；
   读不到才回落上游写死的兰大秋季 11 节表，并在提醒里说明「用的是学校公布的秋季节次时间、春季学期的上课时间可能不同」。
5. **开学日与学期名**：上游完全没有（`semesterStartDate: null`）。这里从页面文字里认「20xx-20xx 学年第一 / 第二学期」
   （`findTerm` 第 388 行），认不到按今天的日期推断学期（`inferParts` 第 425 行），再按
   「第一学期 = 9 月 1 日所在周的周一 / 第二学期 = 2 月 20 日所在周的周一」推算（第 1007-1011 行），**一律写进提醒**；
   总周数取 20，课表更晚就抬高（最多 30），也写进提醒。
6. **周次 / 节次解析重写**：上游 `parseWeeks` / `parseSections` 只认逗号分隔数字与 `a-b`；这里认单双周（含无逗号的前置标记
   `(单)1-8周(双)9-16周`、后置 `1-8周(单)9-16周(双)`）、「第」「周」字、括号备注 / 教学班序号、「共 N 周」（只剥备注本身）、
   全角数字与各种破折号，认不出的计数进提醒（`weeksOf` 第 201 行）。
7. **缺教师 / 缺教室**：上游给空串、教室默认写「未知地点」；这里一律记成 `null` 并按类型汇总提醒（`cleanField` / `normalizeBlock` 第 760 行），
   指向「编辑课程」。
8. **去重与合并**：上游按「课名 + 教师 + 地点 + 星期 + 周次」分组，把相邻节次合并（`start <= end + 1`）并把周次取并集；
   这里同样合并同日同节的重复行与相邻节次，但**只在周次集合完全相同时合并**（`mergeBlocks` 第 792 行），不把不同周次拼成一段；
   上游「起始节次 > 11 就丢掉」的课照常导入，超出 11 节的按 H3 补时间。
9. **课名清理**：上游 `cleanCourseName` 最后一步 `replace(/[;0-9]+$/,'')` 会把「大学英语2」这种课名末尾的数字也吃掉；
   这里只去掉 `;数字` 这种课程号后缀。上游 `parseSections` 把「12」读成第 1-2 节（本校最多 11 节，没有歧义）。
10. **登录页**：页面上有密码输入框就直接报错、不读值、不发请求；上游没有这一步。
11. **诊断信息**：上游失败时 `collectDiagnostics` 会把页面 URL 尾部、表格 DOM 骨架、首个课程格的 `innerHTML` 前 500 字
    弹给用户（`console.error` 还会打印错误），这里全部删掉——那会把页面内容与个人信息带进提示，也不符合给学生看的文案。
12. **提示文案**：上游的 `showAlert` / `showToast` 不移植；所有给学生看的文字都在 `parse.js` 的 `warn`（第 149 行）与
    `throw`（第 30、886、889、893 行）里，按 `docs/ux-writing.md` 写，不出现实现细节。

## 9. 已知风险与未验证项（如实记录）

- **没有本校账号，真机没验过。** fixture 与冒烟都是按上游代码读取的结构合成的，只保证「同样输入 → 同样输出」，
  不保证真实教务页面的 DOM 与合成页一致。
- **本校是 http 明文入口**（`loginUrl` 与课表页都是 `http://jwk.lzu.edu.cn`）：登录凭据在链路上不加密，空课会显示「不安全连接」标记。
- 真实环境才能验的：网格视图的单元格是否真的是 `<br>` 分行、`td` 的 id 是否形如 `星期-序号`、表头 `th[id^="0_"]` 是否带时间、
  课程列表 / `index_frame.jsp` 的行结构、页面上学期文字的具体写法（「2026-2027学年第一学期」还是「2026-2027学年 第1学期」等）。
- **策略顺序跟上游代码**（C → A → B → B2），与任务卡正文的 C → B → A → B2 不同；如果主调度要求以任务卡为准，改 `parse.js:864` 的数组顺序即可。
