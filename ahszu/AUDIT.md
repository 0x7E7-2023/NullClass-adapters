审计对象：`jw-adapters/ahszu/` 下的 `extract.js` / `parse.js` / `manifest.json`，以及它们移植自的上游脚本
`shiguang_warehouse` 的 `resources/AHSZU/ahszu_01.js`（快照 commit `19a65bf07a3e998fcfc69cee692387cdc0523c1a`，2026-10-19 拉取；

## 1. 复制模板与取舍

任务卡的候选是批次十四的 `wzzy`（同样的 `cas/login.action` 入口）与批次十三的 `jyvtc`。选 **`wzzy`** 当模板，理由：本校上游脚本和 `wzzy` 的上游 `WZZY/wzzy_01.js`
是同一份代码骨架——同一个学期列表请求（`getDropLists.action`，同一个请求体）、同一个课表请求（`wsxk.xskcb10319.jsp?params=<Base64>`，GBK 整页）、
同一套课表格子规则（`#mytable` → `td.td` 一格一天 → `div[style*="padding-bottom:5px"]` 一门课 → 子节点逐行「课名 / 教师 / 周次[节次] / 地点」）、同一个「同课名 / 教师 / 地点 / 星期合并」。
`jyvtc` 是 POST 返回网页片段、用正则抠 `mykb` 行的另一种布局，不同构。

与 `wzzy` 实际不同的只有三处：
1. **常量**：上下文路径 `/suzxyjw`、教务主机 `211.86.128.194`（80 端口，没有端口号）、学校名、**11 节**节次时间（每节 45 分钟）。
2. **没有开学日请求**：`wzzy` 的上游还 POST 一次第 1 周周课表去抠开学日（`showLessonScheduleInfosV14.action`），本校上游**没有**这一步，也不设学期配置。
   所以 `wzzy` 的 `fetchWeekDates()`（extract）、`startFromSchool()` 与「周课表日期是不是周一 / 月份合理」整段（parse）、`dates` 顶层键、三条开学日提醒里的两条，**整段不带过来**。
   开学日一律按学期推算（第一学期 = 9 月 1 日所在周的周一，第二学期 = 2 月 20 日所在周的周一）并提醒学生核对。
3. 上游本校脚本**有**登录页判断（`currentUrl.includes(loginUrl)` 就提示先登录并退出），`wzzy` 的上游没有；移植件两者都做：路径含 `/cas/login` 不发请求，另外不在教务主机的页面也不发请求。

周次解析 `weeksOf()`、`runsOf()`、提醒限长出口 `warn()` / `shortName()`、H3 顺推、合并（矩阵 → 连续节次切段 → 同节次段的周次归到一起）都是 `wzzy` 已审计的成品，
对照「审计真抓到过的错」逐条自查（见第 7 节），本批用 `ahszu` 自己的 fixtures 重新钉了一遍。

## 2. 请求清单（与代码逐条对应）

| 谁 | 方法 | 地址 | 干什么 | 取不到时 |
|---|---|---|---|---|
| `extract.js` `fetchTermList` | POST | `<base>/frame/droplist/getDropLists.action`，体 `comboBoxName=StMsXnxqDxDesc&paramValue=&isYXB=0&isCDDW=0&isXQ=0&isDJKSLB=0&isZY=0`，请求头 `Content-Type: application/x-www-form-urlencoded; charset=UTF-8`（与上游 `getYearAndSemester` 逐字一致） | 取学期列表，只用来核对「按日期判断的学期」在不在列表里、取学期名；只留 `code`（形如 `2026-0`）和 `name`（≤40 字），其它键丢弃 | 状态码非 2xx、不是 JSON、不是数组：当作没有列表，继续导入（学期名由 `parse.js` 用学年学期推出），不报错 |
| `extract.js` `fetchSchedule` | GET | `<base>/student/wsxk.xskcb10319.jsp?params=<Base64 的 xn=…&xq=…>`（与上游 `fetchCourses` 同路径；`params` 额外做了 URL 编码，上游没有；学年 2000-2099 × 学期 0/1 的 Base64 实测都不含 `+` `/` `=`，所以编码前后字节完全一致，只是防御） | 取学生课表页（GBK 编码，用 `TextDecoder('gbk')` 解码，上游同样）；DOMParser 解析后只取 `#mytable` 里的课程文字 | 状态码非 2xx 抛「教务系统返回错误（代码 N）」；连不上抛「连不上教务系统」；没有 `#mytable` 且响应被送回 `/cas/login` 或带密码框抛「登录状态已失效」；没有 `#mytable` 也不像登录页：`hasTable=false`，`parse.js` 报「教务系统没有返回这个学期的课表页」 |

`<base>` = 当前页面的 `origin` + 当前路径里 `/suzxyjw` 之前的前缀 + `/suzxyjw`（`jwBase()`）：
- 路径里有 `/suzxyjw/`（或恰好是 `/suzxyjw`）：取到它为止，前面的反向代理前缀（如 `/http/<token>`）原样保留（冒烟 `proxy-prefix` 实测）；
- 路径里没有但主机是 `211.86.128.194`（例如停在站点根 `/`）：补 `/suzxyjw`（冒烟 `root`）；
- 其它主机（门户、统一认证）返回 `null`，直接抛「请先登录宿州学院的教务系统……」，**不发请求**（冒烟 `portal`）；
- 路径含 `/cas/login`：抛「当前打开的是登录页……」，不发请求（冒烟 `login-page`）。

**除这两个请求外没有别的请求**：冒烟脚本对每个场景断言所有请求路径只能是这两个，并断言没有多带 `X-Requested-With`（上游没有）。

**端口与 `allowHosts`**：`loginUrl` 是 `http://211.86.128.194/suzxyjw/cas/login.action`（上游 `import_url` 原样，80 端口）。宿主的白名单只比较**主机名**，
白名单 = `loginUrl` 的主机 + `allowHosts`。两个请求都与页面同源，所以 `allowHosts` 写 `[]`。
**没有写 `scheduleUrlHint`**：上游没有给课表页地址（只在弹窗里说「建议在课表查询页面导入」），也没有验证过的页面可以指（`wsxk.xskcb10319.jsp` 需要 `params` 才有内容），不凭空编一个；缺省时宿主从 `loginUrl` 打开。

与上游的差别（都不牵涉安全）：
- 上游弹窗让用户选学期；移植件按「当前地址 `params` → 页面 `xnxq` 控件 → 按日期判断（并拿学期列表核对）」自动取，只请求一个学期，用了判断值就在 `term.source` 里标明，`parse.js` 据此在提醒里说明。
- 上游的 `fetch` 在网络错误时 `showToast` 后返回 `null` 静默结束；移植件课表请求失败要抛出明确的报错，不静默。
- 上游只判断了「当前地址包含登录页地址」；移植件另外对不在教务主机的页面（门户、统一认证）也不发请求。

## 3. 与上游 / 不同构之处（本件的分析）

1. **课表格子的定位**：`#mytable` 里每个 `<tr>`，行内 `td.td` 的位置（第几个）就是星期几（上游同一规则，注释写「星期一到星期五」，但没有设上限）。`cellsOf()` 完整保留这条规则，
   交出每个格子的 `d`（第几个 `td.td`，从 1 起）。`parse.js` 只收 1-7，更大的计入「所在的格子超出了星期一到星期日的范围」提醒。
   带课程 div 的格子交 `courses`；有文字却没有一个课程 div 的格子（上游会静默漏掉）交 `stray`（前 20 字）并计数提醒；空格子不交。
2. **一个课程 div 的逐行文字**：上游是 `Array.from(div.childNodes).map(textContent.trim()).filter(非空)`，要求至少 3 行，`lines[0]` 课名、`lines[1]` 教师、`lines[2]` 含 `周次[节次]`、`lines[3]` 地点（缺了写「未知地点」）。
   上游的问题：缺教师时 `lines[1]` 是时间行，`lines[2]`（地点）没有方括号，整条课被静默丢掉；只有 2 行（缺教师且缺地点）同样丢；缺地点时写「未知地点」，会被课表当成真地点显示。
   移植件：`extract.js` 逐字保留「每个子节点一行、去空行」（额外跳过注释节点，每行最多 200 字），`parse.js` 的 `timeLineOf()` 找**第 2 行起第一个方括号里含数字的行**当时间行；
   它前面第 1 行是课名，第 2 行起到时间行之前都算教师（多行用「、」连起来，没有就是空）；时间行后面第一行是地点（没有就是空，不写「未知地点」）。
   缺教师 / 缺地点照常导入，汇总进提醒（指向「编辑课程」）；找不到时间行的计数说明。时间行方括号**后面**的文字、地点行**之后**的多余行（上游都会丢）计数提醒「还有别的文字没有导入」。
3. **周次**：上游 `parseWeeks` 按**半角逗号**切段，每段里含「单」就只留奇数、含「双」就只留偶数；段里有 `\d+-\d+` 取区间，否则取段里所有数字拼成一个数（`replace(/[^\d]/g,'')`）；同时含「单」「双」的段会变空（静默丢）；
   「第1-第8周」会被读成 18；全角逗号 / 「周」之外的写法一概不认。移植件沿用 `wzzy`（← `jyvtc` / `swu`）的 `weeksOf()`（按位置归属标记，认「周」「第」全角、`~` `至`、`共 N 周` 备注、教学班序号 `(1)`、备注 `(3组)`），
   与上游口径一致的地方：标记只管它自己那一段（`1-3,5-9 双` 只有 5-9 取偶数；`1-8 单,9-16 双` 各管各）；**单独写的一周**（没有区间）不受单 / 双影响（上游 `else` 分支直接取数字，`weeksOf` 里 `isRange` 判断，变异 m7 钉住）。
   与上游不同的地方（上游会错）：单双同写按每周都上并提醒；超出 1-30 的周次丢弃并计数提醒。`(单)/(双)` 前缀归属（m8）、「共 N 周」只剥备注（m9）、区间终点前的「第」（m10）都有 fixture 钉住。
4. **节次**：上游取方括号里 `split('-').map(Number)` 的第一个和最后一个。`periodRangesOf()` 同样取首尾，并认「第 3-4 节」「1-2,5-6」「1-2 5-6」（逗号 / 空白隔开的各算一段），要求 1 ≤ 起 ≤ 止 ≤ 20，读不出（含字母、超范围）计数提醒（上游得 `NaN`，该课静默不进矩阵）。
5. **合并**：上游先把同「课名 | 教师 | 地点 | 星期」的所有行合成一组，做「周次 → 节次集合」矩阵，每周把节次集合切成连续段，节次段相同的周次归到一起。
   移植件实现同一做法：`groups` → `matrix` → `patterns`。重叠节次（`[1-3]` + `[3-4]`）合成 1-4、同课错位按周切段，不丢任何一周；上游用 `|` 拼分组键，课名里带 `|` 会错位，移植件用 `JSON.stringify` 做键。
   课程再按「课名 + 教师」归档，块按（星期、起始节次、结束节次、起始周）排序，输出顺序固定。同一门课换了地点是同一门课的几个块。
6. **学期**：上游弹窗（`showSingleSelection`，默认第 0 项）。移植件先读当前地址的 `params`，再读页面（含同源框架）里名叫 `xnxq`、值形如 `2026-0` 的控件，都没有才按今天的日期判断
   （8 月到次年 1 月 = 第一学期 `0`，2 月到 7 月 = 第二学期 `1`），并拿学期列表核对：判断出的学期在列表里就用它（`source=guess`），不在列表里就用列表第一个（`source=list-first`，与上游弹窗默认选中的一致），
   列表取不到就直接用判断值。**只取这一个学期**，不回退到别的学期。学期名优先用学期列表里的名字（教务给的文字），取不到用 `xn-xn+1学年第一/二学期`。
   `params` 与 `xnxq` 控件是我们新加的读法，上游没有；控件名 `xnxq` 是照同平台 `jyvtc` / `wzzy` 的写法猜的，没有验证（找不到就走判断，提醒里如实说明，不影响正确性）。
7. **开学日**：上游**不取**开学日（只保存课程和预设节次，开学日由「拾光」自己的学期设置管）。空课的载荷必须有 `firstDay`，不能留空、也不许猜了不说：
   `parse.js` 的 `estimateStart()` 按学期推算——第一学期 = 9 月 1 日所在周的周一，第二学期 = 2 月 20 日所在周的周一（第二学期落在学年起始年 + 1 年；锚点当天若不是周一就回退到它所在周的周一，含当天，手册 §4.3），
   并**一律**写进提醒「课表页面里没有开学日期，第 1 周按「…」推算为 …，请在学期管理里核对成学校实际开学日」。年份读不出的极端情况报错，不编日期。
   已知偏差：学校的实际开学日可能和推算差一周甚至更多，所以提醒永远带着。
8. **总周数**：上游不设。移植件取 20 与课表最大周次中较大者（最多 30），写进提醒——课表最晚排到第 16 周的学期，应用里也会有 20 周，比实际多出的空周不影响课。
9. **节次时间**：上游写死一张 11 节表，每节 45 分钟，逐节照抄如下（已用脚本与上游 `importPresetTimeSlots` 逐节比对一致，`parse.js` 的 `PERIOD_TIMES`）：

   | 节 | 时间 | 节 | 时间 | 节 | 时间 |
   |---|---|---|---|---|---|
   | 1 | 08:05-08:50 | 5 | 14:40-15:25 | 9 | 19:00-19:45 |
   | 2 | 09:00-09:45 | 6 | 15:35-16:20 | 10 | 19:55-20:40 |
   | 3 | 10:05-10:50 | 7 | 16:30-17:15 | 11 | 20:50-21:35 |
   | 4 | 11:00-11:45 | 8 | 17:25-18:10 | | |

   课表用到第 12 节及以后时按统一修订 H3 顺推补齐（课间 5 分钟、每节 45 分钟，越过 23:59 就停，课程照常导入）：第 12 节 21:40-22:25、第 13 节 22:30-23:15，第 14 节会越过 23:59，不补；补了哪些、哪些补不了都写进提醒（fixture `period-overflow`）。
10. **上游的静默丢课**：缺教师（行数错位）、缺地点以外的格式问题、方括号里节次读不出、周次读不出、没有课程 div 的格子，上游一律不吭声丢掉；移植件缺教师 / 缺地点照常导入（`null`），其余各自计数并点名写进提醒。

## 4. 读了什么、交出什么（数据面）

`extract.js` 交出的整个对象（`JSON.stringify`）只有三个顶层键，没有网页原文：

| 键 | 内容 | 用途 |
|---|---|---|
| `term` | `{ xn, xq, source, name }`：学年起始年（4 位数字）、学期编号（`0` / `1`）、`source`（`page` / `guess` / `list-first`）、学期名（学期列表里同 `code` 那一项的 `name`，≤40 字，没有就空串） | 定学期、说明来源、学期名 |
| `hasTable` | 课表响应里有没有 `#mytable` | 区分「没有课表页」与「学期没有课」 |
| `cells` | 数组，每项 `{ d, courses }` 或 `{ d, stray }`：`d` 是行内第几个 `td.td`；`courses` 是该格每个课程 div 的逐行文字（数组的数组，每行 ≤200 字）；`stray` 是没有课程 div 的格子的开头 ≤20 字 | 拆课程 |

**不带出**：响应里 `#mytable` 以外的任何内容（页眉里的学生姓名 / 学号等）、`td` / `div` 的属性（`onclick`、`title`、`id` 等可能带的内部编号）、脚本；学期列表里除 `code` / `name` 以外的键。
冒烟脚本的假响应把「学生某 / 学号 2026000001 / 身份证号 / 手机号」放在页眉、非课表行、`td` 的 `onclick` / `title` 属性和学期列表的额外键里，交出的 JSON 里一个都搜不到（有输出的场景逐个断言，也断言顶层键、`term` 键、格子键的集合）。
教师姓名属于课表内容，随课程原样交出（课表本来就要显示）。
**已知的边界**：课程 div 的逐行文字和 `stray` 是页面原文，若教务把学生个人信息写进课表格子里（我们没有见过），会随之带出；`stray` 限 20 字、每行限 200 字以压低这种风险。

## 10. 已知风险与未验证项

- **没有本校账号，真机没验过；也没有任何一份真实的课表响应样本。** `#mytable`、`td.td`、`div[style*="padding-bottom:5px"]`、子节点逐行「课名 / 教师 / 周次[节次] / 地点」的结构全部来自上游代码的反推；
  页面如果有别的写法（行首的节次列也带 `td` 类、课程 div 的样式写成 `padding-bottom: 5px` 带空格、课名与教师在同一个文本节点里），移植件会按「读不出」或「排版不一样」计数提醒，不会静默，但课读不进来。
  上游代码注释里提到的格式只有「`1-8 单 [3-4]`」这一种。
- **星期由 `td.td` 的位置决定**：照上游。若某些行的 `td.td` 数不是 7（行首有同类名的节次格、被 `rowspan` 占位），星期会错位；上游同样如此，我们无法判断，提醒里有「星期格超范围」的计数但错位在 1-7 之内不会被发现。
- **开学日是推算的**：上游不取，教务页面里我们也没有可靠来源，推算可能和学校实际差一周以上；提醒永远要求学生核对。
  同一平台的 `wzzy` 上游会 POST `showLessonScheduleInfosV14.action` 读第 1 周周课表里的日期，宿州学院是否有同一个页面、返回里是否也有 `<br>月-日`，**未验证**（上游本校脚本没用它）。
  要提高开学日准确度可以另做一次联网验证后再把那段（`wzzy` 的 `fetchWeekDates()` / `startFromSchool()`）加回来；本件按上游代码为准，没有加。
- **周次、节次写法没有见过真实样本**：`parse.js` 比上游认的写法多，但真实页面如果在方括号后面还写了别的（上游会丢），会被计数提醒。
- **多行教师**（时间行前有 2 行以上）按「、」合并成一个教师字符串；如果其实是课名折成了两行，教师就会带上半截课名——纯启发式，上游遇到这种行数会整条丢掉。
- **学期的读法**：学期列表请求的返回格式（`[{name, code}]`）、`code` 形如 `2026-0` 都来自上游代码；列表的顺序假设"第一个是最新学期"（上游弹窗默认选第 0 项）；`xnxq` 控件名是猜的。按日期判断的学期可能不是学生想要的（例如假期里新学期还没排课），
  只请求一次，没有课就报「还没有课」，提醒里已写明学期的来源，让学生在教务页面里切学期后重点。学期编号只认 `0` / `1`；列表里其它编号（如短学期）会被忽略。
- **总周数**是 20 与最大周次中较大者，不是学校的真实总周数。
- 反向代理 / WebVPN 前缀只验证了 `/http/<token>/suzxyjw/…` 这种形状；学校的 WebVPN 主机名不在 `allowHosts` 里（与 `loginUrl` 不同源），经它打开时宿主可能拦截请求，未验证。
- 页面是 `http`（非 https）明文、主机是裸 IP：学校的现状，不是我们引入的；Cookie 只由 WebView 带，适配器不读不存。
- `TextDecoder('gbk')` 依赖 WebView 的 Chromium（Android 5+ 的系统 WebView 都有）；不可用时会抛出原生错误，学生看到的是"提取失败"，未做更友好的降级。
