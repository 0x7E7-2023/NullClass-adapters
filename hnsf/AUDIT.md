# 安全审计 —— 河南师范大学（乘方教务，jwc.htu.edu.cn）

审计对象：`jw-adapters/hnsf/` 下的 `extract.js` / `parse.js` / `manifest.json`，以及它们移植自的上游脚本
`shiguang_warehouse` 的 `HNSF/hnsf_01.js`（快照 commit `19a65bf07a3e998fcfc69cee692387cdc0523c1a`，2026-10-19 拉取，2026-10-20 复核仍是最新；
MIT，作者 星河欲转；`HNSF` 目录最后一次修改 `80e30cf`，与任务卡一致）。

审计方式：逐行读上游两份脚本 + 逐行读移植件，并跑移植手册 §5 的静态扫描。扫描结果（2026-10-20 运行）：

- 绝对 URL：`extract.js` 与 `parse.js` 的文件头各有一处 `https://github.com/XingHeYuZhuan/shiguang_warehouse`（注释）；
  `extract.js` 里有一处 `HOST = 'jwc.htu.edu.cn'`，只用来判断「当前页面是不是教务主机」，不用来拼请求地址；
  三个 `fetch` 的地址全是相对路径（同源）。`manifest.json` 里的 `loginUrl`、`scheduleUrlHint`、`homepage` 是给宿主看的声明，不是请求。
- 网络调用：只有 `extract.js` 里 `request` 函数中的一处 `fetch(path, options)`（`X-Requested-With` 是请求头字符串，不是 XHR 对象）。
  `parse.js` 里没有任何网络调用、没有 `document.` / `window.` / 桥调用。
- 凭据、本地存储、动态执行、写页面：`password` / `passwd` / `localStorage` / `sessionStorage` / `document.cookie` / `eval` /
  `new Function` / `sendBeacon` / `WebSocket` / `new Image` / `innerHTML` / `appendChild` / `.submit` / `setAttribute` 全部无命中。
  `extract.js` 对页面只做两件读操作：`getElementById('xnxqdm')` 读学期下拉框、`DOMParser` 解析自己取回的课表页。
- ES5 token 扫描（注释也算）：`=>`、反引号、`let `、`const `、`class`、`async`、`await`、展开符、可选链、`??`、`padStart`、
  `Array.from`、`new Set` / `new Map`、`includes(`、`startsWith(` 全部无命中；NUL 字节为 0。
- 模板残留：检索「swu」「西南」「jwglxt」「hueb」「正方」「hbmu」「glmu」「xjtu」，代码、manifest、fixtures 零命中
  （仅 `parse.js` 文件头与周次注释里有意写「照批次十 swu」）。
- 个人信息：`fixtures/` 全部为合成数据（甲 / 乙 / 丙老师、虚构教学楼），没有真实姓名与学号；`extract.js` 对排课行按字段白名单取值（见 §3）。

## 0. 上游情况：HNSF 目录里的两份脚本，只做 01

`resources/HNSF/adapters.yaml` 登记了两份：`HNSF_01`（`hnsf_01.js`，作者 星河欲转）与 `HNSF_02`（`hnsf_02.js`，作者 一颗，说明写「该作者没有添加说明」），
两份的 `import_url` 都是 `https://jwc.htu.edu.cn/`。两份读的是同一个学校系统的不同接口：

| | `hnsf_01.js`（采用） | `hnsf_02.js`（不采用） |
|---|---|---|
| 接口 | `POST /new/student/xsgrkb/getCalendarWeekDatas`，体 `xnxqdm=<学年起始年 4 位+学期 2 位>` | `POST /new/desktop/getCalendar`，体 `d1=<月初>&d2=<月末>`（桌面日历，一次只覆盖用户选的那个月） |
| 取数范围 | 整学期一次取全 | 每次只取一个月，要导整学期得重复导入 |
| 周次 | `zc` 逗号列表 | `zc` 列表 / 区间，但硬编码只认 1-20 周 |
| 节次 | `ps` / `pe` 两个数字 | `jcdm` 四位串（"0910"） |
| 节次时间 | 三张 10 节表（非夏季 / 夏季 / 另一校区），弹窗问用户 | 一张 10 节表（每节紧挨、没有课间），不问 |
| 登录判断 | 根路径 / 含 `login` 或 `cas` | 只认 `https://jwc.htu.edu.cn/xtgl/login_slogin.html`（正方的登录路径，与本平台 `/new/…` 的路径不是一个系统） |
| 其它毛病 | — | 月份选项用 `new Date().getFullYear()` 起算 9-12 月 + 次年 1-6 月，一月到六月使用时年份错一年；教师 / 教室缺一个就写成空串；公告里写「自动下载原始数据」，代码里并没有 |

取舍理由：01 一次请求取全整学期、不需要月份向导，是 02 做不到的；02 的一张节次表（每节 45 分钟紧挨、无课间）与 01 的三张表互相不吻合，
我们没有任何一方的权威来源，所以只能二选一，选了作者在说明里写「添加双季作息」、逻辑完整的 01。**02 里的东西一概不移植**（理由同上），
也没有把两份合并（接口不同，合并只会让取数更脆）。

另一件要如实记下的事：01 里的第三张表叫「创新港校区」。创新港是西安交通大学的校区名，河南师范大学有没有这个校区我们无法核实
（01 的校区文字是「建设东路校区/平原湖校区」与「创新港校区」两项）。选项文字按上游保留，不擅自改名，同时在选项里写上第 1 节、第 5 节的开始时间方便学生对照；
列入 §9 请主调度和真机验证确认。

## 1. 请求清单（与代码逐条对应）

三个请求全部在用户已登录的教务页面里发出，全部是**相对路径**（只会打在当前页面所在的主机），登录全程由用户手工完成。

| # | 方法 | 地址 | 请求体 | 干什么 | 取不到时 |
|---|---|---|---|---|---|
| 1 | GET | `/new/student/xsgrkb/week.page` | 无 | 读学期下拉框 `#xnxqdm` 的默认选中项（**当前页面上已经有该下拉框就不发**，直接读用户选的那项） | 任何失败（非 2xx / 网络错误 / 没有下拉框 / 超长）都当没取到，改按今天的日期推算学期，parse.js 在提醒里说明 |
| 2 | POST | `/new/student/xsgrkb/getCalendarWeekDatas` | `xnxqdm=<学期代码>`（与上游 `fetchAndParseCourses` 的体一字不差） | 取整学期排课（`{code:0,data:[…]}`） | 非 2xx → 抛「教务系统返回错误（代码 N）」；网络错误 → 抛「连不上教务系统」；响应不是 `{code:0,data:[…]}`（含登录页 HTML、`code` 非 0）→ 抛「教务系统没有返回课表数据（…）：登录状态可能已失效」；`data` 为空 → 抛「这个学期还没有课表数据」 |
| 3 | POST | `/new/xlxx/getDatesOfWeek` | `xnxqdm=<学期代码>&zc=1` | 取第 1 周七天的日期，用作开学日（**上游不取开学日；这一条是本件新增，见 §5**） | 任何失败都交 `null`，parse.js 按学期推算开学日并在提醒里说明；绝不影响取课表 |

不发请求的情形：当前主机含 `htu.edu.cn` 且路径是根路径（不带查询串）或主机 + 路径含 `login`、含单独的 `cas` 一段 → 抛「当前打开的是登录页…」；
当前主机不是 `jwc.htu.edu.cn` → 抛「当前页面不是河南师范大学的教务系统…」。两种都在发任何请求之前。

提问桥：`__ncSelect` 一次（三选一节次时间），桥不存在（`__ncCapabilities.ask` 为假 / 没有 `__ncSelect`）或用户取消或调用失败都当「没回答」，不阻塞。

## 2. 读了什么、交出去什么（逐字段）

`extract.js` 交给 `parse.js` 的对象（`JSON.stringify` 后的字符串）：

| 字段 | 内容 | 来源 |
|---|---|---|
| `term.code` | 学期代码，必须是 6 位数字 | 下拉框选中项的 `value`；读不到按日期推算 |
| `term.name` | 学期下拉框里的文字（如「2026-2027学年第一学期」），推算时为空串 | 下拉框 `textContent` |
| `term.source` | `page` / `date` | extract 判断 |
| `today` | 提取当天日期 | 本机时钟（本地日期，不用 `toISOString`） |
| `timetable` | `normal` / `summer` / `campus` / `null` | 用户在提问里选的 |
| `weekOne` | `[{xqmc, rq}]`（七天里每天的星期标号与日期）或 `null` | 请求 #3，只取这两个字段 |
| `rows[]` | 每条排课：`kcmc` 课名、`teaxms` 教师、`jxcdmc` 教室、`jxcdmc2` 分周教室、`xq` 星期、`ps` / `pe` 起止节次、`zc` 周次、`qssj` / `jssj` 上课起止时间 | 请求 #2 的 `data[]`，**字段白名单**（`ROW_FIELDS`），其余字段一律不带出 |

响应里夹带的学号、姓名、身份证号、手机号等（上游也没读）不在白名单内，不会出现在输出里；冒烟里往课表响应里塞了 `xh` / `xm` / `sfzh` / `sjh` / `kcrwdm` 与外层 `xsxx`，
输出里都找不到。`jxcdmc2`（同一门课不同周次教室不同时的教室-周次列表）、`qssj` / `jssj`（教务给的实际上课时间）是教学信息，不是个人信息；
它们不在 HNSF 上游脚本里，来源是同平台的其它上游脚本（见 §5 第 7 条与 §9）。

`parse.js` 是纯函数：不碰网络、不碰页面，输出载荷里的教师名只是课表本来就显示的任课教师，不含学生信息。

## 3. 移植手册 §5 八条逐条结论

| # | 检查项 | 结论 |
|---|---|---|
| 1 | 不碰凭据 | 通过。不读 `password` / 登录表单 / `localStorage` / Cookie；`credentials: 'include'` 只是让浏览器带上用户已有的会话；提问只问节次时间，不问账号信息 |
| 2 | 不外发 | 通过。全脚本唯一的 `fetch` 调用点发三个相对路径请求，没有 `sendBeacon` / `WebSocket` / `new Image().src`；没有任何第三方域 |
| 3 | 请求域可控 | 通过。唯一主机是用户当前打开的 `jwc.htu.edu.cn`（额外用 `hostname` 精确比较，其它主机直接报错不发请求）；请求都是同源相对路径，`allowHosts: []`，没有通配。提问桥只注入到 `loginUrl` 同源，与此一致 |
| 4 | 只读课表 | 通过。三个请求依次是：课表页（只读学期下拉框）、整学期排课、第 1 周日期；不请求成绩、学籍、个人信息、缴费等任何其它接口 |
| 5 | 不埋点 | 通过。无统计 / 上报 / 遥测；上游里全部 `console.log` 一并去掉 |
| 6 | 不 eval 远程代码 | 通过。无 `eval` / `new Function`；教务返回的字符串只做 `JSON.parse` 与 `DOMParser` 解析（解析的是只读的新文档，不执行脚本） |
| 7 | 不写页面 | 通过。不写 DOM、不改表单、不提交、不点击；`DOMParser` 解析出来的文档不挂到页面上 |
| 8 | 不依赖用户输入之外的秘密 | 通过。无硬编码密钥 / 令牌 / 他人学号；常量只有接口路径、学期代码格式、体积上限和三张节次时间表 |

## 4. 给学生看的文字

`extract.js` 的报错与提问、`parse.js` 的 warnings 都按 `docs/ux-writing.md` 写成大白话：不出现「接口」「载荷」「上游」「脚本」「字段」「JSON」「HTML」「null」「作息表」；
状态码写成「教务系统返回错误（代码 N）」；时间表统一叫「节次时间」；改开学日、总周数、节次时间指向「学期管理」，改教师 / 教室指向「编辑课程」。
带课名的提醒（缺教师 / 缺教室汇总、不同周次地点不同、周次认不出）课名截到 20 字、最多点名 3 门，每条经过 `warn()` 再截到 200 字以内；
fixture `long-warnings` 钉住这一点。提问的标题 ≤60 字、说明 ≤300 字、三个选项各 ≤60 字（冒烟里逐次断言）。

提醒清单（顺序固定）：① 学期来源（取自教务 / 按日期推算）；② 开学日来源（取自教务 / 推算 / 教务给的日期不属于这个学期而忽略 / 标成周一的日期不是周一已回退）；
③ 总周数（教务不给，按 max(最晚周次, 20) 导入）；④ 节次时间来源（用户选的 / 按排课行的上课时间判断 / 默认第一张）；⑤ 上课时间与所用节次时间对不上（点名并提示哪张表一致）；
⑥ 节次补全（空课默认 / 顺推 / 补不了）；⑦ 被跳过的行（分类计数 + 认不出的周次写法）；⑧ 缺教师 / 缺教室汇总；⑨ 不同周次地点不一样；
⑩ 周次里的序号括号 / 备注括号 / 越界周次 / 孤立单双标记 / 单双同写。

## 5. 与模板（swu）的差异

模板选 `swu`（批次十已审计的正方件）只借它的**解析骨架**：周次解析 `weeksOf`（含前缀 / 后缀单双标记归属、「第1-第8周」、「共 N 周」只剥备注、序号 / 备注括号）、
`runsOf`、提醒限长出口 `warn`、H3 节次补全、缺教师 / 缺教室汇总。库里没有同平台（乘方教务）的已移植件：`hbmu` / `glmu` 走的是 Struts2 的
`xsgrkbcx!getDataList.action`，路径和字段都不同，而且它们更早，周次解析、提醒限长、H3 都比 swu 少，所以不选。解析骨架之外的取数层全部按本校上游重写：

1. **取数是三个同源请求**（§1），不是正方的 `kbList` / `cxRjc` / 校历；没有 WebVPN 前缀处理（上游没有，主机精确比较）。
2. **学期**：读 `#xnxqdm`（用户在课表页上选好了学期再点提取，就取他选的那项）→ 取一次课表页读默认项 → 按日期推算。学期代码须为 6 位数字，不是就不用。
3. **节次时间**：上游写死三张 10 节表并分两次弹窗问用户（校区、再问夏季与否）；这里合成一次三选一提问，逐节照抄三张表。没回答时先看排课行有没有带 `qssj` / `jssj`，
   有且恰好只与一张表完全吻合就用那张，其余用第一张（非夏季）并提醒。已选的表与排课行的上课时间对不上也提醒（点名 + 指出哪张表一致）。
4. **开学日**：上游不取，用户导入后得自己填。这里用 #3 请求取第 1 周周一的日期；取不到按「第一学期 = 9 月 1 日所在周的周一，第二学期 = 2 月 20 日所在周的周一」推算并提醒。
   教务给的日期离推算锚点超过 45 天时当作取错了学期，也走推算并提醒；标成周一的日期实际不是周一，回退到当周周一并提醒。
5. **总周数**：教务不给，上游也没存；`max(最晚周次, 20)`，最多 30，抬高时提醒。
6. **同课合并**：swu 的两阶段合并（连续节次合并 + 周次并集）里，连续节次合并会改上课安排的形状，上游 01 不合并；这里只保留「去掉完全相同的行 + 同一个上课安排的周次取并集」。
7. **新增的两项教务数据**：`jxcdmc2`（不同周次教室不同）只用来数出有几个不同的教室并提醒，教室仍按上游取 `jxcdmc`；`qssj` / `jssj` 只用来核对节次时间。两者都来自同平台的其它上游脚本
   （`CMC/cmc_01.js` 的 `parseVenueWeeks` 与 `isCustomTime`），不是 HNSF 自己的上游，未在本校验证（§9）。
8. 没有 swu 的备注（`cxbjmc` / `xkbz`）、集中实践课（`sjkList`）、每周起始日（`qsxqj`）：本平台与上游 01 里没有对应数据。

## 6. 上游里删掉 / 改掉的东西及理由

| 上游 | 处理 | 理由 |
|---|---|---|
| 七个字段（课名、教师、教室、星期、起止节次、周次）全非空才收，缺一个整行 `continue` | 只要求课名 / 星期 / 节次 / 周次，教师与教室缺了照常导入（null）并按类型汇总提醒 | 公共说明第 4 条「缺教师 / 缺教室照常导入，不许静默丢课」；上游会把没写教师的课整门丢掉 |
| `parseWeeks` 只认逗号分隔的数字（"1-16" 之类算 NaN 被过滤） | 用 swu 的 `weeksOf` 放宽，仍认纯逗号列表 | 上游接受的写法一个不能少；放宽的写法进 fixture `week-markers` / `week-anomalies` |
| 输入框问学年、单选框问学期 | 读页面学期下拉框 / 课表页默认项 / 日期推算 | 公共说明第 2 条：不弹窗问学年学期 |
| 先问校区再问夏季与否（两次弹窗） | 一次 `__ncSelect` 三选一 | 少一次打扰，三张表的取舍完全一致；用户取消不会丢掉课表 |
| `showAlert` / `showToast` / `saveImportedCourses` / `savePresetTimeSlots` / `notifyTaskCompletion` / 全部 `console.log` | 去掉 | 拾光的桥能力，空课由宿主保存；日志属于埋点类输出 |
| 课程按 `{name, teacher, position, day, startSection, endSection, weeks}` 数组交给宿主，教师缺失会被过滤 | 周次数组按手册 §4.1 切成 `(startWeek, endWeek, weekType)` 段，一门课可以有多个上课安排 | 空课载荷格式 |
| 上游按 `name → day → startSection → name.localeCompare` 排序 | 按「课名、教师、教室、星期、起止节次」排序 | 合并需要的稳定顺序；`localeCompare` 在 Rhino 与浏览器里结果不同，不用 |
| `isLoginPage()`：`url.includes('htu.edu.cn') && (根路径 \|\| 含 login 或 cas)` | 保留语义，但不看查询串、`cas` 要求是单独的一段 | CAS 登录页的 `service=` 参数里带着教务自己的地址，看查询串会误判；`cas` 子串会误伤 `cascade` 之类 |

## 7. fixtures（11 对，全部合成）

`basic`（连堂、单双周行合并、分段周次、一课两地点、完全重复行）、`summer-estimate`（学期按日期推算 + 夏季作息 + 开学日推算）、
`second-term-campus`（第二学期 + 另一校区的表 + 抬高总周数 + H3 取空课默认节次）、`late-periods`（H3 顺推 + 补不了的节次）、
`week-markers`（前缀 / 后缀单双归属、共 N 周、第1-第8周、全角标点、多种区间写法、默认节次时间提醒）、`week-anomalies`（序号 / 备注括号、单双同写、越界周次、孤立标记、各类被跳过的行）、

## 9. 已知风险与未验证项（我们没有本校账号，真机没验过）

1. **全部字段形状来自上游脚本与同平台脚本，没有在河南师大真机验证**：`getCalendarWeekDatas` 的 `{code:0,data:[…]}`、`xq` / `ps` / `pe` / `zc` / `kcmc` / `teaxms` / `jxcdmc` 来自 HNSF 上游 01；
   `week.page` 里的 `#xnxqdm`、`getDatesOfWeek` 的 `[{xqmc,rq}]`、`jxcdmc2`、`qssj` / `jssj` 来自同平台（乘方教务）的 `CMC` / `LIT` / `NENU` 上游脚本，不是 HNSF 自己的上游，
   河南师大的部署上不一定有；缺了都有兜底（日期推算学期 / 推算开学日 / 不核对上课时间），并在提醒里说明，不会让导入失败。
2. **三张节次时间表无法核对**：照上游逐节抄，但没有学校公布的时间可对照；「创新港校区」这一项河南师大是否真有该校区无法核实（§0）；夏季作息从哪天开始上游没写，
   所以没有按日期自动判断，而是问用户（取消 / 无提问桥时默认非夏季，并提醒「校区或季节不同，上课时间会整体偏移」）。
3. **总周数是假设**：教务不给，按 `max(最晚周次, 20)`，提醒里说明；真实学期若是 18 周，课表照常可用，只是「共 N 周」显示偏大。
4. **登录页判断是 URL 启发式**：根路径（不带查询串）一律当登录页（与上游一致）。如果河南师大登录后的首页恰好也是根路径，用户会看到「当前打开的是登录页」，需要先点进课表页再提取；
   `scheduleUrlHint` 指向 `week.page`，这个路径取自同平台其它学校的上游脚本，未验证，若 404 用户仍可手动打开课表页。
5. **不支持 WebVPN / 非 `jwc.htu.edu.cn` 主机**：上游 01 把主机写死为 `https://jwc.htu.edu.cn`，这里同样要求当前主机就是它，经 WebVPN 打开会报「当前页面不是河南师范大学的教务系统」。
6. **教师字段原样取**：同平台的 `CMC` 上游会去掉教师名里的 `[…]` 并去重，HNSF 上游没有这样做，这里照 HNSF；若教务把教师写成「张三[教授]」之类，会原样显示。
7. **`jxcdmc2` 的写法是猜的**：按 `CMC` 上游的 `教室-周次,教室-周次` 解析，认不出就不提醒；认出来时教室仍取 `jxcdmc`（可能只是其中一个地点）。
8. **学期推算**：没有读到学期下拉框时，8 月到次年 1 月算第一学期、2 到 7 月算第二学期；夏季学期（代码 03）只有在页面下拉框里选中时才会出现，不会被推算出来。
9. 上游 02（月份日历接口）没有移植；若河南师大其实只开放 02 的接口，01 会在「教务系统没有返回课表数据」处失败，需要真机验证后决定是否补一条备用路径。
