## 0. 平台与上游

本校是 **YETHAN 教学信息服务平台**，特点（来自上游脚本代码与注释，我们没有本校账号）：

1. **单 Action 分发**：只有一条入口 `POST /yethan/CourseAction`，表单里的 `setAction` 决定干什么，没有 REST。
   课表 = `setAction=userCourseScheduleTable` + `viewType=studentCourseTableWeek` + `selectTableType=ThisTerm`
   + `queryType=student` + `weekNo=<第几周>`，返回一张 HTML 课表。
2. **「全部周次」是摆设**：`weekNo` 为空时教务仍只返回当前周（上游实测单次只拿到 2 门课），所以必须逐周请求再合并。
3. **课表表格** `table.table_border`：首行是表头（第一格「节」、第二格「上课时间」、其余七格「星期一03月02日」…），
   数据行第一格是节次号、第二格是该节时间（`08:20-09:05`）、七格对应周一~周日。格子里用 `<br>` 分行，
   形如「B1001 高等数学（4）（张睿）」+「1-16周 东101教室」，一格可叠多门。
4. **没有校历**：表头只有月日没有年份，页头只有「2025-2026第2学期」这样的学期文字；总周数也没有。
5. 数据脏：课程编号与课名挤一行、课名里有版本号括号「（4）」、教师可能缺失、地点可为 `NoRoom`。

选模板：本批任务卡指定借 `imut` 的骨架或 `hbmzu`（extract 里解析 DOM、交结构化行）。实际复制的是 `imut`：
它的 `parse.js` 已带上批次三十三以后的周次写法修正（单双标记归属、`第1-第8周`、`共 N 周`、周次里混节次），
并且有「节次时间优先取页面、读不到回落学校公布的表」这一层，与本校「上课时间列可读、失败回落 11 节表」同构。
取数、字段、逐周合并、学期与开学日按本校上游重写。

## 1. 请求清单（与代码逐条对应）

只有一条接口，重复请求不同周次：

| # | 方法 | 地址 | 请求体 | 干什么 | 取不到时 |
|---|---|---|---|---|---|
| 1 | POST | `{origin}/yethan/CourseAction`（`origin` = 当前页 origin，主机已限定 `jw.guc.edu.cn`） | `setAction=userCourseScheduleTable&viewType=studentCourseTableWeek&selectTableType=ThisTerm&queryType=student&weekNo=<N>`（`application/x-www-form-urlencoded; charset=UTF-8`，带浏览器 Cookie） | 取第 N 周的课表 HTML | 第 1 周失败 → 抛「连不上教务系统」；第 1 周返回登录页 → 抛「还没登录」；第 1 周没有 `table_border` → 抛「没有找到课表」。第 2 周以后失败 / 被截止时间跳过 → 记 `ok:false` 并进 `skippedWeeks`，由 parse 汇总提醒 |

- 抓取范围（`fetchRange`）：先抓第 1~20 周，**并发 4、每请求 8 秒超时**；整段取数有 **20 秒预算**（`EXTRACT_BUDGET_MS`，宿主脚本超时 30 秒，留 10 秒给解析与返回），每开新批次前检查 `Date.now() >= DEADLINE`，到点就把剩下的周次记成 `ok:false`、不再发请求。再从所有响应里找出现过的最晚周次
  （`maxWeekOf`，只看课表格子里的文字、只认 `数字[-数字]周`，最多 30），比已抓的更晚就补抓，循环到不再变化，上限 30 周；补抓同样受截止时间约束。
- 不弹窗问学期：`selectTableType` 固定 `ThisTerm`，只导入教务当前学期。
- **不请求选课页**（上游的 `CourseAction?setAction=userCourseSchedule`）：它只用于学期名与学分；学期名改从课表响应的页头读，
  学分在空课载荷里没有位置，整条请求删掉。

不发请求的情形（都在取数之前判断）：
- 当前主机不是 `jw.guc.edu.cn` → 抛「当前页面不是吉利学院的教务系统…」（`extract.js` 的 `onJwHost`）；
- 当前页是登录页：地址含 `userLogin`，或页面上有 `#ranstring` / `#LoginForm` / 密码输入框 → 抛「还没登录教务系统…」，
  **零请求**（`extract.js` 的 `onLoginPage`）。

提问桥：**一次都不用**。没有校区 / 季节 / 学期分支需要问用户，学期固定当前学期。

## 2. 读了什么、交出去什么（逐字段）

`extract.js` 交给 `parse.js` 的对象（`JSON.stringify` 后的字符串）：

| 字段 | 内容 | 来源 |
|---|---|---|
| `today` | 提取当天日期（本地日期，不用 `toISOString`） | 本机时钟 |
| `termLabel` | 页头的学期文字，如「2025-2026第2学期」，截 120 字 | 第 1 周响应 HTML 的正则 |
| `mondayText` | 表头「星期一」那格原文，如「星期一03月02日」，截 120 字 | 第 1 周响应 `tr` 首行第 3 个 `td` |
| `timeRows[].num` / `.time` | 每个节次行的节次号与「上课时间」列原文（如 `08:20-09:05`），各截 120 字 | 各数据行的第 1、2 个 `td` |
| `weeks[].week` / `.ok` | 周号 / 这一周有没有取到（HTTP 失败、登录页、没有表格、被截止时间跳过都算没取到） | 请求顺序与结果 |
| `weeks[].rows[]` | `day` 1..7、`period` 节次号、`segments` 该格按 `<br>` / 块级元素分行后的文字（每段截 120 字） | 课表表格第 3~9 个 `td` |
| `skippedWeeks[]` | 没取到的周号（失败 + 因取数预算跳过），parse 据此写一条提醒 | `weeks[].ok === false` 的周号 |

学生个人信息（学号、姓名、身份证号、手机号）不进输出：格子里只读看得见的文字，节点自己或**任何一层祖先**带 `hidden`、
`aria-hidden="true"`、内联 `display:none` / `visibility:hidden` 的整棵子树都跳过（`<tr style="display:none">`、`<tbody hidden>` 也吃）。
**边界**：本适配器的表格都是 `DOMParser` 解析出来的文档，没有样式表也没有窗口，算不出计算样式 —— 只靠 class 隐藏的元素认不出来（真机上若教务用 class 藏学生信息，这一层挡不住）。当前页只用来判断「是不是登录页 / 本校主机」，
页面正文一个字都不交出去。冒烟场景 `normal` 往格子里塞了学号 / 姓名 / 手机号（`display:none` 的 `span`），输出里找不到。

`parse.js` 是纯函数：输出里的教师名只是课表本来就显示的任课教师，不含学生信息。

## 4. 给学生看的文字

`extract.js` 的报错与 `parse.js` 的 warnings 都按 `docs/ux-writing.md` 写：不出现「接口」「载荷」「上游」「脚本」「字段」
「课程块」「组件」「模板」「HTTP」「JSON」「DOM」「HTML」「null」「undefined」「学期设置」「作息表」；时间表统一叫「节次时间」；
改学期名、开学日、总周数、节次时间指向「学期管理」，改教师 / 教室指向「编辑课程」。
带课名的提醒课名截到 20 字（`shortName`）、最多点名 3 门；认不出的原文同样截 20 字；每条都经过 `warn()` 再截到 200 字以内。
fixture `long-warnings` 钉住长课名 + 长原文时全部提醒 ≤200 字。

提醒清单（顺序固定）：① 学期来源（页头的学年学期 / 按今天的日期推算并冠学校名）；② 开学日（表头日期 / 按今天推算）；
③ 总周数（默认 20，课表更晚才抬高）；④ 节次时间取自课表还是回落学校公布的 11 节；⑤ 表外节次的补齐（学校公布的表 / 顺推 / 补不了）；
⑥ 有周次没取到（失败或到预算截止）；⑦ 被跳过的课表数据（缺课名 / 星期 / 节次 / 周次 + 认不出的原文）；⑧ 缺教师 / 缺教室汇总；
⑨ 周次里的序号括号 / 备注括号 / 越界周次 / 孤立单双标记 / 单双同写。

## 5. 与模板（imut）的差异

借的是解析骨架：`weeksOf`（前缀 / 后缀单双标记归属、`第1-第8周`、`共 N 周` 只剥备注、周次里的节次整段摘掉、全角标点）、
`runsOf`、`warn` 限长出口、H3 节次补全、缺教师 / 缺教室汇总、多周重复行先去重。取数与本校特有的解析按上游重写：

1. **取数**：imut 是几条 GET / POST 拿整页 HTML；这里是**同一条 POST 逐周请求 1~20（必要时到 30）周**，再按内容合并去重。
2. **学期**：imut 读 `eduaffair:CTRT` 的 `year` / `term`；这里读页头「2025-2026第2学期」，拼成「2025-2026学年第二学期」。
3. **开学日**：imut 按 9 月 1 日 / 3 月 2 日两个锚点推；这里用表头「星期一03月02日」的月日，年份先按学期取学年首年 / 次年，
   没有学期时按「距离今天最近、且那一天真实的星期与表头「星期几」对得上」的年份推定，并把对齐到周一（`pageStart`）。
4. **课程格子**：imut 按 `<<课名>>` 行分组；这里按「课名行 + 周次地点行」成对消费，周次与地点的切分用**最后一个「周」**
   （多段周次与「第1周至第8周」都不会被切掉后半段），紧跟在「周」后面的 `(单)` / `(双)` 归周次。
5. **教师识别**：上游只认末尾全角括号且不纯数字；这里全角 / 半角都认、允许里面再套一层（「张三（外聘）」→ 张三），
   并把「（实验）」「（主讲）」「（外聘）」这类备注词当课名的一部分而不是教师。
6. **节次时间**：imut 的页面表在 `th` 里；这里读「上课时间」列，按上游 `isValidTimeSlots` 的口径校验
   （节次从 1 连续、`HH:mm`、开始早于结束、相邻不重叠），整表不合法就回落上游写死的 11 节表。
7. **某一周失败**：不需要的（imut 是整页一次），这里单独成提醒。

## 6. 上游里删掉 / 改掉的东西及理由

| 上游 | 处理 | 理由 |
|---|---|---|
| 「本学期 / 下学期」选择弹窗（`selectSemester` + `showSingleSelection`） | 去掉，固定 `ThisTerm` | 任务卡：不弹窗，只导入教务当前学期 |
| 选课页请求与学分注入（`fetchSemesterInfo` / `parseCreditMap` / `applyCredits`） | 去掉 | 学分在空课载荷里没有位置；学期名改从课表页头读 |
| `showAlert` / `showToast` / `saveImportedCourses` / `savePresetTimeSlots` / `saveCourseConfig` / `notifyTaskCompletion` | 去掉 | 拾光的桥能力；空课由宿主保存，适配器只交数据 |
| 只抓第 1 周、按它的最大周次补齐（`fetchAllWeeksTimetable`） | 改成先抓 1~20 周，再按抓到的最晚周次补抓，最多 30 | 任务卡：避免「从更晚周次才开始上的课」漏掉；也避免总周数被第 1 周的课表低估 |
| `parseWeeks`（先删括号再切逗号） | 换成按手册 §4.1 的写法 | 上游会丢单 / 双标记、把 `(1-16周)` 当备注删掉 |
| `mergeAndDistinctCourses`（`Map` / 展开 / `Array.from(new Set(...))`） | 换成对象字典 + 数组并集 | ES5，且保留「周次取并集」的语义 |
| 格子里 `textContent`（隐藏元素也读） | 逐节点取可见文字 | 公共说明第 3 条：个人信息不许带出 |
| 上游没有登录页判断 | 请求之前先判断主机与登录页（零请求），第 1 周响应是登录页也明确报错 | 公共说明第 6 条 |
| 某一周失败只 `console.error` | 交 `ok:false`，由 parse 汇总进提醒 | 失败要能被看到，且不许拖垮其余周 |
| 上游「全部周次」返回当前周的注释 | 保留语义，逐周抓取 | 上游实测结论 |
| 上游的 `console.error` / 原始错误文本 | 换成大白话提示 | `docs/ux-writing.md` |

新增（上游没有）的：主机 / 登录页判断与零请求提示、逐周失败的结构化记账、表头日期缺年份时的「星期对得上」年份推定、
`NoRoom` / 占位词一律按没给、教师备注词不当教师、缺教师 / 缺教室汇总、H3 表外节次补齐、提醒限长。

## 9. 已知风险与未验证项（我们没有本校账号，真机没验过）

1. **页面结构全部来自上游脚本，没有在本校真机验证**：`table.table_border`、表头第 3 格、`<br>` 分行的「课名行 + 周次地点行」、
   `NoRoom` 的写法都照上游；若学校改版，会落到「没有找到课表」或跳过行，提醒里会给出计数，但不会静默导入错误周次。
2. **跨行（rowspan）的课可能读不到**：与上游一致，`td` 少于 9 个的行整行跳过（跨节占用时课程内容在首行，通常不丢课）；
   如果 YETHAN 把课挂在跨行的后续行里，那部分课会丢且只在「数据不全」计数里体现不出来。没有真实页面可验。
3. **逐周抓取 20 次请求**：宿主脚本超时 30 秒（`JwScriptContract.DEFAULT_TIMEOUT_MS`，没有按件覆盖的字段）。
   取数有 20 秒总预算（每批 4 个、每请求 8 秒超时），到点后剩下的周次记成没取到并进提醒，整次提取一定会带着结果返回；
   教务慢时课表会不完整，用户可稍后重试。上游同样是逐周抓，没有更省的办法（「全部周次」不可用）。
4. **学期名从课表响应页头读**：上游是从选课页读的同一段文字，我们假设课表页也有同样的页头；
   读不到会按今天的日期推算并冠「吉利学院」，提醒里会说明。
5. **开学日的年份是推的**：表头只有月日；有学期文字时按学年首年 / 次年，没有时按「距离今天最近且星期对得上」的年份。
   年份推错时整学期会偏移，所以每次导入都有一条提醒。
6. **总周数是假设**：教务不给学期总周数，按 20 周，课表更晚才抬高（最多 30）。
7. **补抓周次的判断是格子文字扫描**（`maxWeekOf` 扫课表格子里的 `数字[-数字]周`，不看整页，避免被周次下拉误导）：可能多抓几周（无害，最多 30），
   也可能在周次写法很怪时少抓；真正的周次解析在 `parse.js`，少抓的部分会体现在课表里而不是周次错乱。
8. **登录页判断是地址 / 控件启发式**：地址里一直带 `userLogin` 的页面一律当登录页；登录后若地址没变，用户会看到「还没登录」，
   打开课表页再提取即可。
9. **`allowHosts` 为空**：地址用当前页 origin；若学校以后换到别的主机（如 WebVPN），会报「当前页面不是…」且零请求，
   需要跟着改 `HOST` 与 `loginUrl`。
10. **节次时间整表校验**：只要有缺节 / 重叠就整表回落学校公布的 11 节（与上游一致），不会半用半猜。
11. **靠 class 隐藏的元素认不出来**：表格由 `DOMParser` 解析，没有样式表，`hiddenWithAncestors` 只能看 `hidden` / `aria-hidden` / 内联样式；
    如果教务以后用 class 藏学生信息，这些文字会被带出。冒烟只覆盖了 `hidden` / `display:none` / `<tbody hidden>` 三种写法。
