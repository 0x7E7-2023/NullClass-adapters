## 0. 移植前的分析（通读上游后的结论）

**上游结构。** 单文件 239 行，流程：登录判断 → GET 学年学期 → 弹窗选学期 → 逐周 1..20 GET 课表 → 按「课名|星期|起止节|教室」合并 → 保存课程 → 保存写死的 12 节作息 → 提示完成。

**与模板的不同构之处。** 库里没有同平台件。模板 `hueb` 是正方教务 + WebVPN 映射主机 + POST 表单 + 校历接口 + 作息接口；本校是纯 JSON GET，没有校历接口、没有作息接口、没有 HTML、没有 WebVPN 前缀。extract.js 按上游重写（两个 GET），parse.js 只借 hueb 经过审计的周次解析（单双归属、「共 N 周」剥离、括号序号与备注）、H3 顺推与 warnings 收口，其余按本校数据重写。

**上游的毛病（移植时都已处理）：**
- 默认选「第一个学年 × 第一个学期」（下标 0）。春季就选错，不能照搬。移植件先认标记，没有标记就按提取日推算（§2）。
- `parseWeeks` 不认「(单)」「(双)」：`1-16周(单)` 被 `parseInt` 读成 1..16 每周都上，静默退化。移植件按标记归属读（parse.js `weeksOf`）。
- `parseWeeks` 与逐周循环都写死 20 周，超过的周次直接丢。移植件的逐周上限 = max(20, 已收到记录里出现的最大周)，硬上限 30（extract.js `WEEKS_MIN` / `WEEKS_MAX`）。
- 逐周 `try/catch` 只打日志，单周失败静默少周。移植件记下周次，写进提醒。
- `json.response.forEach` 不检查返回结构，返回结构不对时静默当成空周。移植件按「课表数组」检查，不对就当失败周。
- 合并键是「课名 + 星期 + 起止节 + 教室」，不含教师：同名同节同教室、不同教师的课会合成一条。移植件把教师也放进分组键，周次取并集。
- 上游不合并相邻节次（1-2 与 3-4 分两块）。移植件合并相邻或重叠节次（周次集合相同时），不改任何一周的安排。
- 上游的 `importPresetTimeSlots` 第 10 节 `18:45-19:00` 只有 15 分钟，照抄保留，并在提醒里要用户核对。

**请求清单（上游 vs 移植件）：** 上游两类 `fetch`（学年学期 + 逐周课表）全部在 `https://one.hnzj.edu.cn` 上。移植件保留这两类请求，地址用 `window.location.origin` 拼出，只在 `one.hnzj.edu.cn` 上运行。

## 1. 请求域与请求清单（与代码逐条对应）

`allowHosts` 为空数组。extract.js 只在 `window.location.host === 'one.hnzj.edu.cn'` 时运行（第 120 行的主机检查），所有请求都打在当前页的 origin 上，即同一主机，不需要额外放行的域，也不写通配。登录页或其它页面上点「提取」：大白话提示，**不发请求**（冒烟 `login`、`otherhost` 两例，零请求）。

| 序 | 方法 | 地址 | 用途 | 取不到时 |
|---|---|---|---|---|
| 1 | GET | `{origin}/kcb/api/schoolyearTerms` | 取学年列表与学期列表，选学年学期（§2） | HTTP 非 2xx：「教务系统返回错误（代码 N）」；网络失败：「没有连上教务系统，请检查网络后再试」；列表为空：「没有读到学年学期列表，请确认已登录并能看到课表后再试」。整次中止，不发课表请求 |
| 2 | GET | `{origin}/kcb/api/course?schoolYear={年值}&schoolTerm={学期值}&week=N`，N = 1..limit，串行 | 逐周取课表 | 单周网络失败 / 非 2xx / 返回结构不是课表：记下周次，继续下一周，parse.js 在提醒里点名；全部失败才报错「每一周的课表都没有取到…」 |

逐周上限 `limit` 初值为 20（`WEEKS_MIN`），每收到一周的记录就更新为 `min(30, max(20, 已见过的最大周))`（`limit =` 赋值在 extract.js 第 171 行附近）。「已见过的最大周」取每条记录周次文字里的最大数字（`maxWeekIn`，第 97 行），所以「15-22周」会把上限延伸到 22。硬上限 30（`WEEKS_MAX`）。收到的最大周已到 30 时 `capHit` 为真，parse.js 提醒「之后的周次没有导入」。

没有第三个请求。没有请求体（上游的课表接口也是 GET）。

## 2. 学年学期的选择（替代上游「第一个学年 × 第一个学期」）

`chooseTerm`（extract.js 第 83 行）：

1. **有标记**：学年与学期都带标记（`current` / `isCurrent` / `selected` / `isSelected` / `checked` / `default` / `isDefault` 值为 `true`，`findFlag`，第 31 行）→ `picked = 'flag'`。
2. **没有标记，按提取日推算**（`dateTerm`，第 41 行）：8–12 月 = 当年第一学期；1 月 = 上一年第一学期；2–7 月 = 上一年第二学期。
   - 学年：在 `schoolYears` 里找 label 或 value **以起始年开头**的项（`findYearByDate`，第 50 行），例如 2026 匹配 `2026-2027`，不匹配 `2025-2026`（它的结束年也是 2026，不能用）。
   - 学期：在 `schoolTerms` 里找 label 含「一」或「1」（第二学期为「二」或「2」）的项；都没有时 value 恰好等于 `1` 或 `2`（`findTermByDate`，第 59 行）。
   - 学年找不到 → 退回第一个学年，加按日期推出的学期，`picked = 'yearfallback'`（extract.js `chooseTerm` 第 93 行）。这种情况单独提醒，不写成「按今天的日期选择」，因为学年并不是按日期选的。
   - 学期找不到 → 取列表第一项（`picked = 'first'`），提醒「也对不上今天的日期」。
3. 只有学年有标记、学期没有：学期按日期推算，`picked = 'date'`。

提醒（parse.js 第 508–522 行）：`flag` 为「导入的是教务系统标为当前的学期…」；`date` 为「已按今天的日期选择导入 X 学年第 N 学期，请核对是不是要导入的学期」；`yearfallback` 为「没找到与今天日期对应的学年，已导入列表里的第一个学年 X 学年第 N 学期，请核对是不是要导入的学期」；`first` 为「没有标出当前学期，也对不上今天的日期，已取列表第一项「…」，请核对是不是要导入的学期」。措辞按 `docs/ux-writing.md`（不出现「接口」「字段」「null」等词）。

## 4. 与模板件（hueb）的差异

- 取数：hueb 是正方 WebVPN 的 4 个请求（学年学期首页 HTML、校历、作息、课表 POST）；本件只有 2 个 JSON GET，无 WebVPN 前缀、无 HTML 解析。
- 学年学期：hueb 从课表页下拉框取；本件从 `schoolyearTerms` 取，按标记或提取日选择（§2）。
- 节次时间：hueb 从教务作息接口取，取不到回落 13 节表；本件没有作息接口，只用上游写死的 12 节表，超出按 H3 顺推。
- 开学日：hueb 从校历取；本件没有校历，按学期推算（第一学期 9 月初、第二学期 2 月下旬、第三学期 7 月初），提醒核对。
- 总周数：hueb 从校历取；本件没有，写死 20，课表里有更晚的周次就抬高到 30 以内。
- 周次解析、单双归属、「共 N 周」剥离、括号序号与备注、H3、warnings 收口：照 hueb 的已审计写法（parse.js `weeksOf` / `runsOf` / `warn`）。
- 合并：hueb 按上游 `mergeAndDistinctCourses` 两阶段，本件是「分组 → 去重 → 相邻节次合并（`<= 结束 + 1`，周次集合相同）→ 按周次拆块」，因为逐周请求的数据形状不同。
- 占位文字：教师、教室写「未知」「待定」「暂无」「暂无教师」「暂无教室」时按空处理（parse.js `realOrEmpty`，第 72 行），载荷里是 null。

## 5. 上游删掉或改掉的东西及理由

| 上游 | 移植件 | 理由 |
|---|---|---|
| `selectYearAndTerm` 弹窗选学期，默认下标 0 | 标记 → 提取日推算 → 第一项（§2） | 批次二十八主调度决定：默认下标 0 在春季就是错的；不弹窗 |

## 7. 已知风险与未验证项（如实写）

- **没有本校账号，真机没验过。** 所有样本（`fixtures/*.extracted.json`）与冒烟里的接口响应都是按上游代码读取的字段形状编造的，接口的真实返回未见过。
- **学年学期标记与日期规则未经接口验证。** 上游代码没有用到 `schoolyearTerms` 的标记字段，真实接口是否有、字段名叫什么，都无法确认。移植件认 §2 列出的几种名字；都没有时按提取日推算（8–12 月当年第一学期，1 月上一年第一学期，2–7 月上一年第二学期）。日期推算依赖学校的学年划分是「9 月开学、次年 2 月开学」这种常规形式；若学校有其它学期安排，推算会错，提醒会说明选了哪一学年哪一学期，用户可核对。
- **学期项的匹配是猜的。** 学期 label 含「一」「二」或数字 1、2 即认；只有 value 时，value 必须恰好是 `1` 或 `2`（不做包含匹配，因为 `12`、`16` 之类会误中）。真实 value 若是别的编码，会落到「取第一项」的提醒上。
- **开学日是推算的，不是教务给的。** 学期序号从学期文字判断（含「二」或「2」为第二学期，含「三」或「3」为第三学期，其余为第一学期）；学年读不出时用今天所在周的周一。推算结果写进了提醒。
- **周数有取数上限，超出的周次会漏。** 逐周请求的上限是 `max(20, 已见最大周)`，硬上限 30。**只出现在第 21 周以后的课仍然可能漏**：这类课不会出现在第 1..20 周的任何一周的响应里，既取不到，也不会提醒（上游同样如此）。第 1..20 周内开始、之后延续到 21 周以上的课，周次文字里有完整周次，会被导入并抬高总周数（`week-failed`、`week-cap-first` 与冒烟 `extend` 用例钉住）。超过 30 周的课，`capHit` 时有提醒，但之后的周次不会导入。
