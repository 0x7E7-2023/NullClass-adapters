# 安全审计 —— 浙江科技大学（正方新版教务 jwglxt，经学校 WebVPN 子域名或校内直连访问）

审计对象：`jw-adapters/zust/` 下的 `extract.js` / `parse.js` / `manifest.json`，以及它们移植自的上游脚本
`shiguang_warehouse` 的 `ZUST/zust_01.js`（快照 commit `e15c6274ac347c9642da890504651a9b4e374391`，2026-10-26 拉取，MIT，维护者 小漫君；本校脚本最后一次修改 `c625921`，2026-10-21 新增，已用 `git log -1 -- resources/ZUST/zust_01.js` 核对一致）。

审计方式：逐行读上游脚本 + 逐行读移植件，跑 `check.js`（Rhino 1.8.0 实跑全部 fixture + 载荷校验 + ES5 + 控制字节 + allowHosts），再用 Playwright 在 Chromium 里起假教务站实跑 `extract.js`（10 个场景，见第 8 节）。

## 0. 出处与模板

- 上游 `ZUST/zust_01.js`：正方 V9，全部请求都是 GET + 查询串，弹窗选学年学期，按校区取节次时间，保存学期配置 / 作息 / 课程三步。
- 模板选 `jsei`：同为正方新版 `/jwglxt/`、同样 WebVPN + 直连双入口、同样有学期周次校历与节次时间接口，且已吸收批次七至十六的审计修正
  （前缀 / 后缀单双标记各归各段、共 N 周只剥备注、H3 补节次、校历第 1 周回退周一、去重合并、提醒限长）。WebVPN 子域名写法参考 `xmcu`（主机固定）。
- 在模板之外补的：周次里的「第」（`第1-第8周`）、按校区取节次时间、校区名进地点、节次表重复行去重、学期回显核对。

## 1. 请求清单（与 `extract.js` 逐条对应）

主机一律由 `window.location.origin` 拼出，不写死；当前主机必须是 `https-newjwxt-zust-edu-cn-443.webvpn.zust.edu.cn` 或 `newjwxt.zust.edu.cn`（`onJwHost`），否则直接报错不发请求。
上下文路径跟着当前地址走（`jwBase`），没有就用 `/jwglxt`。全部是 GET，`credentials: 'include'`，头只带 `X-Requested-With` 与 `Accept`。

| 方法 | 地址 | 干什么 | 取不到时 |
|---|---|---|---|
| GET | `<origin>/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N2151&layout=default` | 读 `#xnm` / `#xqm`（**页面上已有这两个字段时跳过**） | 报错，提示重新登录后再点「提取课表」 |
| GET | `<origin>/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151&xnm&xqm&kzlx=ck&xsdm=&kclbdm=&kclxdm=` | 取整学期课表（排课行、实践课；`xsxx` 只比对学年学期） | 报错 |
| GET | `<origin>/jwglxt/kbcx/xskbcxZccx_cxZcByXnxq.html?gnmkdm=N2154&xnm&xqm` | 学期校历（开学日、总周数） | 交 `null`，`parse.js` 推算开学日、总周数按 20 并说明 |
| GET | `<origin>/jwglxt/jzgl/skxxMobile_cxRsdjc.html?gnmkdm=N2154&xnm&xqm&xqh_id=<校区>` | 每个出现过的校区各取一次节次时间（最多 6 个校区） | 该校区交 `null`；基础校区取不到则整张用空课默认节次时间并说明，其它校区取不到进「节次时间不同」提醒 |

与上游一致：路径、方法、查询参数、菜单号（课表 N2151、校历与节次时间 N2154）逐字照抄上游 `zustFetchCourses` / `zustRequest`。
不同：上游每次先取课表首页给弹窗用，这里页面上读得到就不取；校历与节次时间失败上游整次报错，这里降级（见第 5 节）。
登录过期判断照上游：响应地址含 `authserver/`、`login_slogin`、`site-nav/`，或页面标题以「统一身份认证」开头 → 报「登录已过期，请通过 WebVPN 重新进入教务系统」。

入口判断：`loginUrl` 是 WebVPN 首页 `https://webvpn.zust.edu.cn/`（上游 `import_url` 带一个没替换的 `${redirect_url}` 占位符，不照抄）。
停在 WebVPN 首页 / 统一认证页 / 教务登录页点「提取课表」：给大白话提示，**不发请求**（冒烟 `home` / `auth` / `loginpage` 场景覆盖）。

| 数据 | 带出的字段 |

| 排课行 | 白名单 `kcmc` `xm` `cdmc` `xqj` `jcs` `zcd` `xqh_id` `xqmc`（`ROW_FIELDS`） |
| 实践课 | 只留 `kcmc` |

冒烟里在课表行、`xsxx`、校历行里都塞了学号 / 证件号 / 手机号 / 教室内部 ID，交出的 JSON 里一个都没有。

## 3. 移植手册 §5 八条逐条结论

1. **不碰凭据**：不读不存不发账号密码；只用 WebView 已登录的会话（`credentials: 'include'`），不读 Cookie。通过。
2. **不外发**：全部请求同源（`window.location.origin`），主机两个都在 `allowHosts` 里。`extract.js` 里没有任何写死的绝对地址。通过。
3. **只读课表**：只请求课表、校历、节次时间三类接口，不碰成绩 / 学籍 / 个人信息。通过。
4. **字段白名单**：见第 2 节。通过。
5. **不埋点**：无 `sendBeacon` / `WebSocket` / `Image` 上报。通过。
6. **不动态执行**：无 `eval` / `new Function`。通过。
7. **不写页面、不提交表单**：只读 `#xnm` / `#xqm`，首页用离线 `DOMParser` 解析，不插入当前页面。通过。
8. **不硬编码秘密**：无任何账号、学号、令牌。通过。

## 4. 与模板 `jsei` 的差异

- 请求全部 GET + 查询串（模板 POST 表单）；课表多一个 `kclxdm=`；节次时间按校区取（模板固定 `xqh_id=1`）。
- 入口：主机固定为两个（WebVPN 子域名 / 直连），不在其上不发请求（模板不判主机）。
- 周次：先去掉「第」（`第1-第8周`）；其余解析与模板相同。
- 地点写成「校区名 教室」（上游 `position`）；只有校区没有教室算缺教室。合并键含校区号。
- 节次时间：基础校区自动取课数最多的（并列取先出现的）；其它校区与基础不同的课汇总提醒；节次表同一节重复且时间一样只留一条（上游同样）。
  模板的「学校 11 节表」换成空课默认 12 节（上游没有写死表）。
- 学期名：学期下拉框文字是 1 / 2 / 3，直接按数字判断第几学期，再看中文数字与学期代号 3 / 12 / 16。
- 学期回显核对：响应 `xsxx.XNM` / `XQM` 与所选不一致就报错（上游同样，核对只在 `extract.js`，`xsxx` 不交出）。

## 5. 上游里被删掉 / 改掉的东西及理由

- **选学期 / 选校区弹窗**（`zustChooseSemester`、`zustSelect`）：改为读页面当前学期（移植手册 §3）；基础作息校区改为自动判断，影响只是提醒，不影响课表本身，所以不用提问桥。
- **逐校区自定义时间**（`isCustomTime`）：空课载荷没有单门课自定义时间，课表仍按原节次放入，其它校区时间不同的课进提醒（`otherTimes`）。
- **严格校验后整次报错**（周次无法识别、校历不连续、作息编号不连续、课程节次超出所属校区作息等）：按空课规范降级为 warnings，不静默丢课、不猜测。
  周次认不出的行计数进「数据不全」提醒；校历取不到 / 异常推算开学日；节次时间不合法当没取到。
- **课表周次超过校历周数整次报错**：改为抬高总周数并提醒（总周数上限 30）。
- **未排课课程**（`sjkList`）：上游列在确认弹窗里；这里写进提醒，让学生自己添加。
- **保存桥调用、确认弹窗、`notifyTaskCompletion`、`showToast`**：「拾光」的桥能力，空课由宿主保存，适配器只交数据。
- **学分 `xf`**：空课载荷没有学分，不带出。
- **安吉校区第 5 节午休**：上游保留原编号并加注「午休预留」；这里同样按教务给的节次原样保留，不加注（备注无处可放）。

## 8. 浏览器冒烟（Playwright + 假教务站，不联网）

场景 10 个全部 OK：`vpn`（WebVPN 子域名，请求全在该主机、全是 GET）、`lan`（直连主机）、`menu`（页面没有 `#xnm` 先取课表首页）、`home`（WebVPN 首页，不发请求）、
`auth`（统一认证页，不发请求）、`loginpage`（教务登录页，不发请求）、`expired`（课表请求回统一认证页 → 报登录过期）、`mismatch`（回显学期与所选不一致 → 报错）、
`aux-fail`（校历与节次时间 500 → 仍能导入，推算开学日 + 空课默认节次时间 + 提醒）、`one-campus`（只有一个校区只取一次节次时间）。
每个场景都检查：请求方法为 GET、请求里没有个人信息、交出的数据里没有个人信息、节次时间请求的校区与课表里出现的校区一致、每条提醒 ≤200 字。

## 9. 已知风险与未验证项

- **没有本校账号，真机没验过**：接口字段名、校历 `rq` 的「起日/止日」格式、节次时间的 `jcmc` / `qssj` / `jssj`、学期下拉框文字是 1 / 2 / 3，全部来自上游脚本的读法，没有拿真实响应对过。
- **校历总周数含假期**（上游注释明说「范围可能包含假期」）：总周数取校历行数，超过 30 钳到 30 并说明；真实校历若超过 30 行，30 周之后的课（本不该有）放不进。
- **`scheduleUrlHint` 写成了真实课表页地址而不是一句话**：该字段是「一键刷新时优先打开的课表页」（见规范 `jw-adapter-spec.md`），写大白话会打不开；提示文字改由提取失败时的报错给出。
- **`check.js` 的 `allowHosts` 检查有误报**：它用 `/^https?/` 拒绝以「https」开头的主机，而本校 WebVPN 子域名主机名就是 `https-newjwxt-zust-edu-cn-443.webvpn.zust.edu.cn`（以字符串 `https-` 开头，不是协议）。
  按未改动的 `check.js` 跑，唯一一条失败就是它；把正则改成 `/^https?:/` 后（我在临时目录的副本上验证）全部 PASS。需要主调度决定是否修正工具（我没有改 `.test/` 下的任何文件）。
- 多校区时只按「课数最多」选基础校区；如果学生主要在课数少的校区上课，提醒里会指出其它校区的课，时间以教务为准。
