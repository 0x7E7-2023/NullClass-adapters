- 上游快照：`e15c6274ac347c9642da890504651a9b4e374391`（2026-10-26 拉取）；本校脚本最后一次修改 `80e30cf`（2026-09-23，仓库整理提交，核对过，与任务卡一致）

## 1. 平台与模板选择

上游脚本打的是 `xsgrkbcx!getXsgrbkList.action`（学期下拉框所在页）和 `xsgrkbcx!xsAllKbList.action?xnxqdm=…`（课表页，源码里内嵌 `var kbxx = [ … ];`），
属于 Struts2 教务平台的 `xsgrkbcx` 族，与 `hbmu` / `glmu`（同样请求 `xsgrkbcx!…`，但它们取 `getDataList.action` 的 JSON 分页接口）同平台不同接口。
**取数层没有现成模板**（没有已审计件读 `xsAllKbList` 页面里的 `kbxx`），`extract.js` 按上游自行写成；
`parse.js` 的周次解析、提醒限长、缺教师教室汇总、H3 补节次照 `scut`（批次十四，同一作者 dezige131 的件）的成品写法，并保留 `hbmu` 的开学日探测与学期推算思路。
`scut` 是正方 V9，与本校平台不同，只借它的"后半段"（纯转换层）；`hbmu` / `glmu` 里 Struts2 的 `jcdm`（每节两位拼接）写法，本校的 `jcdm2` 是逗号分隔，不同构。

## 3. 读了什么、交出去什么

- 读：①页面（或列表页）的学期 `option` 的 `value` / 文字 / `selected`；②课表页源码里 `kbxx` 数组；③日期响应；当前页面是否有 `input[type="password"]`（**只看有没有，不读它的值**）。
- 交出去（字段白名单）：`{ term: { code, name, source }, today, dateInfo, rows }`
  - `rows[i]`：只有 `kcmc`（课名）、`teaxms`（教师）、`jxcdmcs`（教室）、`xq`（星期）、`zcs`（周次串）、`jcdm2`（节次码）六个字段，其余字段（学号、姓名、院系、班级等）一律不带出；每个字段限 300 字、对象 / 数组类的值直接丢；
  - `dateInfo`：只保留含 `xqmc`（星期）+ `rq`（日期）的叶子对象，层级照旧，其余键整棵丢掉；
  - `today`：本机日期（只用于推算兜底，不涉及个人信息）。
- 冒烟里在课表页源码、行对象、日期响应里都放了学号 / 身份证号 / 手机号 / 姓名 / 自造的 `extra` 字段，确认 `extract.js` 输出里一个都没有。
- 教师姓名与教室属于课表本身的内容（载荷里要用），不算个人信息。

## 4. 与上游的差别

1. 上游把课表交给 `window.shiguangBridge*`（拾光的宿主接口）；这里改成 **return 一个 JSON 字符串**，不触碰任何页面全局。
2. **不弹窗选学期**：上游一律弹「请选择要导入的学期」。这里：页面上有下拉框就读用户此刻选中的；没有就取列表页读 `selected` 项；
   列表里一项都没标又有多个学期才用 `__ncSelect` 问一次（最多列 12 项，取消则报「已取消导入」）；桥不在就取第一项并在提醒里说明（`source: first`）。
3. 上游在脚本里正则抠 `kbxx`、拼课程、去重、存节次时间；这里 `extract.js` 只抠数组（按括号配对扫描，跳过字符串里的括号，比上游的"懒惰匹配到第一个 `];`"更不容易被课名里的符号截断），其余转换全在 `parse.js`。
4. **周次解析重写**：上游 `parseWeeks` 只认逗号分隔数字与 `a-b` 区间（`parseInt` 遇到别的写法得 `NaN`、整门课静默丢掉）。这里还认单双周（含 `(单)1-8周,(双)9-16周` 这种前缀写法，标记各归各段）、
   「第」「周」字（`第1-第8周`）、括号备注 / 教学班序号、「共 N 周」（只剥备注本身），认不出的计数进提醒。
5. 上游缺教师写 `"未知"`、缺教室写 `"待定"`（会作为真实教师 / 教室显示）；这里记为空（`null`），并按类型汇总提醒，指向「编辑课程」。教务自己写的「未知 / 暂无 / 待定 / 无」同样当作没有。
6. 上游去重只认"星期-节次-课名-周次串"完全相同；这里先按"课名 + 教师 + 星期 + 节次 + 地点"归并同一时段，周次取并集再切成连续段 / 单双周段，不改任何一周的安排。
7. **开学日与总周数**：上游完全没有（空课的课表必须有开学日）。优先用 ③ 探到的第 1 周周一（先过一道"是否属于这个学期"的筛，与学期锚点差 45 天以上就不采用）；
   取不到按学期代码推算（第一学期 = 9 月 1 日所在周的周一，第二学期 = 2 月 20 日所在周的周一）并在提醒里说明；学期代码认不出时退到"今天所在周的周一"。总周数取 20 周，课表更晚就抬高到最晚周次（最多 30），也说明。
8. **节次时间**：上游写死的 11 节表逐节搬过来（见下），随载荷交出；上游同时存的 `defaultClassDuration: 45` / `defaultBreakDuration: 10` 只是拾光的 config，不进载荷。
   课表用到第 11 节之后的节次时按 H3 逐节补，补了哪些、哪些补不了都写进提醒。
9. 登录页：页面上有密码输入框就直接提示、不发请求；会话失效时（教务回 200 + 登录页）读不到学期下拉框或课表数据，给大白话提示。上游没有这一步（它会报"无法在页面中找到学期选项"之类）。
10. 上游的浏览器测试分支（`prompt` / `alert` / `console.log`）、`showToast` / `showAlert` / `saveCourseConfig` / `savePresetTimeSlots` / `saveImportedCourses` / `notifyTaskCompletion` 全部不移植；上游出错时 `console.error` 打印页面源码前 800 字，同样不移植。

## 9. 已知风险与未验证项（如实记录）

- **没有本校账号，真机没验过。** fixture 与冒烟都是按上游脚本实际读取的字段形状合成的，只保证"同样输入 → 同样输出"，不保证在真实教务上解析正确。
- 真实环境才能验的：`getXsgrbkList.action` 的 `#xnxqdm` 里哪一项带 `selected`、选项文字长什么样（学期名直接用选项文字）、学期代码格式（推算开学日只认 `YYYY01/02` 与 `YYYY-YYYY-1/2` 两种）、
  `zcs` / `jcdm2` 的真实写法、`getKbRq.action` 在本校是否存在（不存在就走推算 + 提醒，不影响导入）、日期响应的真实形状（沿用 `hbmu` 的探测口径）。
- 上游示例注释写 `zcs` 为 `"17,2,3,4,6"` 这类乱序列表；我们按"逗号分隔的周次集合"处理，排序去重后切段。若教务的第一个数字另有含义（如总周数），会被当成一个真实周次，需真机核对。
- 同一门课相邻节次分成两行（如 1-2 节、3-4 节）不合并，会显示成两个相邻的块；这与上游一致（上游也不合并），不丢课。
- 总周数按 20 周给（教务没给）；本校实际学期周数如不同，用户需在学期管理里改（提醒里已写）。
- 学期名直接用下拉框选项文字；如果文字很短（如"2025-1"）也照用。
- `scheduleUrlHint` 填的是 `https://jwxt.jxfu.edu.cn/xsgrkbcx!getXsgrbkList.action`（上游取学期下拉框的那一页，推断是「我的课表」页，未在真机验证；打不开时用户仍可手动进入该页）。

修订（2026-10-27，审计 B1）：`weeksOf` 的前缀归属原先只认「标记前面不是数字 / 周」，`(单)1-8周(双)9-16周`（无逗号）里的第二个标记被当成上一段后缀；现在当前段以前缀标记开头时，后一个紧挨「周」/数字的标记算下一段的前缀（`parse.js` 的 `weeksOf` 内，按函数名引用）。两端都无前缀的 `1-8周(单)9-16周` 仍按后缀读（1-8 单周 + 9-16 每周），因为 `1-8周(单)9-16周(双)` 这类后缀写法同样合法，两者无法区分。
